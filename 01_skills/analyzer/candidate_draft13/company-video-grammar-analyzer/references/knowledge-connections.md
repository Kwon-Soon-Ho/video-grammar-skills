# 지식 조회 → 사례 → 사용처 → 검수

이 경로는 회사 영상 DB 수집에서 사용한다. 공통 개념은 사례를 찾는 언어이고, 원칙은 검토 질문이다. 둘 다 실제 원본 관측의 증거를 대신하지 않는다. 프로젝트가 제공한 Phase 00 루트와 현재 안내/판본을 확인하고 필요한 항목만 읽는다. 전체65항목을 매번 적용하지 않는다.

## 먼저 조회할 것

현재 사전/관련 심화·회사 적용·판정 문맥의 위치/판본을 남긴다. `scripts/knowledge_links.py catalog --phase00 <루트> --out <작업용카탈로그.json>`은 기존75용어+폐기1개·65기본지식·26품질 질문과 필요한 R1–R8 참조의 경로/해시를 읽는다. 정본을 바꾸지 않으며 외부 스킬을 실행/설치하지 않는다. `query --catalog <파일> --query <명칭>` 또는 `--id <정확ID>`로 후보를 조회한다. 실제 적용 조건/반례는 반환된 원문을 읽는다. 단순 단어 일치가 적합성 판정은 아니다.

프로젝트의 기존 사용 색인이 있으면 해당 개념의 사례/정의/근거·차이를 먼저 찾는다. 없으면 이번 사례의 지역 후보부터 만들고 기존 색인이 없었다고 남긴다. 자료가 없거나 해시가 바뀌면 영향받는 지식 연결을 유보하고 관측 가능한 수집은 계속한다. 없는 ID/회사 승인/관측을 만들지 않는다.

## 기록 관점 — 서로 조합하는 여섯 묶음

| 관점 | 원본에서 보존하고 검색할 것 |
|---|---|
| 정보·설명 | 주체·방향·비교 기준·관계·내용/설명 순서. 문서 확인과 기능 해석 구분 |
| 화면 구조 | 전체/구역 범위, 정보관계형 레이아웃과 기하 격자·정렬·여백·영역 조합 구분 |
| 표현 언어 | 제목/지표/단위/본문 역할, 역할 색, 형태/선/프레임, 재질·빛·깊이·배경/전경·반복 모티프가 함께 작동하는 방식 |
| 모션·시간 | 전체 흐름/독립 동작, 대상별 시작·진행·정착/퇴장·반복, 선후/중첩/유지, 실제 음성 검수 범위 |
| 재사용 | 정의/판본·묶음/하위 구성·배치, 현재 사용처·근거·차이·미검증, 보호/가변 후보·적용/제외 조건 |
| 근거·판단 | 관측/계산/추론, 원본·변환·시각·방법, 관련 질문과 실제 판정·보류/미검수 |

이는 여섯 개 정본 분류ID나 배타적인 트리가 아니다. 해당 없는 세부는 이유를 적고, 미관측을 해당 없음으로 닫지 않는다. 전체 사례를 유지하면서 구역/대상/동작에 여러 태그를 붙인다. 두 판이 있다고 비교, 원근이 있다고 등각, 숫자가 크다고 정량 차트로 확정하지 않는다. 사전에 맞는 관계가 없으면 자유 기술/미분류 이유를 보존하고 확장 후보로 남긴다.

표현 언어는 특징의 역할/조합으로 설명한다. 개별 픽셀 수치만 모으거나 ‘고급/세련됨’으로 대체하지 않는다. 미감 태그와 기능 태그는 함께 필요하다. 모든 장면에 같은 재질/격자/모션 방향을 강제하지 않는다. 정확 폰트/색/곡선 미상과 디자인 관계의 관측 가능성을 구별한다.

## 개념·정의·사용처·판정을 분리한다

- **개념 연결:** 대상 단위/범위, 정확ID·카탈로그 판본, 분류 이유와 현재 근거. 원본 현상을 분류하는 행위 자체는 분석자의 해석이다.
- **정의:** 역할·구성·조건·가변/보호 후보를 가진 재사용 단위. 기존 ID를 재사용하면 뜻/판본을 유지한다. 지역 부품/표현 프로필을 모션 DETAIL로 강제하지 않는다.
- **사용처:** 어떤 영상·시각·구역·내용에 어느 정의/판본을 썼는지. 이번 근거·차이·미검증을 연결한다. 한 번 관측된 후보/반복 확인/동일 원본 자산/회사 규칙은 별도다.
- **검토:** `review_relevant`는 검토할 지식의 연결이다. 실제 적용 효과/승인이 아니다. `evaluated_against`에는 실제 검토 행을 연결한다. 선택한 항목의 `pass/fix/hold/not_applicable/not_reviewed`, 이유·근거·검토 주체/범위·다음 확인을 남긴다. 아직 보지 않았다는 것을 pass/비적용으로 바꾸지 않는다.

기본 결과는 Markdown이다. 지식조회 기록, 사례의 여섯 관점, 정의/사용처, 선택한 검토 항목을 표나 연결 문서로 적는다. 파일 수나 태그 수를 고정하지 않는다. 사례 요약→전체 상세→근거의 읽기 순서를 유지한다.

## 기계 색인 요청 시

사용자가 DB 연결/검색 구현·검사를 요청한 경우에만 [부속 색인 계약](knowledge-sidecar.md)을 사용한다. `video-knowledge-links-0.1`은 연결 구조의 편집 원본이며 전체 관측 MD/그림은 고정 원문으로 연결한다. MD를 변경하면 pin/연결도 확인한다. 자동 동기화나 R4 적합성을 주장하지 않는다.

`check --catalog <파일> --record <부속JSON>`은 참조·해시·범위·판정 연결만 검사한다. `index --catalog <파일> --records <파일...> --out <색인>` 후 `query --catalog <파일> --index <색인> --id <ID>` 또는 `--query <단어>`로 양방향 사용처를 조회한다. `--motion-only`는 실제 관측 기록을 가진 모션만, `--include-unobserved`는 조사 항목을 따로 조회한다. 이미 만든 색인의 원문/부속 기록이 바뀌면 재생성 전에 변경 이유를 검토한다.

종료 전에 사례→정의→개념→다른 사용처→각 근거와 사례→관련 질문→실제 판정을 왕복한다. 관측 내용·분류 적합성·스킬 성능·회사 승인은 다른 검증이다.
