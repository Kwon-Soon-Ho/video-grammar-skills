# Markdown 수집 기록 계약

기본 경로다. 한 사례는 `collection.md` 등 읽기 쉬운 Markdown으로 저장한다. 사용자 지정 파일명/구조가 있으면 따른다. 사례가 길면 근거와 재사용 색인을 분리해 연결한다. JSON 복사본·PDF·새 화면안을 수집을 위해 의무 생성하지 않는다.

## 1. 원본과 범위

사례 ID, 스킬 판본, 원본 경로/해시, 분석 창과 주변 맥락, 실제 프레임 시각/근거 경로, 관측 방식·표본 간격, 원본/크롭/축소 이력, 문서 판본/유형과 음성 검수 여부를 남긴다. 공통 근거 문서에 한 번 쓰고 사례에서 참조해도 된다. 표본 수를 연속 관찰 시간으로 바꾸지 않는다.

## 2. 정보 관계와 전체 디자인

| 항목 | 기록할 내용 |
|---|---|
| 전달 대상/정보 관계 | 누가 무엇을 요청·지원·비교·분류하는지, 총량/하위 항목·같은 집계의 다른 분류·단위가 다른 지표 등 |
| 전체 배치/위계 | 주요 구역과 연결, 주항목/보조항목, 제목·수치·라벨·설명의 관계, 읽는 흐름 |
| 표현과 부품 | 장 표식·정보판·차트·문구·도상·업무 이미지·배경층·프레임/선·재질의 외형 |
| 조합과 역할 | 어떤 부품이 무엇과 함께 쓰이고 어떤 기능을 맡는지. 원제작 의도와 기능 해석은 분리 |
| 상태별 차이 | 도입·이동·강조·정착 중 달라지는 배치/내부 상태와 배경/전경 관계 |

전체 관계를 먼저 쓰고 필요한 값만 정밀 보강한다. 이름/색 목록이나 픽셀 좌표만으로 디자인을 대체하지 않는다. 목적 해석을 이유로 보이는 요소를 생략하지도 않는다.

## 3. 전체 흐름과 독립 동작

전체 흐름에는 주요 상태와 앞뒤·겹침·계속 남는 맥락을 기록한다. 세부 동작에는 대상/역할, 시작→진행→끝/퇴장, 근거, 동반/시차, 변수와 미상을 연결한다. 수치 정착과 보조 도상 완성이 다르면 따로 남긴다. 작은 부품 단계는 하위 설명으로 보존하고 새 번호를 남발하지 않는다.

정확한 시작이 없으면 마지막 미발생~첫 발생 범위로 쓴다. `10.0초 미발생 / 10.5초 첫 가시성 → (10.0, 10.5]초`는 경계 범위이지 모션 길이 0.5초가 아니다. 진행 표본이 부족하면 정착과 곡선 미상을 구별한다.

## 4. 근거 성격

| 성격 | 기록 원칙 |
|---|---|
| 원본 관측 | 화면/실제 청취에서 확인한 대상·문구·변화와 근거 |
| 계산 | 입력 근거·연산/방법·단위·오차 |
| 기능 해석 | 위계/대비/리듬이 수행하는 역할에 대한 추론과 이유. 원제작 의도 확인 없이도 근거 있는 가설로 기록 가능 |
| 변경안/요청 내용 | 문서/사용자 요청의 내용 기준. 원본 관측의 다른 값을 덮어쓰지 않음 |
| 새 설계 제안 | 별도 요청 시 작성하며 원본 수집/반복의 근거에서 제외 |

원본 수치와 변경안이 다르면 양쪽의 판본을 유지한다. 우측 색 글씨 등 사용자 지정 해석은 그 적용 범위를 기록한다. 원고를 실제 음성으로 취급하지 않는다.

## 5. 재사용 단위와 반복

번호/정의 판본, 사례/구역, 현재 근거, 전체 레이아웃/흐름/세부 역할, 포함·배치 기준·선후·겹침·동반을 남긴다. 처음은 구성·단계·조건을 상세히, 반복은 기존 정의+현재 차이/미검증을 연결한다. 공식 라이브러리가 없으면 충돌하지 않는 로컬 후보 ID를 쓰고 [기계 등록](pattern-composition.md)과 구별한다.

같은 것으로 본 범위, 색/문구/항목 수·그리드→가로열 등 이번 차이, 미검증 차원, 사용/제외 조건, 변경 가능한 범위를 기록한다. 공통 외형 가족·동일 부품·회사 공통 규칙은 별도 판단이다. 원본 언어 유지와 다른 스타일 활용을 모두 열어두되 정보 관계·단위·의미를 구별한다.

정식 ID/판본은 정의와 사용처에서 동일하게 쓴다. 짧은 별칭을 쓰면 정식 ID로 연결하는 표를 한 번 두고, 별칭만 복사해도 다른 정의와 혼동하지 않게 한다. 미관측 동작을 위한 조사 항목은 관측된 패턴 정의와 구별한다.

조건은 사례별 실제 쟁점을 쓴다. 추론한 조건·구체 반례의 논리 검토·실제 시험을 구별한다. 일반 조건 한 문장을 모든 패턴에 복사해 채우지 않는다.

## 6. 미상과 내용 검수

`미관측 / 판독 불가 / 정지 확인 / 해당 없음 / 정밀 원값 미상`을 구별한다. 이유·영향받는 사용·다음 확인을 남긴다. 미상의 폰트명은 위계 기록을 막지 않지만 못 본 퇴장을 관측 완료로 처리하지 않는다.

선언한 범위에서 원본의 구역·문구·부품·강조·층/조합이 기록에 대응하는지, 시작/중간/끝·내부/주변 변화·동반/시차·경계가 빠지지 않았는지 대조한다. 반복 번호는 현재 근거/차이를 가리켜야 한다. 다음 조회자가 근거·정보 관계·조건·미검수 범위를 찾을 수 있는지도 확인한다. 실제 방법/검토 주체를 남긴다. [원본 재대조](source-readback.md)에서 중요한 식별·수치 귀속과 ID 왕복을 확인하고, 지적된 오류는 이전 실행을 덮어쓰지 않고 별도 정정 이력으로 연결한다.

부분 수집은 초안으로 저장하되 중요한 미관측 구간을 밝힌다. 수집물의 검수, 패턴 분류, 정본 등록, 독립 성능 평가, 새 주제 활용 검증은 별도 상태다. 새 화면 제작을 수집 완료 요건으로 두지 않는다.

## JSON 모드와의 관계

기계 연계 요청 시 [JSON 계약](output-contract.md)으로 작성/변환한다. 기존 스크립트는 JSON과 근거 연결을 검사하며 이 Markdown의 의미/누락 전체를 검사하지 않는다. 둘을 관리하면 편집 원본을 명시하고 자동 동기화가 있다고 주장하지 않는다.
