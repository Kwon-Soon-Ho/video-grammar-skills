## 분석 결과와 R4를 어떻게 연결할 것인가

R4 v0.2는 아래 13개 최상위 필드를 요구한다. 실스키마에서 확인한 필드명이다. 다음 표는 이관 설계이며 완성된 변환기나 적합성 인증이 아니다.

| R4 필드 | 현재 MD/분석JSON에서 가져올 원천 | 남은 검증 |
|---|---|---|
| schema_version, record_id, version | 선택 규격·사례/판본 | 기존 video-observation-0.4를 이름만 바꿔 통과시키지 않음 |
| catalog_refs | 원본/근거 카탈로그, 이번 개념/정본 pin | 정확 source/hash/허용판본 확인 |
| spatial_contract | 원본 크기·시간 계약·대상/주장/근거 | 대상↔주장 단위 변환·시간/영역 검증 |
| units | 전체 영상·설명구간·화면상태·짧은동작 | target_ref 및 related_state_refs 연결. 프레임은 표본이며4층 배타 트리로 만들지 않음 |
| coordinate_bindings | 크롭/축소 좌표와 변환 이력 | 원점·단위·배율·회전·증거 위치 연결 |
| cut_markers | 실제 확인한 컷 경계 | 모르면 정밀 시각/경계 생성 금지 |
| asset_metadata | 원본파일/메타데이터·자료 유형 | 실제 파일/권한/관측 자산과 정본자산 구분 |
| design | 관측 구성/프로젝트 역할/프로필 | CI 원값·관측 추정·프로젝트 선택 분리 |
| run | 추출/분석/판정 실행 기록 | 스킬 판본·실제 방법·입출력/환경 |
| review_contexts | 적용 질문·판정 주체·근거/보류 | R7 현재 pin/범위·사람 회신·권한 |
| notes | 한계·미관측·해석·후속 | 필수 구조를 notes 자유문으로 우회하지 않음 |

R4 필드의 상세 하위 계약은 원문 스키마/현재 예시를 따라야 한다. 이번 사용 색인은 `uses.json` 기반 조회 초안이며 R4의 모든 필수 계약을 충족하지 않는다. 실제 R4 적합 이관은 다음 구현/검증 묶음으로 남긴다.

## 이후 분석에 넣을 연결 절차 — 구현 제안

1. 현재 사전/지식/한맥/판정 문맥의 판본을 고정하고 필요한 범위를 조회한다. 기록 시작 시 기존사용처/유사후보를 찾아 비교한다.
2. 원본에서 전체 정보·구도·표현·흐름을 수집한 뒤 해당 구역/동작에 개념 태그와 이유를 붙인다. 사전이 원본 관찰을 대신하지 않는다.
3. 독립 재사용 후보를 정의하고 사용처/현재 차이/조건을 연결한다. 원칙은 관련 검토 질문으로 연결하고 실제 적용/판정을 별도 기록한다.
4. 사례→정의→개념→다른 사용처→각 근거를 왕복한다. 근거가 없으면 미관측/미분류로 남기며 원칙명으로 채우지 않는다.
5. 선택한 R7 질문의 적용/비적용/미검수와 근거를 정리한다. 수집 충실도·분류 적합성·회사 승인·다른 주제 활용 성공을 구분한다.

이번 문서가 존재하는 것만으로 앞으로 스킬이 위 절차를 자동 수행한다고 보고하지 않는다. 스킬 반영/실제 출력 검증은 별도 작업이다.
