# 웹 1차 자료 — 무엇을 규격화할 수 있는가

2026-10-19 공개 공식 문서를 직접 열어 확인했다. 아래는 프로젝트용 설계 해석이며 이 문서들에 따라 우리 DB가 이미 표준 적합하다는 의미가 아니다. 새 라이브러리 설치/렌더 도입이 목적도 아니다.

| 1차 자료와 확인 부분 | 가져올 구조 | 적용 한계/보류 |
|---|---|---|
| [W3C SKOS Reference](https://www.w3.org/TR/skos-reference/) — concepts/labels, §8 의미 관계, §10 mapping | 대표어/별칭, 상·하위/관련 관계, 외부 체계와 근접/관련/동일 대응을 구별 | 유사한 AP/MP를 자동 동일 병합하지 않는다. closeMatch는 전이되지 않는다. 유형별 적용 조건/근거 신뢰도는 별도 계약 필요 |
| [W3C Web Annotation](https://www.w3.org/TR/annotation-model/) — body/target, §4.2 selectors | 설명/판단과 대상 원본 분리, 시간/영역 선택자, 특정 부분의 근거 연결 | 좌표 변환·표본 간 미확정 경계·측정 오차는 프로젝트 계약으로 보강. 단순 해시/앵커가 의미 진실성을 보장하지 않음 |
| [W3C PROV-O](https://www.w3.org/TR/prov-o/) — §3.1 entities/activities/agents 및 derivation | 원본→추출→크롭→관측→분류의 파생 관계와 수행 주체/활동 구분 | 원제작 의도·회사 승인·외부 신원/권리 인증으로 확대하지 않음. 전면 RDF 이관 없이 개념을 참고 가능 |
| [DTCG Format 2025.10](https://www.designtokens.org/tr/2025.10/format/) — §3 token/type/alias, §8/9 유형 | 이름/값/유형/설명/별칭, 색·치수·시간·곡선·타이포/그림자 같은 복합 값의 구분 | W3C 표준이 아닌 Community Group 보고서다. 관측값을 곧바로 승인 토큰으로 만들지 않는다. 정확한 색/곡선을 못 봤다면 null/정성/추정으로 유지. 당장 전면 포맷 교체 불필요 |
| [Vega-Lite Encoding](https://vega.github.io/vega-lite/docs/encoding.html), [View Composition](https://vega.github.io/vega-lite/docs/composition.html) | 데이터 필드/유형↔위치·길이·색 등 부호 대응, 단일 뷰와 layer/concat/facet/repeat의 조합 구분 | 차트만의 문법을 모든 영상에 강제하지 않는다. 공유척도도 의미가 맞아야 한다. 템플릿 형태가 맞는 것과 데이터/분모/한국어 정확성은 별도 |
| [Carbon v10 Choreography](https://v10.carbondesignsystem.com/guidelines/motion/choreography/) — composition/continuity/sequence | 의미/공간 일관성, 연속 대상, 순서/시차를 함께 기술하는 방식 | **보관된 v10 UI 지침**이다. 대각선 금지·20ms/500ms·같은 easing 등을 사내 영상 의무 규칙으로 가져오지 않는다. 실제 영상의 다중 동작/화면 폭/읽기 시간에 맞춰 판단 |

규격화 우선순위는 **① 개념·패턴·사용처·판정의 구분 ② 대상/시각/근거/판본 연결 ③ 격자·표현 프로필·모션 사건의 유형 필드 ④ 필요할 때 도구 간 교환 포맷**이다. 형식만 표준화하고 좋은 디자인의 조건을 잃지 않도록 ‘무엇을 설명하고 어떤 조건에서 재사용 가능한가’를 함께 적는다.

이미 00의 R4/R5/R6에서 다루던 시간/좌표/파생/역할 구분도 있다. 이를 새 발견으로 포장하지 않고 현재 수집 기록에 연결할 누락으로 분류한다. 표준의 전체 적합성/시청자 이해도/회사 규정 검증은 수행하지 않았다.
