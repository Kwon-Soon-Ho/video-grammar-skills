# 레이아웃 지식을 읽고 사용하는 순서

R2는 화면에 어떤 이름을 붙일지 정했다. R3-2는 설명할 정보에 어떤 구조가 적합한지 판단할 참고 지식이다. 14개 명칭을 국제표준·유일한 레이아웃 전부라고 표시하지 않는다.

1. 지금 전달할 질문·정보 항목·관계·출처를 확인한다. 관계는 화면 모양만으로 자동 부여하지 않는다.
2. [14개 적용 예·반례](07_레이아웃별_선택조건과반례.md)에서 후보와 대안을 비교한다. 이름 분류와 품질 평가는 별개다.
3. [8개 화면 설계 기준](08_화면설계_적용기준과반례.md)으로 위계·그룹·밀도·한국어·색·읽는 시간·데이터·선택 이유를 확인한다.
4. 실제 문구·숫자·단위를 넣고 가로·세로·정사각 대안을 검토한다. 화면비에 따라 구조를 재배치하되 관계·순서·비례·버전은 유지한다.
5. 데이터·시청 환경·동일 대상·기능 출처가 부족하면 해당 판단만 보류한다. 관측 가능한 화면 구조까지 지우지 않는다.

‘초점 하나·중앙 금지·카드 금지·12열·8px·제목2줄’은 회사 영상의 보편 규칙이 아니다. 비교에서는 동등한 두 대상이 필요할 수 있고, 단일 요점도 중앙에 배치할 수 있다. 여백·낯섦·효과의 수만으로 품질을 통과시키지 않는다.

시청 환경과 출력 화면비가 없으면 완성 레이아웃의 가독성과 안전영역을 확정할 수 없다. 정지 그림의 균형뿐 아니라 정보가 완성된 상태·읽는 동안의 가림·유지 구간을 본다. 사용자가 직접 속도를 조절하는 웹 화면과 고정 영상의 노출 시간은 다르다.

한맥 디자인 정본은 [참고 연결](../03_한맥디자인/00_디자인안내.md)로 유지한다. 웹 토큰을 영상 기본px로 변환하거나 가족사 CI를 한 팔레트로 합치지 않는다. R1은 자산 위치·출처, R5는 회사 디자인 적용 조건, R4는 실제 DB 필드다. 실제 분석 구현은01-A이며 이번에는 수행하지 않는다.

정본은 레이아웃_심화지식.json이다. 예와 반례는 프로젝트가 작성한 설명용 사례로, 사내 영상의 실제 사례나 검증된 효과가 아니다. 스킬 파일은 참고 텍스트만 읽었으며 R3-3의 심층 검토·실행 평가 완료로 표시하지 않는다.
