# 수행 fixture 범위 설계 검토

2026-10-15. main이 전달한 수행 fixture 설계안에 대한 정적 검토다. 후보/실제 fixture/실행 결과는 아직 검토하지 않았다.

설계안은 R4/R5 실제 수정·backup 실패·기존 checkpoint 복구 3과제를 기존/수정 스킬로 비교한다. 평가 노출 방지를 위해 R8/R3 스킬 이식 평가문서·타스킬/evals·R7 평가계획·완료/검토 보고를 수행 DB에서 제외하고 제외 목록/원본 hash를 별도 보존한다. R4/R5 검사에 필요한 정본/코드/회사 자산을 포함하며 R6 실제 CI 최신성 질문/답변은 필요한 문맥만 포함한다. 제외 때문에 R7 완전조회/전체 R6 검증은 수행 DB에서 미실시로 남기고 D 운영 old14/R7 pin은 main이 별도로 확인한다.

**초기 의견: 역할별 합성 개발시험으로는 가능. 아래 조건을 충족해야 하며 full R6/R7 통합평가·미사용 평가·최종 판정은 아니다.**

- 기존/수정 수행의 포함·제외 경로, 원문 bytes/hash, 도구, 허용 쓰기, 요청을 동일하게 고정한다. 비교 변인은 스킬이다. 재실행/실패도 모두 보존한다.
- D 운영의 R6/R7 정상확인은 C 수행 DB의 현재성 통과 근거가 아니다. 둘의 경로/입력/목적을 보고서에서 구분한다.
- C 수행에서 누락된 R6/R7 검증은 미실시·불완전으로 명시한다. 빠진 참조를 추측 생성하거나 manifest를 재생성해 통과시키지 않는다.
- R4/R5 허용 범위의 한정된 초안 작업과 R6/R7 통합판정을 구분한다. 후보의 실패 중단 규칙이 모든 자료 조회 누락을 모든 작업의 일괄 차단으로 확대하지 않는지 확인한다. 해당 작업에 실제 필요한 의존성이 실패하면 작업을 중단해야 한다.
- R6 CI 원문의 필요 부분만 포함한 경우, 그 문맥을 실제 질문/확인 범위로만 읽는다. R6 통합 검증·새 품질 검수·회사 승인을 수행했다고 보고하지 않는다.
- checkpoint 복구는 요청된 대상·정확한 snapshot/hash·현재 대상의 변경 감지·다른 파일/backup 불변을 검증한다. 단순 파일 존재·복구 선언은 성공 증거가 아니다.
- R8-4의 평가 설계 분리·새 미사용 사례는 필수 잔여다. 이번 개발시험을 그 대체나 full R8 완료로 사용하지 않는다.

후보와 fixture manifest가 나오면 위 조건을 실제 경로/내용으로 대조한다.
