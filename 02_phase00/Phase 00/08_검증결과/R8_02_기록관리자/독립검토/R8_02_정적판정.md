# R8-2 기록 관리자 후보 정적 판정

2026-10-15 · `video-record-steward 0.2.0-draft.2`

**정적 검토 통과. 역할별 합성 개발시험으로 진행 가능하다.** 실제 쓰기·backup 실패·checkpoint 복구 행동은 아직 검증하지 않았으며 후보 채택·R8 완료 판정이 아니다.

초기 후보에서 저장 후 검사 실패/부분 저장 시 ‘성공으로 발표하지 않는다’는 규칙만으로는 이미 바뀐 활성 초안이 남을 수 있다는 결함 1건을 지적했다. draft.2는 현재 바이트가 내 쓰기와 같을 때 영향 대상을 작업 전 backup으로 복구하고 SHA/관련 검사를 확인하도록 명시한다. 외부 변경·복구 실패는 덮어쓰지 않고 미복구/사용 중단으로 남기며 새 결과의 격리/미반영·실패 흔적 보존도 포함했다. 문구상 결함은 해소됐다. 이전 draft.1 두 파일의 실제 backup 바이트/hash도 대조했다.

후보 4파일과 구성안내를 읽고 R4/R5/R6/R7의 현재 안내·코드와 대조했다. R4 기본 도구는 코드 위치의 BASE를 사용하므로 호출 DB의 코드/규격과 맞춰야 한다는 지침이 정합하다. R5 `inspect(data,base=루트)`, R6/R7 `--base`, R4 `--output`의 DB/08_검증결과 한계도 현재 코드와 맞는다. 후보 Markdown 참조 3개는 실제 파일로 연결된다.

고정 운영 정본·원본·규격 예시·snapshot을 보존하고 별도 초안으로 작업하는 규칙이 있어, ‘실제 파일 수정’ 문구가 알려진 고정 원문 덮어쓰기를 의무화하지 않는다. 요청된 필드·필요 판본·명시 연결만 수정하고 원본 identity/hash·시간/PTS·좌표·수치의 추측 보완과 schema_version만의 구형 강제변환을 금지한다. backup 이전 쓰기·충돌 우회·타인 변경 덮어쓰기도 금지한다.

R5 별도 적용 초안, R6 실제 질문/답변 문맥, R7 별도 참조와 미검수/보류/비적용·필수 누락을 구분한다. CI 최신성 회신을 새 품질·회사 승인으로 전용하거나 구조 통과를 사실/사람/권한 승인으로 바꾸는 경로는 허용하지 않는다. 01-A/OCR/측정·새 디자인 창작의 경계도 유지한다. 후보에는 예정된 세 시험의 구체 ID·파일명·수치·정답이 들어 있지 않아 특정 사례 정답을 직접 삽입한 징후는 없다.

입력보존 대장 164파일을 hash 대조했으며 변경은 main이 신고한 안내/진행 4파일과 정확히 일치했다. 나머지 160파일은 동일하다. R7 고정목록 130개는 저장 hash와 모두 일치했다. 이는 정적 byte 보존 확인이며 R6/R7 live checker를 실행한 결과가 아니다. 읽은 D 파일별 경로·SHA·바이트 수는 `R8_02_읽은D파일hash.json`에, 초기 후보의 hash 증거는 `R8_02_초기후보_읽은D파일hash.json`에 따로 보존했다.

수행 fixture에서 평가문서/R7 전체 문맥을 제외하면 R6/R7 통합 확인은 미실시·불완전으로 남겨야 한다. D 운영의 정상 확인을 사본 통과로 전용할 수 없다. R4/R5 한정 작업은 해당 의존성을 실제 검사하고, 누락 자료는 추측 생성하거나 manifest 갱신으로 보완하지 않는다. 실제 행동시험에서는 허용 변경 diff, backup bytes, 실패 시 대상 불변/복구와 외부변경 분기를 별도로 확인해야 한다. R8-4의 평가설계 분리·새 미사용 사례는 계속 필수 잔여다.

D 운영 쓰기·후보 수정·행동시험·R6/R7 live 검사기는 실행하지 않았다. 정적 읽기/hash 대조만 지정 Python `-B`로 수행했고 C 독립검토 폴더에만 결과를 썼다.
