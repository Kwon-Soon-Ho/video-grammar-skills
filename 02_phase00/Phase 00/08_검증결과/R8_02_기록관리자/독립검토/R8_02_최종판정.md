# R8-2 기록·한맥 연결 관리자 최종 레드팀

2026-10-15 · 후보 `0.2.0-draft.3`

**후보 재구성·소량 합성 개발 비교·보완·출력/뷰어·레드팀 정리라는 한정 범위의 마무리를 뒷받침한다. 차단할 미해결 결함은 없다.** 이번 사람 출력 피드백은 아직 없으며 후보 채택·기본 전환·R8/Phase00 전체 완료·실영상 성능·회사 승인을 뒷받침하는 판정은 아니다.

## 실제 파일과 실패 보존

초기4회와 최종6회, 총10개 모델 시행의 실제 파일을 읽었다. 완료대장의 task/transcript/output SHA가 모두 실제 파일과 일치했다. 실행 전 fixture 목록과 현재 각 수행DB를 대조해 허용 밖 기존 입력 변경·삭제는 없었다. 새 수행DB 파일은 복구 과제의 요청된 실패본 보존2건뿐이다. 출력 JSON은 중복 key·비유한수·잘못된 문자까지 읽어 오류가 없었고, 실제 승인/사실/권한을 true로 만드는 알려진 flag도 발견하지 않았다. 이는 최종 파일 관측이며 실행 중 모든 임시 변경이나 작업 주체·이벤트를 인증하는 것은 아니다.

정상 수정의 실제 JSON diff는 모든 시행에서 R4 `/units/2/target_ref/version`과 자체 `/version` 두 곳이었다. 최종 v3 후보의 R5는 연결 SHA·연결 version·자체 version 세 곳만 바꿨다. 초기 후보/기존과 최종 기존은 연결 두 곳만 바꾸고 자체 version을 유지했다. 따라서 원본 identity·시간/PTS·좌표·수치·회사/색·검수/실행 상태 등 다른 값과 타입은 그대로다. 변경 전 각 파일의 실제 bytes/SHA와 일치하는 backup을 직접 찾았다. backup 생성 선행 순서는 transcript/작업 로그 근거이며 파일 존재만으로 시간 순서를 인증하지 않는다.

backup 실패 과제는 양쪽·두 iteration 모두 활성 초안과 기존 일반 파일 충돌 경로가 그대로다. 최종 양쪽의 별도 미반영 후보는 purpose와 자체 version만 달랐으며 참고 메모를 새 승인/검수 회신으로 이식하지 않았다. 구형 이관이나 원문 덮어쓰기, 다른 backup 위치 우회는 최종 산출물에서 발견하지 않았다.

정확 복구 과제는 양쪽 모두 요청 checkpoint SHA와 정상 사본을 대조했고 활성 R4의 최종 전체 bytes가 그 사본과 같았다. 복구 전 실패본의 bytes/SHA도 보존됐으며 기존 checkpoint·복구 요청·구형 추가자료는 불변이다. 구형 자료의 needs_migration/valid=false 및 읽기만 했다는 결과를 남겼고 실제 접수·이관·가짜 identity/시간 생성은 없다.

R4/R5 실제 검사 결과와 독립 채점자의 재검사 근거를 읽었다. 본 최종 레드팀은 검사기를 다시 실행해 시험 수를 늘리지 않았고 별도로 원문 SHA·실제 diff·연결 SHA/판본·보존 파일을 계산했다. R6 CI 최신성 회신은 질문/확인 범위만 설명하며 새 품질/회사 승인으로 쓰지 않았다. R6/R7 full 문맥 미실시, 합성 범위, 내용/측정·사람·회사·사용권한·운영 승인과 구조 검사의 차이가 결과에 남아 있다. 영상/OCR/측정·새 디자인·01-A 구현의 증거는 없으며 완료로 주장하지 않는다.

## 집계와 뷰어

| 과제 | 최종 후보 | 최종 기존 |
|---|---:|---:|
| 통합 기록·디자인 연결 수정 | 8/8조건 | 7/8조건 |
| 지정 backup 실패·승인 범위 | 8/8조건 | 8/8조건 |
| 정확 checkpoint 복구·구형 읽기 | 6/6조건 | 6/6조건 |

최종은 각 과제/구성1회, 6시행이며 후보22/22조건·기존21/22조건이다. 초기4회는 양쪽 과제1의 7/8 실패와 과제2의 8/8 결과로 따로 보존했다. 초기·최종을 합친 조건 판정은73/76이지만 서로 다른 버전의 반복 개발 이력이며 하나의 독립 성능 점수로 해석할 수 없다. 최초 기대22문자열·채점 경계는 그대로이고 비교정본·benchmark·각 grading의 기대항목/산술/SHA가 일치한다. 준비만 한6폴더와 초기 미실행2폴더를 모델 시행으로 세지 않았다. 시간/token·반복 분산을 지어내지 않았고 일반적인 효율/독자효과를 주장하지 않는다.

공식 뷰어 원본과 표시 사본의 embedded JSON은 같다. 최종6run의 grading과106개 출력, 이전4run의63개 출력 내용을 실제 파일과 대조해 모두 일치했다. 텍스트는 일반 파일 읽기와 같은 줄바꿈 정규화 후 비교했고 원시 bytes는 별도 보존한다. 최종 실제 출력의 표시 누락은 없다. 표시 사본의 외부 resource 태그는0이고 embedded JSON의 script 경계가 이스케이프돼 있다. 이는 HTML/데이터 구조 대조이며 브라우저 렌더·클릭·시각 검수를 실행하지 않았다.

## 경계와 남은 일

main 사실검사 코드의 CRLF/LF 재직렬화 assert 실패와 실제 byte-pinned backup으로 바꾼 보완을 별도 원문/hash로 확인했다. 이는 모델 시행 실패/무효가 아니다. 최종 기존 backup 실패 과제 안에서 KeyError를 고쳐 재실행한 이력도 같은 모델 시행의 transcript에 남아 있다. 본 독립 뷰어 감사에서도 객체 키 가정으로 KeyError1회가 있었고 초기 코드·실패/수정 기록을 보존했다. 모두 원시 수행 결과를 고치거나 시행을 제외하지 않았다.

기존 canonical14와 R7 고정130파일은 hash 불일치가 없다. D 착수164파일 중 변경은 신고한 안내/진행4파일뿐이며 후보5파일도 행동보완 확인서와 같다. global human_feedback_received=true는 R8-1 회신 범위이고 R8-2 received=false다. 이번 판정은 게시 전 상태를 고정한다. 이후 요청된 안내/진행5파일 갱신과 D R6/R7 조회·보존 확인은 main의 별도 게시 후 영수증으로 구분해야 한다.

실제 저장 후 검사 실패에 따른 자동 rollback, 복수 파일 부분 실패, backup 이후 외부 변경, 복구 실패 분기는 아직 행동 검증하지 않았다. 명시 checkpoint 복구 성공은 그 분기들의 증명이 아니다. 전체 R6/R7 현재 문맥·스킬 간 전달·기본 전환과 평가설계가 분리된 새 미사용 사례는 R8-4 잔여다. 같은 과제를 보고 보완한 재시험, 요청 문구의 해석 한계, main의 추가 R1 근거 전달과 비맹검 이력도 유지한다. 실제 사람 피드백·회사 내용/권한 승인·실영상 분석/납품 품질은 별도다.

독립 검토자는 D나 후보·수행 입력/결과·grading·뷰어를 수정하지 않았다. C 검토 폴더에서만 읽기/hash/JSON/HTML 구조 대조 코드를 실행했다. 게시 전의 D 상대경로와 C 작업폴더 상대경로별 SHA는 `R8_02_최종판정.json`에 고정한다.


## 게시 도구 긴 경로 보완 검토

첫 게시가 Windows 대상 경로266자의 copy2 오류로 중단됐다. 이전 게시 도구와 이 판정 원문은 게시보완이력/긴경로_수정전에 보존했다. 이미 복사된3,644파일은 C 원문 SHA와 모두 같으며 D 결과보고서/안내·진행은 아직 게시 전이다. 착수164의 기존 안내/진행4변경 상태와 이전 판정의 D 입력 SHA는 그대로다.

현재 수정은 safe()로 검증한 절대 대상에 Windows 긴 경로 prefix를 더하는 copy2 인자1곳과 보고서 설명1문단이다. 원래 파일명/경로·존재 파일 불일치 거부·SHA 대조·보존 정책은 유지된다. 제한 판정은 같고 현재 게시 도구/이 보완 기록의 C SHA만 갱신했다. D 쓰기나 게시 재실행은 하지 않았으며 실제 재개 성공/게시 후 보존·R6/R7 확인은 별도 영수증이 필요하다.


## 긴 경로 SHA 재열기 보완 검토

두 번째 게시는 긴 대상 복사 뒤 일반 경로로 SHA를 다시 읽는 단계에서 중단됐다. 보고서/진행은 게시 전이고 기존 판정의 D173경로와 C 결과는 게시 도구 외에 같다. 직전 도구/판정 원문은 게시보완이력/긴경로_해시보완전에 보존했다.

현재 exact는 safe() 검증 뒤 만든 같은 io_dst를 폴더 생성·존재 확인·복사·SHA에 일관되게 쓰며, 상대 manifest는 원래 dst 기준을 유지한다. 다른 실행 AST는 그대로이고 이력 설명만 두 중단으로 정확화했다. 작성자의 현재 코드SHA에 연결된290자 신규복사/기존사본재개 시험과 초기 길이설정 실패 원문을 읽었고, 실제 남은290자 사본의 바이트/SHA도 직접 확인했다. 본 검토는 그 IO 시험이나 게시를 재실행한 것이 아니다. 제한 판정은 유지하고 현재 도구/보완 기록 SHA를 갱신했다. 게시 성공/후속 보존·R6/R7 조회는 여전히 별도 영수증이 필요하다.
