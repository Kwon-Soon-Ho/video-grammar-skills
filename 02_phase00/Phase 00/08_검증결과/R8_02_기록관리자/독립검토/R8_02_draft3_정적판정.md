# draft.3와 iteration-2 정적 판정

2026-10-15 · **후보·helper·iteration-2 fixture 정적 검토 통과.** 동일 과제 재시험을 진행할 수 있다. 차단할 미해결 정적 결함은 발견하지 않았다. 실제 새 후보 수행·helper 단위시험·채점기는 실행하지 않았다.

`판본대조.py`는 Python 표준 라이브러리만 사용한다. 코드와 AST에서 파일 쓰기·네트워크·다른 프로세스 실행을 발견하지 않았다. content_edit은 같은 논리 기록의 ID/schema_version 보존과 바이트 변경 시 소유 version 변경을 대조한다. 이는 실제 R1 계약의 메타데이터 수정도 새 판본으로 보존한다는 규칙과 맞는다. 정확 복구는 checkpoint SHA/after 바이트 일치를 대조하며 손상된 before JSON을 파싱할 필요가 없고 새 판본을 강제하지 않는다.

CLI는 before/after 경로를 필수로 받고 checkpoint와 명시 SHA가 필요한 분기를 검사한다. 파일 읽기·JSON/문자·깊이 오류는 실패로 남긴다. 루트/경로 허용성을 자체 강제하지 않으므로 스킬이 지정한 허용 입력만 넘겨야 한다. helper는 자동 수정/판본 부여·허용 필드와 수치 보존·전체 R4/R5 구조/참조·checkpoint의 업무상 정당성·외부변경·권한 검사를 대신하지 않는다. 이 한계가 후보 참조에 명시돼 있으며 backup/외부변경 감지/실제 복구 책임은 기존 절차에 남아 있다. 내용/회사/운영 승인 flag도 false다.

후보 5파일 SHA는 행동보완 확인서와 일치한다. D helper, C 원문, 저장된 12조건 단위보고의 코드 SHA도 같다. 12/12는 작성자의 좁은 helper 시험 결과를 읽은 것으로 독립 재실행 성적이 아니다. 변경한 draft.2 3파일은 C 후보보존과 D backup에서 기존 SHA를 확인했다. 운영 old14와 R7 고정130파일도 다시 hash 대조해 불일치가 없다.

초기 완료4run의 출력·transcript·grading이 남아 있다. 저장된 grading은 과제1 양쪽7/8, 과제2 양쪽8/8이며 R5 자체 판본 누락 실패를 삭제하지 않았다. 과제3 미실행2run은 별도 이력에서 prepared/ungraded로 남아 있다. 초기 공식 뷰어 SHA는 확인서와 일치한다. task의 ‘연결만’ 해석 한계와 main이 채점자에게 추가 R1 근거를 보낸 비맹검 이력도 기존 채점/요약에서 확인했다. 이번 정적 검토는 그 과제를 새로 재채점한 것이 아니다.

iteration-2의 active 6run을 실제 읽어 fixture_before/포함 원문 hash와 대조했다. 모두 일치하며 기존/수정의 비스킬 입력265·267·268개는 각 쌍과 최초 준비본 사이에 같다. task는 해당 원래 run 절대경로만 정규화하면 양쪽 및 최초 과제와 모두 같다. loaded new5/old2파일은 실제 후보/기존 원문 SHA와 일치한다. 제외한 평가 경로/evals·R7 평가계획·완료보고는 수행DB에 없으며 6dispatch는 아직 prepared 상태다.

기존22조건과 채점 경계/범위는 그대로다. 평가항목의 달라진 키는 문서 version=0.1.1과 candidate_version=draft.3뿐이다. 새 SHA는 고정기록과 같으며 prior_model_trials=4, 이번 iteration dispatch=0을 구분한다. 새 문구/helper는 R1 공통 규칙 보강이고 특정 fixture ID·수치·정답을 코드에 삽입하지 않았다. 다만 같은 사례를 보고 개선한 개발 재시험이므로 새 미사용 평가나 독자효과 증명으로 보고할 수 없다.

R6/R7 전체 문맥은 여전히 범위 밖이다. 실제 수행의 허용 쓰기·판본·backup·실패안전·복구는 이후 결과로 확인해야 한다. R8-4의 평가설계 분리·새 미사용 사례 확인도 남아 있다. D에는 쓰지 않았고 C의 정적 근거/판정만 작성했다.
