# R8-2 수행 fixture 판정

2026-10-15 · **수정 후 정적 fixture 검토 통과.** `0.2.0-draft.2`의 역할별 합성 개발 시행을 시작할 수 있다. 실제 수행/채점·검사기 재실행은 하지 않았다.

초기에는 R6 `출처와사용범위_연결목록.json`의 `original_record`에 R3/R8 평가/이식 설계 문단이 복제돼 있어 보완을 요청했다. main은 R6 입력을 실제 CI 회신/질문·접수 문맥과 안내 7파일로 좁혔고 문제 파일을 제외했다. 수정 전 준비6run은 `시험준비이력/평가문단_간접포함_수정전/iteration-1`에 그대로 남아 있으며, 간접 문단과 원래 SHA가 그 6사본에 모두 보존된 것을 확인했다.

수정 후 active 6run의 실제 파일을 읽어 `fixture_before` hash와 대조했다. 불일치·추가 파일은 없다. 포함 목록 262개 파일은 모두 실제 원문 SHA와 일치하고, 제외 목록 568개 경로 중 수행 DB 안에 남은 경로는 없다. 알려진 간접 평가 문단도 active 입력에 없다. 남은 평가 관련 검색 결과는 운영규격/한계 안내의 역사 점수 재사용 금지나 일반 규격 내용이며 이번 수행의 정답/채점 설계 문단과 구분했다.

각 과제의 비스킬 입력은 기존/수정에서 각각 265·267·268개 파일이며 경로→SHA 전체 지도가 같다. task.txt의 해당 run 절대경로만 `{RUN}`으로 치환해 비교한 실제 텍스트도 세 쌍 모두 같다. 각 task SHA는 dispatch와 일치하고, loaded skill 원문은 앞서 독립 검토한 D 기존 스킬/수정 후보 hash와 6run 모두 일치한다.

22조건 평가항목은 수행 DB 밖에 있고 고정기록 SHA `c8ee5024c94d73e995b3a72406b35538407906c8bf20edc9e0792dde3b90f4ed`와 일치한다. 관찰 시점의 6 dispatch는 모두 `prepared_not_executed`다. 기준은 요청된 실제 수정·backup 실패·정확 복구와 검수/합성 경계에 대응하며, R6/R7 완전 자료 누락을 실패로 세지 않는 범위도 명시한다.

R4/R5/자산 preflight 통과는 main이 저장한 결과를 읽었으며 독립 재실행 성공으로 보고하지 않는다. 이 사본에는 full R6/R7 문맥이 없으므로 그 정상 결과나 새 품질/회사 승인을 주장할 수 없다. 수행자가 평가항목·포함/제외 목록·이전 준비본·다른 run을 열람하지 않는지는 실제 실행 흔적에서 추후 확인해야 한다. 이 개발시험은 맹검·미사용 평가·스킬 독자효과 증명이나 R8-4의 평가설계 분리/새 사례 확인을 대신하지 않는다.

독립 근거는 `R8_02_fixture정적근거.json`에 실제 경로·SHA·바이트 수와 쌍별 대조 결과로 보존했다. C 검토 폴더에만 썼으며 D 쓰기·후보 작성·수행자/채점기 실행은 하지 않았다.
