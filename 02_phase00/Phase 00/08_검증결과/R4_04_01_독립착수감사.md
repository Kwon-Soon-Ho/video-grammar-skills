# R4-4 통합·이관 착수 감사

2026-10-15. **착수 감사·통합 설계 검토만 수행했다. 구현·이관·실제 영상 분석은 하지 않았다.** 기존 4단위·5판정, 미상 보존, 시간 A, 좌표 A, 사람 내용검수와 초안 권한 결정은 유지한다. 검토 중 사용자가 **이관 정책 A(새 통합 기본·부족한 구형은 원문/누락 접수함·추정 금지)**를 확정했으므로 이를 반영했다.

## 우선 막아야 할 위험

1. **중복 정본:** 현재 좌표 계약 안에 근거 계약, 그 안에 시간 계약이 있다. 새 DB의 별도 시간·자료·대상 목록과 중첩본을 각각 수정 가능하게 만들면 서로 다른 사실이 된다. 기록당 한 표현을 정본으로 정하고 기존 검사기에는 읽기 전용 view/adapter를 전달한다. 평탄화·모듈형 경로는 구현 선택이지만 중복 사실은 허용하지 않는다.
2. **이관 중 사실 생성:** 기존 설명예의 영상 경로/hash/시간은 null, 프레임은 없다. 새 계약의 필수 hash·PTS를 맞추려고 fixture의 반복 hash·가상 시간을 채우지 않는다. 미제공 자산과 미작성 분석 계약을 명시적으로 보존하고 원본 JSON snapshot/이관 사유를 따로 둔다. JSON 파일 hash를 영상 hash로 사용하지 않는다.
3. **분류 범위 이동:** 기존 설명예는 segment에 layout 태그가 있지만 R2는 layout을 state에만 허용한다. 프레임을 state로 만들거나 실제 상태를 추정해 태그를 옮기지 않는다. 원래 계획·후보/legacy 주석을 보존하고 실제 범위·주장 근거가 없는 판정은 미검토/미상으로 남긴다. R2 state와 R4 target의 screen_state는 명시적으로 연결하며 object를 다섯 번째 분석 단위로 만들지 않는다. beat는 상태 경계 교차·동시성을 유지한다.
4. **좌표 보류의 무조건 해제:** R4-2 검사 287~288/311의 공간 supported 차단을 ref 존재나 formula_checked로 대체하면 안 된다. 표본→같은 자료/대상/frame→geometry/space 버전→명시한 변환 경로→량/단위/앵커→오차·근거·사람 검수까지 연결해야 한다. 미상·미지원·비영 오차/전파·quantity=other는 현재 계약으로 승인하지 않는다. 실제 내용검수 전에는 대기를 유지하고 사실/사람 인증/회사/운영 승인 flags를 true로 바꾸지 않는다.
5. **검수 context 누락:** 현 context_hash는 시간/자료/대상/근거/주장과 근거·시간 검사기 hash만 고정한다. 새 공간/변환/geometry/mapping, 수치 계산식·표본 연결, 판정에 영향을 준 분류/정본과 통합·좌표 검사 의존성도 고정하지 않으면 좌표 변경 후 옛 receipt를 재사용할 수 있다. 새 계약/이관은 기존 receipt를 자동 유효화하지 않는다.

## 연결할 최소 필드

| 묶음 | 통합에서 정할 연결 |
|---|---|
| 기록/자산/의존성 | 기록 ID·버전, schema ID·버전/hash, 원본 자료 ID·버전/hash·출처/접근 선언; taxonomy/profile의 정확한 snapshot |
| 4단위와 분류 | 영상→설명 구간→화면 상태, 동작/대상/상태교차 참조; 축별 허용 단위, 5판정·이유·후보·주장/근거 pin |
| 시간·시나리오 | R4-1의 시간축/구간/프레임 단일 참조; 원문/전사/OCR/계획 구분과 인용/기간; 임의 FPS 환산 금지 |
| 근거·수치·공간 | support/oppose/context, 측정 표본·량/단위/계산근거·오차와 R4-3 geometry/space/경로의 버전 연결 |
| run | 미실행/null 사유 또는 실행 종류(수동입력/검사/이관/추출 구분), 입력/출력 snapshot, 도구/모델·설정 버전, 시각·부분실패/한계. 이관 시각을 과거 추출 시각으로 쓰지 않음 |
| metadata | 실제 확인값/미상·출처·단위/stream 연결, 원본 native 표기와 표준화 값 구분. 해상도/SAR/회전/FPS/길이의 중복 수정 가능한 정본을 만들지 않음 |
| 검수·이관 | 구조 검사/내용 검수/회사 규칙 승인 구분, 대기/충돌/stale; source 경로+hash+버전→새 출력/ID 대응·미이관 사유·rollback |

`$ref`는 고정 버전의 로컬 schema 등록부로 해석하고 `$id`/base URI/JSON Pointer 경로를 검사한다. 실행 중 웹에서 schema를 가져오지 않는다. 내장 schema를 계속 쓰면 원본과의 hash/검증 본문 일치를 검사한다. schema 형식 검사만으로 참조 해석·필드 연결 검사를 대신하지 않는다.

## 실제 기존 파일 범위와 호환

Phase 00 내부의 JSON 173개를 top-level 형상으로 조사했다(backup/.환경/.git 제외, 파싱 실패 0). legacy 기록 후보는 5개이며 모두 동일한 예시 record_id와 synthetic_example, 영상 path/hash=null이다. 04의 설명 정본 1개, 06의 스킬 평가 입력 1개, 08의 과거 평가 입력·변경 전후 3개다. 이 수는 외부 운영 DB의 전수 조사나 실제 데이터가 없다는 증명이 아니다. 세 독립 설명 계약도 합성이다. 전체 경로/hash는 착수감사.json에 남겼다.

확정 A에 따라 04의 부족한 설명예는 원문/hash·누락 보고와 함께 접수함으로 **사본 보존**하고 정식 분석/회사 문법 검색에서 제외한다. 새 통합 설명예는 별도 합성 자료로 만든다. 06 평가 입력과 08 평가 이력·backup은 그대로 유지하고 현행 호환용 새 평가 입력은 따로 만든다. 같은 record_id라고 합치거나 덮어쓰지 않는다. 실제 DB는 사용자가 경로·대상을 지정한 뒤 별도 manifest/dry-run 대상으로 받는다.

기존 세 스킬의 작업기준은 자료검증.py를 호출한다. 이 도구의 validate_record는 오류 list를 반환하며 CLI는 --record/--output을 사용한다. 새 dict 반환을 같은 함수에 조용히 넣으면 호출자가 오판할 수 있다. 버전별 검사 경로/출력 범위를 명시하고, 지식조회.py가 import하는 catalogs/BASE도 유지·회귀한다. 과거 형식을 검사한 결과를 새 통합 검증 완료로 표시하지 않는다. 스킬 지침/참조/eval·실행안내·버전목록·인계 링크를 함께 갱신하되 스킬 목적/권한 확대나 재구성은 별도 검토 범위다.

## 최신 연결 설계의 보완점과 사람 판단 범위

새 진행안·통합 연결 초안은 단일 정본, 프레임/상태 구분, 상태교차 동작, 분류 출처, 근거/좌표 연결, run, context 확장, 사실/운영 분리를 적절히 반영했다. 다음은 2단계 전에 구체화할 항목이다.

- 통합 schema의 정확한 모듈 경로와 로컬 `$ref` 등록·ID/version/hash 정책, state→screen_state 명칭 대응을 명시한다.
- metadata 항목별 출처/미상·중복 정본 정책과 수치 표본의 geometry component/량/단위/앵커 대응을 구체화한다.
- 접수함도 최소 규격을 둔다: 접수 ID, 원문 경로/bytes hash·구형 버전·원래 ID, 누락/미판정 사유, 사본 위치, 처리 이력, 분석/회사 검색 제외. 접수 성공을 분석 valid/supported로 표시하지 않는다.
- 구형을 새 기본 진입점으로 받았을 때 접수함 결과로 내보내고 예전 오류 list 통과를 통합 valid로 전달하지 않는 호환 규칙을 명시한다.
- 연결 초안의 migration.link는 아직 ‘사용자 선택 대기’다. 확정 A와 사용자 결정 근거·시각을 기록하고 검토안은 역사 자료로 남긴다. 결정 상태 표기 보완이며 새 허가 요청이 아니다.

이미 정한 4단위·미상·시간/좌표 기준·사람 검수·초안 권한·이관 A는 다시 묻지 않는다. 새로 발견한 실제 DB 경로/대상만 확인이 필요하며 현재 자료만으로 회사 DB 전체를 이관했다고 주장하지 않는다. 평탄/중첩 구현 선택은 원칙이 같으면 작업자가 결정할 수 있다.

공간 supported는 이번에 자동으로 허용된 것이 아니다. 새 게이트를 설계하더라도 실제 검수 전 대기는 유지한다. 비영 오차·미지원량까지 보류를 완화하거나 회사 승인/스킬 권한을 바꾸려면 기존 결정 범위를 벗어나므로 최소 4지선다와 추천안을 따로 검토한다.

## 권장 다음 순서와 완료 조건

대상 manifest·원본 backup → 단일 정본/참조·4단위·미제공 경로 설계 → run/metadata·공간 표본/context 연결 → 새 버전 schema와 버전별 검사 → dry-run 이관·필드 대조 → 이전 누락 및 정상/오류/미해결 회귀 → 독립 레드팀 → 문서/세 스킬 참조·평가/도구 호환 확인·인계 순서가 타당하다. 기록 수·ID 대응·원본 hash 보존·재실행 중복 방지·rollback과 실제 검수 대기까지 확인해야 한다. 기존 시간 4누락·근거 7유형·공간 결함 및 각 독립 규격의 양성을 통합 경로에서도 재검사해야 한다. 개별 단계의 통과 개수를 더해 통합 완료라고 판정하지 않는다.

현재 판정은 **착수 감사와 설계 권고 완료, 통합/이관 구현 미수행**이다. 01-A 추출·자동 분류/측정·미디어 가공과 실제 영상 내용검수·회사 승인·업무 효과 검증은 이번 범위 밖이다.
