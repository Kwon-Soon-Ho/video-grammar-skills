# R4-1 보완 결과와 독립 레드팀

2026-10-15. **시간·프레임의 독립 기록 계약과 합성 검사 범위 완료. R4 전체는 진행 중이다.** 사용자 A(재생0초+원본PTS·변환근거 보존)를 반영했다. 최종 DB 통합 전의 승인 전 초안 v0.1.0이며 회사 사실/규칙 승인과 다르다.

## 이번에 한 일

기존 스키마·검증기·R2 인계를 읽고 정상 대조 1건과 잘못된 시간 입력4건을 재현했다. 독립 감사에서도 모두 같은 결과였다. 이어 공식 W3C/FFmpeg/JSON Schema의 관련 본문과 시간 상수를 확인해 재생 시간·원본 PTS·원점·순간/구간·불확실성·프레임 선택/번호 계약을 정했다. 전체 표준·모든 코덱·실영상 분석을 조사한 것은 아니다.

| 정리한 내용 | 적용 예·오류 예 |
|---|---|
| 재생0초와 원본시각을 분리 | PTS 시작90000,단위1/90000,프레임360000→3초 |
| 시작 포함·끝 제외 | [0,3)에서3초는 다음구간/문맥프레임. 내부근거로 쓰면 거부 |
| 순간/미상/오차 | range0길이 거부,instant별도;미상을0초로채우지않음;오차로범위초과합법화금지 |
| 원본 프레임과 선택 방식 | requested/actual 분리,음수PTS 보존,VFR에서FPS환산금지,추정PTS미해결 |
| 참조·자기일관성 | 부모순환/다른시간축/없는ID/번호시간충돌거부. 사실 검증과 구분 |

## 레드팀에서 발견한 문제와 수정

| 발견 | 보완 |
|---|---|
| duration0/frame_count0에도 미매핑·번호미상의 프레임이 등록됨 | 해당 시간축의 모든 프레임 등록 거부 |
| 동일 자산/스트림의 시간축을 ID만 바꿔 중복 등록 | 원본 스트림마다 단일 시간축;파생은 별도 자산/변환 계약으로 인계 |
| PTS끝 개행이 정수로 통과 | 문자열 종단·표기 엄격화,해시 길이도 확인 |
| 동일ordinal이 다른시간/표시순서가 역전됨 | original_pts+mapped의 선언된 순서 비교. 동일PTS의다른ordinal은임의금지안함 |
| instant 부모 밑 unknown 자식 규칙 모호 | 모든instant부모 거부 |
| 자체 검수:미정 sentinel/오차끝점 | AV_NOPTS_VALUE는null/unknown;순간오차가제외끝점에닿으면미해결 |

현재 정상·오류·미해결 합성 시험 **75/75 통과**. 오류 입력은 기대한 오류 유형도 확인했다. 독립 레드팀은 자체 입력으로 수정 전 문제를 재현하고 최종 후보를 다시 검사했다. 독자 입력20/20·실행예외0이며 개별 독자 입력의 원문 전체는 저장하지 않았다. 재실행 가능한 원문과 검사 코드는 내장75건에 보존했으며 독립 검토 메시지 요약과 당시 검사기/결과의 해시를 함께 기록했다. 검사 개수는 분석 정확도·업무 효과의 점수가 아니다.

## 아직 남은 것

**기존 `최소기록_스키마.json`과 `자료검증.py`의 시간누락4건은 아직 남아 있다.** 호환 초안을 중간에 바꾸지 않고 R4-4에서 기존 예시 이관과 함께 수정·재검사한다. 새 시간 검사기의 대응 수치 반례는 차단했으나 실제 evidence의시간/대상 연결은 R4-2에서 설계해야 한다. 따라서 현재 기존 검사만으로 시간 검증 완료라 판정하면 안 된다.

R4-2: 근거가 어느 자산/시나리오/상태/동작에 연결되는지, 주장이 어떤량/시간범위를 말하는지, 관측/추정/의도를 분리하고 버전·근거 충분성·미해결을 정한다. R4-3: 좌표 원점·단위·해상도·회전/크롭/리사이즈 관계. R4-4: R2의4단위/5판정상태/분류대상·run/metadata·Hanmac참조를 최소 DB에 통합하고 기존 기록 이관/회귀를 수행한다.

실제 파일 존재/hash 진실성, 근거 ID 본문, PTS/원점 정확성, nearest 최단선택, ordinal 실제프레임대응, 전체프레임인덱스는 이번 단계에서 확인하지 않았다. 회사 규칙 승인은01-B, 분석·추출 구현은01-A와 구분한다. 기존 맞춤3스킬과 한맥/R2/R3 정본은 변경하지 않았다.
