## 세 규격 재사용과 통합 프로필

시간·근거 정본과 검사기는 변경하지 않는다. 공간 정본도 변경하지 않는다. 통합 스키마는 세 규격을 로컬 본문으로 포함하고 원문 hash를 고정한다. 현재 원문에 원격 $ref가 없어 네트워크 조회가 필요하지 않다. 동일 본문을 여기저기 독립 수정하지 않도록 통합 스키마의 원문 pin을 검사한다.

유일한 공간 구조의 확장은 **좌표를 아직 기록하지 않은 경우 spaces=[]를 허용**하는 통합 프로필이다. 공간이 없으면 변환/기하/매핑은 참조 검사상 담을 수 없다. 시간·근거가 식별된 새 기록에 허위 프레임이나 공간을 만들 필요가 없다. 원본 identity 자체가 없는 구형 자료는 이 예외로 수용하지 않고 접수함에 보존한다.

## 좌표 표본 연결과 한계

R4-2의 공간 표본 px와 R4-3의 raster_px는 해당 raster 성분에 한해 같은 단위로 대응한다. normalized는 그대로 구분한다. geometry의 표본 근거·대상·원본 프레임, x/y/width/height 성분, 단위, 실제 공간 ID/버전을 대조한다. mapping을 쓸 때는 source geometry와 결과 geometry까지 따라간다. R4-3 mapping 자체에는 version이 없어 참조 version은 소유한 공간 계약 버전에 고정한다. 통합 context는 실제 mapping 내용도 hash에 포함한다.

표본 숫자는 geometry의 유리수 성분과 정확히 대조한다. 소수로 표현할 때는 exact_decimal 또는 자리수 0~12를 명시한 rounded_decimal(half-even)을 쓴다. 이것은 저장 표현의 반올림이며 측정 불확실성/허용 오차가 아니다. px 변환·단위 변환을 임의로 추정하지 않는다.

시간에 따른 스칼라 표본은 같은 축을 사용하고, 프레임별 명시 공간 기준/변환 계열이 다르면 비교 미해결로 남긴다. 동일 크기 화면이라고 카메라/대상 추적이 검증됐다는 뜻은 아니다. 모델 위치·잘린 결과·미상/비영 오차는 관측 사실로 확정하지 않는다. single_sample_component의 단일 성분 결과/표본/단위 일치만 자동 검사한다. 다른 계산법·속도/가속도·오차 전파·추적은 내용 검수 대기다. 새로운 자동 영상 분석/수치 추출은 01-A에서 한다.

**R4-2의 공간 supported 보류는 유지한다.** R4-4에서 표본 연결을 실제 검사하지만, 연결 검사를 사람의 측정 내용·권한·승인 대신 사용하지 않는다. 공간 연결 상태 linked도 사실/오차 검증을 뜻하지 않는다. 사람 내용 검수·검수자/행위·권한과 운영 승인은 R6/R7 및 실제 자료 확보 후 인계한다.

# R4-4 통합·이관 결과와 레드팀

2026-10-15. **시간·근거·좌표를 연결한 v0.2 기록 계약, 구형 원문 접수/누락 보고, 기본 검사 도구 전환 범위를 완료했다.** R4의 Phase 00 기록 기반 검수는 마쳤다. 전체 Phase 00은 R5~R8 잔여가 있으며 01-A는 시작하지 않았다.

## 무엇이 달라졌는가

예전에는 ‘구간에 태그·프레임·모션을 적는 JSON’이었다. 지금은 **영상 전체 → 설명 구간 → 화면 상태**, 그리고 상태를 가로지를 수 있는 **짧은 동작**의 대상을 나누고 시간·근거·좌표와 연결한다. 프레임은 화면 상태를 확인하는 표본이며 상태 자체가 아니다.

| 연결한 것 | 적용 예 | 막는 반례 |
|---|---|---|
| 시간 | 재생 0초와 원본 PTS·구간/프레임을 같은 정본으로 연결 | 다른 시각·구간 제외 끝점·원점 모순을 근거로 사용 |
| 근거 | 원본/파생 자료 pin → 대상/선택 부분 → 지지·반대·문맥 주장 | 파일/대상 ID만 있어 관측·의도 확인으로 처리 |
| 좌표 | 표본 → geometry → x/y/폭/높이 → 단위/필요시 변환 결과 | px/normalized 혼용·없는 공간·서로 다른 성분·오차 누락 |
| 분류 | 단위별 허용축과 classified/unknown/not_applicable/other_candidate/not_assessed | 구간 태그를 화면 상태로 상속·미상을 정답으로 채움 |
| 실행·검수 | 구조화 run/metadata·한맥/용어 pin·통합 context | 임의 run 객체를 실행 증명으로 사용·옛 receipt를 변경 후 재사용 |

데이터는 spatial_contract 안의 근거 계약, 그 안의 시간 계약에 한 번만 저장한다. units와 좌표 표본은 ID/버전을 참조한다. 별도 시간/근거 사본으로 모순을 만들지 않는다. 좌표 미기록 영상은 빈 공간 목록으로 보존할 수 있지만 원본 identity 미상을 가짜 값으로 채우지는 않는다.

## 실제 구형 자료는 어떻게 처리했는가

현재 찾은 5개는 모두 설명용·스킬 시험·과거 평가 자료다. **5개 원문을 수정하지 않고 접수함에 사본·누락 보고로 보존했다.** 원본 영상 버전/hash·시간·화면 상태가 없어 실제 회사 영상 기록으로 바꾸지 않았다. JSON 원문 hash와 영상 hash를 구분했다. 동일ID라도 출처가 다른 파일을 별도로 보존하고 같은 원문의 재실행은 불변이다.

v0.2 합성 설명 예시는 별도 규격 예다. 구형 예시에 가짜 hash/PTS를 채운 이관본이 아니다. 현재 자동 도구는 copy-only 접수·누락 진단·검사이며, 구형 의미 전체를 추정해 자동 변환하는 도구는 만들지 않았다. 원본과 의미 대응이 확인된 이후에만 새 통합 초안을 작성한다. 실제 회사 영상 분석 기록은 **0건**이다.

## 사람 검수·남은 일

구조 통과·좌표 연결·context 일치는 화면/대상 해석·시간/픽셀 실측·실행 사실·실제 사람 검수·회사 승인과 다르다. 필요한 내용은 대기 목록으로 남긴다. 실제 자료가 없어 이번에 실제 영상의 내용 검수나 검수자 인증은 하지 않았다. 공간 측정의 supported 보류도 유지하며 R6/R7의 권한·내용 검수로 인계한다. 속도/가속도 자동 분석·오차 전파·ROI/OCR/추적·영상 가공은 01-A다.

# 무엇에 이름을 붙이는지 구분하기

사용자가 선택한 A안에 따라 영상 전체·설명 구간·화면 상태·짧은 동작을 구분한다. 컷 전환은 보조 정보다. 아래 단위는 모션그래픽을 기록하기 위한 프로젝트 기준이다.

| 단위 | 쉬운 예 | 나누는 기준 |
|---|---|---|
| 영상 전체 | 한 편의 기술 설명 영상 | 제공 파일과 버전 |
| 설명 구간 | 침투수의 원인을 설명하는 부분 | 설명하는 주제·질문이 바뀌는지 |
| 화면 상태 | 제목만 보임 → 제목과 도표가 함께 보임 | 정보 역할·배치·주석 대상이 달라지는지 |
| 짧은 동작 | 도표 공개·강조 이동·숫자 변화·정보 유지 | 어느 대상이 어느 시간에 변하거나 유지되는지 |

화면 상태는 완전히 멈춘 화면이 아니다. 제목을 읽는 동안 배경 입자가 움직여도 같은 정보 구성이 유지될 수 있다. 짧은 동작에는 움직임뿐 아니라 특정 대상의 유지·정지 같은 시간 사건도 포함한다. 이름이 고정된 최대 길이를 뜻하지는 않는다.

동작은 화면 상태 사이를 가로지를 수 있고 여러 동작이 겹쳐 발생할 수 있다. 그래서 모든 동작을 한 상태의 배타적인 자식으로 묶지 않는다. 레이아웃이 변하는 중에는 이전·이후 상태와 전환 동작을 구분하며, 중간 화면을 완성된 새 레이아웃으로 단정하지 않는다.

컷이 바뀌어도 같은 설명을 이어갈 수 있고, 컷 없이 설명 주제가 바뀔 수 있다. 경계가 불분명하면 후보와 이유를 남긴다. 프레임 간격이나 컷 검출만으로 설명 구간을 확정하지 않는다.

| 분류축 | 기록하는 단위 |
|---|---|
| 영상 유형 | 영상 전체·설명 구간 |
| 전달 목적 | 설명 구간·화면 상태·짧은 동작 |
| 정보 관계 | 설명 구간·화면 상태 |
| 화면 레이아웃 | 화면 상태 |
| 모션 기능·관측 속성·시간 특성 | 짧은 동작 |
| 표현 속성 | 화면 상태·설명 구간 |

화면 일부에 붙인 태그를 영상 전체에 자동 상속하지 않는다. 관측이 충분하면 태그를 유지하고, 구현만 불명확한 경우 구현 주장을 별도로 남긴다. 예를 들어 확실한 크기 변화는 기록하면서 카메라/Scale 원인은 미확인으로 둘 수 있다.

**프레임은 표본이며 화면 상태와 다르다.** 현재 DB에는 asset/segments/frames/beats가 있고 별도 state 필드는 없다. [분류 운영규칙](분류운영규칙.json)은 의미 기준이다. 실제 저장 필드·상태와 동작의 참조·시간 경계 검사는 [R4](../09_다음단계인계/R2_R4.md), 구현은01-A에서 연결한다.

## R8에서 나눠 진행할 일

1. 현행 세 스킬과 공통 참조·평가 입력을 보존하고 각 스킬의 목적/입출력/실패 조건과 새 계약의 차이를 대조한다.
2. [외부 스킬 심층 검토](../08_검증결과/R3_03_보완결과와레드팀.md)와 [발표·설명 원본 목록](../05_출처와검토/R3_발표설명스킬_원본확보목록.json), [편집·화면 원본 목록](../05_출처와검토/R3_편집화면스킬_원본확보목록.json)을 확인한다. 실제 가져올 원문·참조·코드·의존성·라이선스와 필요한 부분만 다시 대조한다. 정적 검토/다운로드는 코드 실행이나 효과 검증이 아니다.
3. Anthropic Skill Creator의 현행 지침을 읽고 별도 작업 사본에서 맞춤 스킬을 재구성한다. 참조만으로 해결할 규칙을 대형 본문에 중복하지 않는다. Taste·웹 UI 규칙을 영상의 회사 필수 기준으로 복사하지 않는다.
4. 스킬별 소단계 초안→중간 목적 검토→테스트→레드팀→보완 순서로 진행한다. 기존 권한 안의 수정은 진행하되 새로운 목적·의미 병합/회사 필수화 등 판단이 생기면 최소4지선다와 추천안을 제시한다.
5. 적용/반례·없는 근거·모호한 자료·오래된 버전·서로 다른 회신 문맥·필요 사람 검수·기권을 평가한다. 기록 수정에는 허용 파일 외 변경, 로그/backup/diff·복구, 검사 실패 후 중단을 포함한다. 기존 예시만 외워 통과하는 평가를 피하고 별도 미사용 사례를 둔다.
6. 동일 과제·자료/기준 버전에서 기존/수정 스킬·필요시 스킬 없는 기준을 비교하고 모든 시행/실패를 보존한다. 문서/합성 검사는 실제 영상 성능이나 업무 시간 절감 성적과 구분한다. 시험 운영 범위가 바뀌면 구체 결과로 검토받는다.
