**영향:** 01-A 모델/DB 구현자가 이미 있는 state 계약을 다시 만들거나 beat의 부모를 잘못 작성할 수 있다. **보완:** 구형 DB 서술을 당시 v0.1 이력으로 한정하고 현재 v0.2 정확한 경로/키를 안내한다. 화살표는 “4종 기록 단위”로 쓰고 상태/동작은 설명구간 아래 별도 대상·동작의 상태 교차참조라고 명시한다. **재검사:** state/beat 두 sibling 구조와 상태를 가로지르는 beat 예시가 문서·schema·검사 모두 일치; 잘못된 state 자식 beat는 거부.

### T05 — P3: 실행 안내의 경로/쓰기/출력 제한이 서로 다른 시대 표현으로 남음

기존 기록관리자 references/작업기준.md는 `--output`을 Phase00 안으로 설명하지만 현재 자료검증.py는 08_검증결과 안만 허용한다. R1 실행예는 -B 없이 검사/조회/재생성을 나열한다. 구형 좌표시험 BASE는 D 절대경로다. 최신 후보의 기록연결기준.md는 실제 BASE 확인·08_검증결과 제한·검사누락 범위를 비교적 정확히 설명한다.

**영향:** 새 사용자의 C 사본 실행이 D 데이터로 읽기를 건너가거나 의도치 않은 pycache/조회문서 재생성·출력 실패가 생길 수 있다. **보완:** 원 고정 스킬 본문은 유지하면서 현행 실행안내에서 우선 계약/읽기와쓰기/구형역사도구를 명확히 하고 실제 호출 예제에 -B 및 실제 DB 루트를 명시한다. 스킬 후보 기본전환과 별개로 처리한다. **재검사:** 경로에 공백/한글인 루트에서 읽기 검사만 실행했을 때 입력 hash와 파일집합 불변, 생성기는 명시 실행에서만 출력, --output 허용/금지 위치 차이.
