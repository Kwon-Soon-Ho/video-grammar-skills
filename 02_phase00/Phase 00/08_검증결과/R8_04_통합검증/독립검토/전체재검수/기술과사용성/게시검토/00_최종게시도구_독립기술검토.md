# 최종 게시 도구 독립 기술 검토

2026-10-15. **발견한 게시 차단 결함은 보완을 확인했다. 아래 고정된 C 코드에 대해 남은 P1/P2 또는 확인된 실행 차단 결함은 없다.** 이는 게시 도구의 정적 검토와 국소 합성 확인 판정이다. 최종 출고 판정·freeze·실제 D 게시 성공을 대신하지 않는다.

- 검토 코드 `R8_04_최종게시.py` SHA256: **f07e306f1459f647f450eee9cc2f1d07f72c41f66636006c5b57aa4ec5d5b73b**.
- 보고 초안 SHA256: **d5d66513420a798bdbf9870fd7b015412746236eee7a177d2bda73d647e3446e**.
- 위 두 파일을 이 폴더 `검토본_최종게시.py`, `검토본_최종보고_초안.md`로 보존했다. 이 해시 이후 코드/초안 변경은 이 판정의 자동 적용 대상이 아니다.

## 수행 범위

게시 코드·공통지원의 save/safe·보고 초안을 직접 읽었다. main/prepare는 호출하지 않았고 D를 수정하거나 freeze를 생성하지 않았다. 실제 시험 수행자·기대항목·출력·채점 본문은 열지 않았다. C의 자체 합성 파일만 사용하여 io/exact/owned/record_failure 및 main 내부의 **읽기·assert 전용 final_integrity 함수만 추출**해 시험했다. sources도 모든 원본 루트를 작은 C 합성 폴더로 바꾼 후에만 호출했다.

다음 확인은 게시 보조 함수의 단위 확인이다. 스킬/모델 시행이나 새로운 행동 성능 증거가 아니다. 재확인한 같은 조건은 합쳐 시행 수를 늘리지 않는다.

## 게시·보존·권한 경계의 최종 정적 확인

1. **게시 순서:** freeze와 별도 독립 출고 판정의 script/freeze SHA 및 한정 종료 지지를 확인한 뒤 in_progress를 쓴다. 보존·현재 안내·요약/문맥·기존 R6/R7 및 새 R8 조회·링크 검사를 거쳐 receipt를 쓰고 재대조한 다음 complete marker를 마지막에 쓴다. marker→receipt와 receipt→report/summary/보존목록/후보문맥 및 owned_content_hashes가 연결된다.
2. **원본 보존:** 세 봉인보고/기존 영수증/원래 고정 pin은 수정하지 않는다. source 초기 보존과 실제 freeze 현재 D 입력을 함께 대조하므로 정상 보완 이력과 무단 후발 변경을 구분한다. 후보의 옛 판본은 기존 snapshot의 SHA를 확인하고 별도 보존연결을 만들며 보고 본문을 소급 수정하지 않는다.
3. **목록 제외:** os.walk의 dirs를 prune하여 `__pycache__`, `고정문맥_검증전용`, `isolated`, `robustness`, `targeted_v3` 하위는 순회/해시하지 않는다. C 합성 3개 원본 루트와 제외 sentinel에서 예상8파일만 수집했으며 제외 sentinel이 해시 함수에 도달하지 않았다. 실제 수행 자료를 열어 이 시험을 한 것이 아니다. C 원본 삭제/이동은 없다.
4. **실패/재실행:** 실패 때 자기 마지막 OWN SHA와 같은 상태/보고만 무효화하며 외부 변경/부분 파일을 임의 복구하지 않는다. journal과 실제 partial SHA를 남긴다. 동일 freeze 자동 재실행은 marker/현재값이 D_before와 달라 거부됨을 확인했다. 자동 resume 기능으로 안내하지 않으며 실패/부분 상태 보존 후 재검토·새 게시 판정 절차가 필요하다. 초안에도 이 한계가 명시됐다.
5. **시행 숫자:** 코드의 3+5+11+2+3=24와 사실검사22+인계2의 구분, 실패1건을 지우지 않는 42/43 표기, 마지막3의 재사용 표적 회귀 구분, 준비만 한2건·실영상0·token/time null을 정적으로 확인했다. 실제 ledger24건의 내용·24고유실행/점수·판본 대응은 이 감사에서 열지 않았으며 후속 독립 출고 검토와 freeze의 실제 원문 대조 대상이다. 부모가 채점 완료를 알린 사실과 이 감사자의 직접 점수 검증을 혼동하지 않는다.
6. **권한:** R8_4_technical_complete만 한정 true이고 R8_complete/Phase00_complete/phase01a_started/candidate_adopted/company_approved는 false다. 기본 스킬을 후보로 덮거나 전역 설치하는 코드가 없다. 기존 시범 권한과 후보 A~D 선택지는 유지되며 추천안 제시가 자동 전환은 아니다.

## 한계와 게시 전 조건

확정된 source freeze와 독립 출고 판정이 실제로 생성되기 전에는 main을 실행하지 않는다. 실행 시 위 검토 SHA의 코드·초안과 출고 판정의 SHA가 맞아야 한다. 최종 freeze 이후 이 검토 산출물도 변경하지 않는다.

이 도구는 완전한 파일 묶음 원자성·OS 배타 잠금·디스크 고장 증명을 제공하지 않는다. 마지막 검사 직후의 파일 경합이나 실패기록 자체의 OS 오류까지 모두 해결했다고 해석하지 않는다. exact의 기존파일 확인과 복사는 전체 파일시스템 트랜잭션이 아니다. 실패 시 marker/receipt와 부분 상태를 우선 확인한다. 지정 Python 일반 실행에서 검사하며 안전 가드인 assert를 제거하는 최적화 실행은 이 검토의 전제가 아니다.

정적/합성 검토를 실제 D 게시 성공으로 쓰지 않는다. 실제 게시 뒤에는 marker→receipt→보고/목록/후보문맥·원 R6/R7 고정 입력·실파일의 한정 후검사가 필요하다. 이번 보고는 그 후검사나 포괄 Phase00 승인·후보 기본 전환을 대신하지 않는다.

현재 범위에서 추가 일반 강화는 후속 한계로 남기며, 게시 도구 검토 산출물을 위 SHA 기준으로 고정한다. **D 변경·main/prepare 실행·freeze 생성·PC 종료는 하지 않았다.**
