## 2차 수정에서 정리할 사항

**S-01 / P3 / 진행 상태 표현 정합화.** `01_진행현황.md:14`, `14_스킬재구성/R8_현재사용안내.md:3`은 “2차보완 진행 중”이라고 하지만 `14_스킬재구성/진행상태.json:65–67`은 1차보완 재검수 대기/2차보완 `not_started`다. 전체 보완 과정을 넓게 부르는 뜻으로 읽을 수 있으나 단계명으로 읽으면 모순이다. 현재 시점에는 “1차 보완 후 독립 재검수 중, 2차 보완 예정”처럼 실제 상태를 일치시키고, 2차 적용 후에는 그때의 사실로 갱신한다. `R8_4_substages:60–63`도 진행자가 아는 실제 착수 상태와 최종 게시 시 대조한다. 이 감사는 시험을 열람하지 않았으므로 어느 substage가 완료됐다고 추정하지 않는다. 완료/미완료 전체 판단을 뒤집는 결함은 아니다.

**S-02 / P3 / 현재 회신으로 가는 직접 링크.** `14_스킬재구성/R8_현재사용안내.md:5`와 `01_진행현황.md:20`은 3개 sidecar의 동일 basename만 설명한다. 새 안내에서 사용자가 바로 각 현재 회신에 도달하는 Markdown 링크 3개를 추가하면 충분하다. 기존 봉인보고를 고쳐 역링크를 넣지 않는다. 기존 링크 오류는 아니며 검색 부담을 줄이는 동선 보완이다. 회귀는 새 3링크의 존재/대상과 기존 receipt→report 연결 불변을 확인한다.

**S-03 / P3 / 정정표의 변경된 근거 처리 명시(예방 보강).** 현재 원문/basis 11개 해시는 모두 맞는다. 다만 정정표의 `if_source_hash_changes`와 현재 안내:9는 원문 SHA 변화만 명시한다. 현재 안내의 “원문·결정 근거 함께 확인”을 좁게 해석하지 않도록, source 또는 basis 중 하나가 없어지거나 해시가 달라지면 해당 정정만 보류하고 자동 재고정하지 않는다고 정정표/현재 안내에 명시하면 좋다. 현재 내용이 잘못됐다는 판정이 아니며 이를 위해 기존 고정 파일이나 수행 중인 후보를 무조건 다시 수정할 필요도 없다. 최종 현재 문맥 검사에서 양쪽 기대값을 각각 대조하면 된다.

선택적 추적성 보강: 제한 소스 기록에 해당 보관 LICENSE의 정확 경로/SHA 또는 기존 source_id를 덧붙이면 미래 권한 담당자가 대상을 더 쉽게 특정한다. 현재는 기존 보고로 연결되고 해당 pptx 국소 상태가 명확하므로 보완 부재를 P1/P2 결함으로 올리지 않는다. 현재 안내의 일반 Python/출력 경계 규칙은 유지한다.

## 반론과 해소 조건

- “원문을 안 고친 정정표는 또 다른 진실을 만드는 것 아닌가”: 원문과 현재 근거를 고정하고 적용 범위를 역사적 단계/저장위치 해석으로 한정했으며 실제 예시가 그 해석을 지지한다. 따라서 현재 방식은 타당하다. 추후 의미/권한 변경을 정정표로 우회하면 이 결론을 재검토해야 한다.
- “봉인 복원은 과거 후속 회신을 지우는 것 아닌가”: append본은 원래 SHA로 보존됐고 sidecar에 원문 후속 기록이 있다. receipt를 현값으로 바꾸지 않고 원래 기대 보고로 복원했으므로 증거 연결을 수리한 것이다. 최종 보고에도 이 복원 이력을 남겨야 한다.
- “권리 미정 하나 때문에 전부 중단해야 하는가”: 해당 소스를 재복제/실행/이식/재배포하는 범위는 보류한다. 별도 자체 계약과 사용 가능한 선별 자료의 정적/합성 검증까지 중단할 근거로 확대하지 않는다. 보관 처리나 활용을 확정할 때만 해당 소스·행위·조건을 권한 담당자에게 확인한다.
- “새 지침을 썼으니 안전성은 종료 가능한가”: 불가하다. 정확 후보 SHA에서 허용 쓰기·외부 변경·저장/부분실패·복구/미복구 보고를 실제 확인한 결과가 필요하다. 역할별 허용 쓰기 권한이 남아 있으면 그 범위도 판정에 반영한다.
- “기존 정책을 그대로 두면 회사 승인 없이 기술 종료 가능한가”: 한정 기술 결과를 정리할 수 있다. 이를 후보 기본채택/사람 출력 확정/실영상 효과/회사 사용승인으로 읽히지 않게 표시해야 한다. R8-4 결과에 관한 사람 피드백은 해당 결과·판본·확인 범위로 남기며 이미 확인한 CI 최신성/산하 AI 부재를 다시 묻지 않는다.

## 최종 추가 감사의 잔여

진행 중 시험을 현재 통과로 처리하지 않는다. 시험 종료 후 정확 후보 버전/SHA, 실패/무효 시행 보존, 개발/미사용 구분, 각 분기의 실제 수행과 관측 근거, 정상 유지/부분 보류/허위 인용/외부 자료 명령 분리, 한국어·수치·무음/미관 취향의 정보목적 종속, 순차 인계의 의미/판본/권한 보존을 확인해야 한다. 전수 원문 이해·단일 품질총점·소량 실행의 일반 우위·실영상 효과로 확장하지 않는다.

새 최종 R8 문맥을 고정한 뒤 원래 R7 130 pin·기존 스킬·평가계획이 그대로인지, 새 정정표/현재 안내/권리미정/sidecar가 어느 문맥에 포함되는지, 새 manifest를 과거 manifest의 대체로 오해하지 않는지 재감사한다. 최종 고정 전이라는 현재 사정을 실패로 세지 않았다. S-01/02 정리와 S-03 처리 여부, 3 봉인보고의 receipt 연결, 최종 사람 판단 잔여의 대상/범위를 함께 확인한다.

지금은 이 독립 정적 재검수와 C 산출물 저장을 마쳤다. 2차 수정 적용·행동시험 판정·새 문맥 최종 감사는 후속 작업이다.
