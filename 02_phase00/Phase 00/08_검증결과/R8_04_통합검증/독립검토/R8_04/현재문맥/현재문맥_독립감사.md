# R8-4 현재 문맥 독립 감사

2026-10-15. 읽기 전용 코드·데이터 감사다. D의 파일·후보·고정 목록을 수정하지 않았다. 결과는 이 폴더에만 작성했다. 모델 수행 비교·실제 영상 효과·사람 내용 검수·기본 전환을 완료했다고 주장하지 않는다.

## R7 보존과 R8 별도 문맥

R7 `현재연결_입력고정.json`은 ID `r7-foundation-link-context`, version `0.1.3`, scope `fixed_foundation_references_only`다. EXPECTED_PATHS를 코드에 고정하며 기존 세 스킬의 SKILL·참조·evals, 기존 평가계획을 포함한다. 후보 11개 파일은 이 130 pin에 포함되지 않는다. 현행 R7 통과는 후보의 현재성/동작 확인이 아니다.

따라서 R7 목록을 후보 해시로 덮어쓰거나 기존 세 스킬 경로에 후보를 복사해 오류를 없애면 안 된다. R7 원문·검사기·고정 목록은 그대로 두고, R8에는 세 후보 모두를 포함한 **별도 후보 문맥**을 만든다. 권장 최소 필드는 별도 ID/판본/scope, R6와 R7 manifest 경로·SHA, 검사기 경로·SHA, 세 후보의 SKILL/모든 참조/보조도구 경로·SHA·판본, 명시적 `candidate_only`, `company_approved=false`, `operational_release=false`다. 이 감사에서는 새 문맥이나 검증기를 구현하지 않았다.

## full R6/R7 사본의 정확한 필요 집합

`full_R6_R7_copy_set.json`은 **변경 없는 현행 API를 실행할 고정조회 사본**의 정확한 선택 파일 800개, 상대경로·SHA·bytes를 담는다. 총 78,901,855 bytes다. R6 manifest 50 pin, R7 manifest 130 pin, 두 manifest 자체, R6 원문대장 544행이 선택한 파일과 등록 자산 135개를 합쳐 중복 제거했다. 현재 모두 D 안에서 존재하고 기대 SHA와 일치한다. `.환경` 전체 복제는 포함하지 않으며 지정 Python 환경을 그대로 사용할 수 있다. JSON schema 런타임 패키지 판본은 JSON에 기록했다. 새 설치·네트워크가 필요하지 않았다.

폴더 전체를 무차별 복제할 필요가 없다. 위 800개를 상대 위치 그대로 검증 전용 루트에 복제한 뒤 SHA, R6 네트워크 없는 현행 읽기 API, R7 현행 읽기 API를 실행하면 된다. 이는 준비 방안이며 이번 감사에서는 실제 사본 생성/사본 API 실행은 하지 않았다. R4/R5 실제 draft 기록 검사는 이 조회 통과와 별도로 기존 도구에 실제 대상 파일을 넘겨야 한다. 해당 도구 import는 `required_files.json`에 보존했다.

R6는 원문이 있으면 그것을 우선 검사하고 없을 때만 보존 snapshot을 쓴다. 현재 원래 호스트 절대경로 4개(구 presentations 버전)가 부재여서 D의 `backup/2026-10-15_R6_01_출처복구/호스트참조원문/` 4개가 선택된다. 각 원래 경로·선택 경로·SHA를 JSON의 artifact_selection에 담았다. 다른 호스트에서 같은 절대경로가 다시 존재하면 선택이 달라질 수 있으므로, 단순 복사만으로 다른 환경에서도 같은 선택을 보장한다고 말하면 안 된다. 현재 환경에서는 blocker가 아니다.

## 평가문단 노출 없는 수행 경계

원본 full R7 검사를 통과시키면서 같은 파일에서 평가문단을 삭제하는 것은 양립하지 않는다. 삭제하면 올바르게 hash 불일치가 나고, 재고정은 과거 문맥 보존을 해친다. full 고정조회 사본과 역할별 수행자료를 두 루트로 나누는 것이 필요하다.

1. 검증 담당자만 원문 그대로의 800파일 고정조회 사본에서 full API를 실행한다. 수행자는 full 원본 트리나 평가계획을 읽지 않고, API 이름·문맥 SHA·결과·범위 제한을 담은 조회 영수증을 받는다.
2. 역할별 수행사본은 필요한 지식/기록/회신·원문 근거와 해당 역할 스킬 한 버전만 포함한다. old/new는 동일 상대 경로·동일 자료·권한으로 맞추고 상대 스킬·예상 답안·채점표·레드팀 결론을 빼며 미사용 요청/판정 경계를 실행 전에 고정한다.
3. 변환은 수행사본에만 적용한다. 원본 path/SHA와 JSON pointer 또는 문단, 변환 이유, 대체·제거 내역, 수행본 SHA를 별도 전처리 manifest로 남긴다. 수행자료의 pin은 별도 ID로 만들며 기존 R6/R7 full valid인 것처럼 표시하지 않는다. 변경된 draft는 역할별 기존 구조검사와 새 R8 pin/권한 검사로 확인한다.
4. 간접 복제도 검사한다. 현재 `05_출처와검토/스킬심층검토/스킬심층검토정본.json`의 `/cards/6/application_example`, `/cards/6/unresolved/0`에 R8 평가설계 문구가 있고 `05_출처와검토/검수와사용범위/출처와사용범위_연결목록.json`의 `/links/645/original_record/…`에도 복제돼 있다. 이것만 지워도 원문 전체가 모두 평가와 무관해지는 것은 아니다. `06_맞춤스킬/평가계획.json`, 세 구형 evals, `13_품질검수/평가계획/`, 이전 결과/실행로그도 수행자료에서 제외하거나 필요한 운영 사실만 출처와 함께 추출해야 한다.
5. 동일 계정 파일 접근을 실제로 막지 않으면 지시상 격리다. 도구/실행 로그의 실제 열람 범위를 남기고, OS 격리나 무노출 맹검을 주장하지 않는다. 스킬 연결 시에도 전달 묶음에는 대상 ID/판본/SHA, 읽은 근거와 깊이, 수정 허용 범위, 미결 질문/역할/판본, 검사 영수증을 넣되 평가 기대답은 전달하지 않는다.

## 기존 뷰어 원래 과제/출력 대응

R8-1 최종 6회, R8-2 최종 6회와 초기 4회, 합계 16회 데이터를 디코딩해 확인했다. 16회 모두 뷰어 `run.prompt`가 해당 원래 `task.txt` 및 `eval_metadata.json.prompt`와 정확히 같았다. 218개 표시 출력은 실제 로컬 시행 출력과 텍스트 내용 또는 바이너리 바이트가 일치하며 파일명 집합도 같았다. R8-2 최종의 previous_outputs 4회/63파일도 실제 초기 출력과 일치했다. task/metadata/출력 총 250파일은 D 보존 backup의 같은 파일과 바이트가 같았다. 상세는 `viewer_task_output_audit.json`이다.

105개 텍스트 출력은 HTML 데이터로 읽을 때 CRLF가 LF로 정규화되어 raw bytes와 달랐다. 이것은 원문 파일 변조가 아니다. 디코딩 문자열과 줄바꿈 정규화의 일치 여부 및 원문 SHA를 각 행에 별도 기록했다. 바이너리는 base64를 디코딩하여 바이트로 비교했다. 뷰어 JS는 `prompt-text.textContent = run.prompt`로 연결한다. 정적 데이터에서 과제가 서로 바뀌거나 잘린 결함은 발견하지 못했다. 브라우저 렌더/클릭 검수는 하지 않았다.

따라서 현재 과제 표시를 수정할 근거는 없다. 나중에 실제 표시 결함이 재현되면 기존 HTML·공식 생성원본·원래 task/metadata·출력을 SHA로 보존하고 **별도 표시용 HTML 사본**에서만 prompt 또는 UI를 보완한다. 출력/점수/과제 원문은 수정하지 않고 디코딩 전후 출력이 동일한지 재대조한다. 이 감사는 뷰어 보완을 수행하지 않았다.

## 차단 사유와 남은 실제 작업

현재 D 원본 조회에는 blocker가 없었다. 후보를 포함한 R8 별도 문맥은 아직 구현/검사하지 않았고, full 사본의 실제 생성·조회/전처리 동등성 확인도 이번 읽기 전용 감사 범위 밖이다. 이것을 기존 도구의 실패로 기록하지 않는다. 새 미사용 사례·실제 저장 실패/부분 실패/외부 동시 변경·역할 간 전달은 별도 실행 결과가 필요하다. 평가계획과 기존 개발시험을 읽은 것만으로 새 수행 성능, 실제 영상 효과 또는 사람 승인을 주장하지 않는다.
