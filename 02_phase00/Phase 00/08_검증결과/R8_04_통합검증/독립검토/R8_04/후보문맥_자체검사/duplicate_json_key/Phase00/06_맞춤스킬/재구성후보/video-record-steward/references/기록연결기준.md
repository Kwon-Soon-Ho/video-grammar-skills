# 기록과 연결 — 필요한 규격만 조회

루트는 호출에서 명시한 경로를 우선한다. 현재 도구가 실제 어느 BASE를 사용하는지 확인하고 그 루트의 코드·규격만 이용한다. 코드/도구가 없거나 수행 사본에서 자료가 생략됐다면 미검사 범위로 밝힌다. 다른 운영 루트로 자동 대체하거나 누락을 가짜 값으로 채우지 않는다.

하위 검사기는 통합 v0.2의 로컬 의존 규격을 사용한다. 원격 스키마/패키지를 내려받아 검사하지 않는다. 기존 프로젝트 Python을 사용하되 자료/도구는 실제 호출 DB와 일치시킨다. `자료검증.py --output`은 해당 DB의 `08_검증결과` 안만 허용한다. 다른 출력 위치가 필요하면 stdout/API 결과를 허용 출력으로 따로 보존하며 도구 제한을 고치지 않는다.

구형은 읽기 검사만으로 접수·이관하지 않는다. 명시 접수 요청일 때만 `기록접수.py`의 copy-only 흐름과 현재 입력 경계를 확인한다. 원문 identity/시간/상태·과거 승인이 부족하면 원문과 누락 목록을 보존한다. 원본 hash를 모르는데 JSON hash/0해시를 대신 넣지 않는다.

현재성 검사 실패는 해당 문맥/연결을 통과로 쓰지 못한다는 뜻이다. 수행 사본의 명시 누락이나 무관한 미정 때문에 독립적으로 검증 가능한 요청 초안까지 전부 중단하지 않는다. 필요한 계약 자체가 불명확하거나 영향을 분리할 수 없으면 관련 반영을 보류하고 구체 대상·자료를 요청한다. 현재 pin을 재작성해 실패를 숨기지 않는다.

R5 관측색은 명시 선택한 프로젝트 초안의 역할 후보다. 한맥 공통 라이브러리와 회사색을 구분하고 미상 프로필/가독성·최종 배경·CI 세부조건은 그대로 남긴다. 8회사 CI 최신성·산하 AI 원본 부재에 대한 실제 R6 회신은 그 확인 범위만 유효하다. 새 회사/시안/내용 승인 또는 원래 없는 파일 생성 지시가 아니다.


## 전후 판본의 보조 대조

후보에 포함한 `scripts/판본대조.py`는 Python 표준 라이브러리만 쓰는 읽기 전용 도구다. content_edit 모드는 이전 bytes와 새 bytes가 달라질 때 동일 ID의 자체 version도 다른지 확인한다. 연결 메타데이터/직렬화 변경의 SHA 충돌도 놓치지 않으며 ID/schema_version 오변경을 진단한다. 자동 수정·새 판본 부여·허용필드 승인·R4/R5 전체 구조/참조·내용 검수는 하지 않는다. 호출에서 허용한 입력 경로만 전달한다.

CLI 결과0은 이 좁은 대조 통과,1은 오류다. exact_restore 모드는 명시 checkpoint SHA와 복원 bytes가 같은지만 확인하므로 정확 복구에 새 version을 강제하지 않는다. 복구 전 snapshot·현재 파일/외부 변경·실제 권한 확인은 수정/복구 절차에서 따로 수행한다.
