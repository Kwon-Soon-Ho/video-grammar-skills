# R4-4 통합·이관 결과와 레드팀

2026-10-15. **시간·근거·좌표를 연결한 v0.2 기록 계약, 구형 원문 접수/누락 보고, 기본 검사 도구 전환 범위를 완료했다.** R4의 Phase 00 기록 기반 검수는 마쳤다. 전체 Phase 00은 R5~R8 잔여가 있으며 01-A는 시작하지 않았다.

## 무엇이 달라졌는가

예전에는 ‘구간에 태그·프레임·모션을 적는 JSON’이었다. 지금은 **영상 전체 → 설명 구간 → 화면 상태**, 그리고 상태를 가로지를 수 있는 **짧은 동작**의 대상을 나누고 시간·근거·좌표와 연결한다. 프레임은 화면 상태를 확인하는 표본이며 상태 자체가 아니다.

| 연결한 것 | 적용 예 | 막는 반례 |
|---|---|---|
| 시간 | 재생 0초와 원본 PTS·구간/프레임을 같은 정본으로 연결 | 다른 시각·구간 제외 끝점·원점 모순을 근거로 사용 |
| 근거 | 원본/파생 자료 pin → 대상/선택 부분 → 지지·반대·문맥 주장 | 파일/대상 ID만 있어 관측·의도 확인으로 처리 |
| 좌표 | 표본 → geometry → x/y/폭/높이 → 단위/필요시 변환 결과 | px/normalized 혼용·없는 공간·서로 다른 성분·오차 누락 |
| 분류 | 단위별 허용축과 classified/unknown/not_applicable/other_candidate/not_assessed | 구간 태그를 화면 상태로 상속·미상을 정답으로 채움 |
| 실행·검수 | 구조화 run/metadata·한맥/용어 pin·통합 context | 임의 run 객체를 실행 증명으로 사용·옛 receipt를 변경 후 재사용 |

데이터는 spatial_contract 안의 근거 계약, 그 안의 시간 계약에 한 번만 저장한다. units와 좌표 표본은 ID/버전을 참조한다. 별도 시간/근거 사본으로 모순을 만들지 않는다. 좌표 미기록 영상은 빈 공간 목록으로 보존할 수 있지만 원본 identity 미상을 가짜 값으로 채우지는 않는다.

## 실제 구형 자료는 어떻게 처리했는가

현재 찾은 5개는 모두 설명용·스킬 시험·과거 평가 자료다. **5개 원문을 수정하지 않고 접수함에 사본·누락 보고로 보존했다.** 원본 영상 버전/hash·시간·화면 상태가 없어 실제 회사 영상 기록으로 바꾸지 않았다. JSON 원문 hash와 영상 hash를 구분했다. 동일ID라도 출처가 다른 파일을 별도로 보존하고 같은 원문의 재실행은 불변이다.

v0.2 합성 설명 예시는 별도 규격 예다. 구형 예시에 가짜 hash/PTS를 채운 이관본이 아니다. 현재 자동 도구는 copy-only 접수·누락 진단·검사이며, 구형 의미 전체를 추정해 자동 변환하는 도구는 만들지 않았다. 원본과 의미 대응이 확인된 이후에만 새 통합 초안을 작성한다. 실제 회사 영상 분석 기록은 **0건**이다.

## 사람 검수·남은 일

구조 통과·좌표 연결·context 일치는 화면/대상 해석·시간/픽셀 실측·실행 사실·실제 사람 검수·회사 승인과 다르다. 필요한 내용은 대기 목록으로 남긴다. 실제 자료가 없어 이번에 실제 영상의 내용 검수나 검수자 인증은 하지 않았다. 공간 측정의 supported 보류도 유지하며 R6/R7의 권한·내용 검수로 인계한다. 속도/가속도 자동 분석·오차 전파·ROI/OCR/추적·영상 가공은 01-A다.

세 스킬의 본문·참조·평가 입력은 원래 hash를 유지했다. 새 규격의 쓰기/기권 호환·로그/backup 재평가는 [R8 인계](../09_다음단계인계/R4_통합규격_스킬호환_인계.md)에 남겼다. 과거 비교 점수를 새 호환 검증으로 쓰지 않는다.

다음은 R5의 한맥/가족사 CI·디자인 적용 연결이다. R6 출처·권한·검수 결정, R7 품질/조회 검수 기준, R8 맞춤 스킬 재구성과 평가까지 보완한 뒤 전체 Phase 00을 판정한다.
