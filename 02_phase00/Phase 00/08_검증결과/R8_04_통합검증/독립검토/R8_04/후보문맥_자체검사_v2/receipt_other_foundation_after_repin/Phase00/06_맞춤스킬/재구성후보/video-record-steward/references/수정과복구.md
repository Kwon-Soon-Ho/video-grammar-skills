# 초안 수정·백업·실패·복구

## 수정 전

- 읽기 검사와 쓰기/접수/복구 요청을 구분한다. 쓰기 대상·실제 루트·허용 필드/부수 판본·출력·backup 위치를 정한다. 고정 원문/정본·기존 receipt/pin은 수정 대상으로 추정하지 않는다.
- 대상의 원문 bytes·SHA·ID/버전과 관련 참조를 보존하고, JSON은 중복 키·비유한수·정수/분수 타입을 구분해 파싱한다. 잘못된 입력을 자동 형변환·중복 병합·재해석하지 않는다.
- backup은 대상 변경 전에 원문 바이트 그대로 별도 생성하고 SHA를 대조한다. 이미 같은 사본이면 동일성을 확인해 사용하고 다른 내용이면 보존한다. 충돌/쓰기 오류가 나면 대상은 그대로 두고 제안·실패 로그만 허용 출력에 남긴다. 지정 backup 경로를 임의 삭제/이름 변경/다른 위치로 대체하지 않는다.

## 수정·검사·게시

1. 후보 bytes와 요청 범위의 JSON 차이를 먼저 확인한다. `00_운영계약/01_보존과버전_계약.md`에 따라 같은 ID의 새 내용·메타데이터는 새 자체 판본으로 구분한다. R4의 새 SHA/판본을 R5 참조에 연결하는 변경도 R5 내용 변경이다. 바뀐 각 파일을 별도로 대조하며 schema_version·원본 asset version·참조 대상의 version을 소유 기록 version과 혼동하지 않는다. 판본 고정의 명시 요구와 충돌하면 반영을 보류한다.
2. 가능한 구조/참조 검사를 후보에 먼저 실행한다. 여러 파일 연결은 예상 판본/실제 저장 bytes hash와 순서를 계획한다. 요청된 연결 수정 밖의 참조·검수 context를 자동 갱신하지 않는다. 새 내용 때문에 옛 검수가 stale라면 그 사실을 남기며 승인 영수증을 새로 만들지 않는다.
3. 첫 쓰기 전 모든 대상이 snapshot과 같은지 다시 확인한다. 같은 폴더 임시 파일·허용된 교체 방식 등으로 부분 JSON 저장을 줄인다. 이는 여러 파일의 원자 transaction·보안 서명을 보장하지 않는다.
4. 각 저장 뒤 실제 bytes·diff·연결·관련 검사를 확인한다. 읽기 전용 `scripts/판본대조.py --before <변경전backup> --after <후보/저장파일>`로 각 변경 기록의 ID/규격 판본·자체 판본을 확인한다. 일반 기록 검사만으로는 이전 version 누락이 잡히지 않을 수 있다. R4를 저장한 후 명시된 R5 링크를 같은 ID/새 판본/정확 SHA로 갱신하는 경우 최종 두 기록을 별도로 검사한다. 여러 파일 중 일부만 저장됐다면 그 상태를 기록하고 성공으로 발표하지 않는다.
5. 저장 후 검사 실패나 부분 저장 오류가 나면 작업 전부터 있던 오류와 새 변경 오류를 구분한다. 이미 바꾼 대상의 현재 바이트가 내가 기록한 바이트와 같을 때는 영향받은 대상을 작업 전 backup으로 되돌리고 복구 SHA와 관련 검사를 확인한다. 실패 후보·원인·로그는 별도 허용 경로에 보존한다. 외부 변경 또는 복구 실패가 있으면 덮어쓰지 말고 해당 경로를 미복구/사용 중단 상태로 명시한다. 새로 만든 결과 파일도 허용 범위에서 격리하거나 미반영/사용 중단으로 표시하고 목록에 남긴다. 삭제는 명시 허용 범위에 한정하며 실패 흔적을 지우지 않는다. 미복구 활성 초안을 그대로 둔 채 수정 완료로 보고하지 않는다.

## 복구

명시 복구 요청 또는 내 실패한 변경을 원상복구하는 범위만 다룬다. checkpoint의 대상/버전/정확 SHA와 현재 실패본 SHA·작업 로그가 맞는지 확인한다. 복구 전 실패본도 따로 보존한다. 출처 불명 사본·SHA 충돌·외부 변경이 있으면 추측 복구하지 않는다.

복구 직전 현재 파일이 확인한 실패본/내 쓰기 bytes와 같은지 확인하고, 해당 작업 전 snapshot bytes를 복원한다. 정확 복원 요청이면 JSON 재직렬화·버전 상승·다른 개선을 섞지 않는다. 복원 후 byte SHA 동일성·관련 구조/참조와 작업 범위를 확인하고 실제 결과를 별도 로그로 남긴다. 같은 helper의 `--mode exact_restore --checkpoint <정상사본> --checkpoint-sha <명시SHA>`는 복원 bytes만 대조하며 복구 전 파일이 손상 JSON이어도 읽을 수 있다. 실제 기록 구조 검사는 별도로 수행한다. 백업/원본/실패 기록을 삭제하지 않는다. 여러 파일은 복구 순서·각 최종 상태와 미해결을 명시한다.

타인 수정이 끼어들면 내 snapshot을 무조건 덮어쓰지 않는다. 영향과 필요한 사람 판단을 남긴다. 복구 불가·임시/부분 파일·검사 오류를 성공으로 바꾸지 않으며 동시성 안전이나 손실 없는 복구를 시험하지 않은 범위까지 보장하지 않는다.
