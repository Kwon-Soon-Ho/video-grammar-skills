# 큐레이터가 읽을 기반

## 루트와 버전

요청의 명시 DB 루트를 우선한다. 아래 경로는 그 루트 기준이다. 후보 스킬·시험 사본은 폴더 깊이가 달라질 수 있으므로 스킬 경로의 두 폴더 위를 무조건 루트로 쓰지 않는다. 원본/파생·정본/표시·backup은 `00_운영계약/01_보존과버전_계약.md`를 따른다. 상태/버전·형식 통과는 회사/내용 승인과 다르다.

| 작업 | 먼저 읽을 자료 | 판단에 필요한 경우 추가 |
|---|---|---|
| 용어·별칭/의미 | `01_공통용어/공통용어사전.json`·`분류운영규칙.json` | `용어판정기준.json`, 관련 혼동쌍/현재 이관 규칙 |
| 원칙/예·반례 | `02_원칙과레이아웃/모션과정보전달원칙.json`, `화면설계원칙.json`의 관련 항목 | `03_모션원칙_적용예와반례.md`, 관련 조사 원문/읽기 깊이 |
| 레이아웃 | `02_원칙과레이아웃/레이아웃지식.json`·`레이아웃_심화지식.json` | `07_레이아웃별_선택조건과반례.md`, 화면비/한국어 사례·표/순환/분기 후보 |
| 외부 지침 이식 | `05_출처와검토/스킬심층검토/05_세스킬_이식설계안.md` | `04_라이선스와출처_검토결과.md`·`08_기능별_연결표.md`. 보류 원문/코드를 복사하지 않음 |
| 회사 디자인 언급 | `03_한맥디자인/한맥디자인정본.json`·`09_다음단계인계/R5_디자인연결_인계.md` | R5 적용 초안/실제 CI 출처·R6 현재 확인 범위. 공식 미정 수치를 채우지 않음 |
| 검수 근거/보류 연결 | `13_품질검수/03_판정운영기준.md`·관련 `품질항목_정본.json` 카드 | `연결과인계/03_검수와보류_연결규칙.md`, 실제 필요한 R6 질문/답변 문맥 |

지식 종류에 없는 필드를 억지로 만들지 않는다. 원본의 `source_refs`, `status`, `case_refs`/`company_examples` 규칙을 유지한다. 설명 예시는 실제 회사 사례로 등록하지 않는다. 추가 조사는 부족한 개념/출처에 한정하고 읽은 부분만 기록한다. 제목/요약/전체 본문의 확인 깊이를 구분한다.

## 도구가 확인하는 범위

- `07_실행도구/지식조회.py`는 같은 루트의 관련 용어·원칙/레이아웃을 찾는 기존 읽기 도구다. 사용법/루트 결정을 코드에서 먼저 확인한다. 검색 누락을 개념 부재의 증거로 삼지 않는다.
- `자료검증.py`의 현재 기본은 R4 v0.2 통합 영상 기록 검사다. 별도 `validate_catalogs()`는 지원하는 지식 목록 검사이며 모든 지식 해석·새 draft의 진실성/권한까지 확인하지 않는다. 실제 실행 없이 검사했다고 쓰지 않는다.
- `R7_연결확인.py --base <DB루트>`는 고정 기반의 현재성과 연결표/빈 양식 구조를 본다. 고정 파일이 바뀌면 자동 재고정하지 않는다. 미래/별도 지식 초안이나 실제 영상 검수 결과를 검사한 것이 아니다.
- `R6_통합조회.py`는 고정 출처·회신 선언 문맥을 별도로 확인한다. 다른 질문에 과거 답변을 자동 옮기거나 실제 사람 신원·회사 승인으로 바꾸지 않는다.

프로젝트의 `.환경/Scripts/python.exe`가 실제 있으면 사용한다. 시험 사본에 환경이 없다면 시험에서 지정한 Python을 쓴다. 설치/복사된 모든 스킬 코드를 실행하지 않는다. 도구가 없거나 실패하면 지원 범위/오류를 기록하고 결과를 추정하지 않는다.

단독 지식 초안 수정은 파싱/필수 구조·ID/출처 참조·판본/허용diff를 직접 확인해 그 좁은 범위를 보고할 수 있다. 이런 검사를 R4 전체 스키마나 실제 내용 검수로 이름 바꾸지 않는다. 정본/표시 연결목록에 명시된 생성물만 해당 생성기로 갱신하고 수동 안내를 자동 생성물로 표시하지 않는다. draft가 미등록이면 미등록 상태와 최종 등록/기본 전환 잔여를 명시한다.
