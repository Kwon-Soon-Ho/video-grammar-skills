# 결과 보고

먼저 실제로 무엇을 수정/복구했거나 왜 대상은 그대로 두었는지 적는다. 검토 가능한 결과 초안·검사 JSON과 짧은 한국어 설명을 저장한다. 요청한 안전한 정리를 수행하고 모든 항목을 막연히 보류하지 않는다.

- 대상/작업/루트·원문 ID/판본/SHA·허용 변경, 변경 전후 판본/SHA와 실제 파일 경로.
- byte 일치 backup·후보/실패본·diff/변경 필드·작업 로그와 실제 변경 파일 전체. 남은 임시/부분 산출물도 표시.
- 실제 실행한 도구·입력·종료/결과와 검사 범위. 제안 명령·자기기록·독립 관측을 구분. 미수집 시간/token은 null/미수집.
- 구조/참조 오류·unresolved·사람 대기·복구/미반영 상태를 따로 기록. valid나 빈 오류를 내용/회사 승인으로 승격하지 않음.
- 한맥·회사 CI·R4/R5 연결·R6 질문 문맥·R7 적용/필수 항목 중 이번에 확인한 것과 미실시. 자료 일부 읽기·선언 구조·full 현재 조회·실제 기록 검사·사람 내용 확인을 구분.
- 필요한 실제 사람 검수는 대상·판본·질문·근거·판단 범위를 묶어 제안/요청. 결정이 필요한 부분은 최소4선택지와 추천안을 제시하되 기존 승인된 목적·단순 수정 권한은 다시 묻지 않음.

합성 개발 사례는 spec_test/spec_example와 실제 관측·프로젝트를 구분한다. 수행하지 않은 영상 분석·회사 승인·R8/Phase00 완료를 만들지 않는다. 실제 판단을 접수한 경우에만 그 회신의 범위·문맥을 연결한다.
