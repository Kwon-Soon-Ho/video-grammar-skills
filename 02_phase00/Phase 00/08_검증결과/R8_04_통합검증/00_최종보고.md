# R8-4와 Phase 00 전체 재검수 — 최종 보고

2026-10-15 · **R1~R8 재검수, 1차 보완, 독립 재검수, 2차 문서·행동 보완을 거쳐 R8-4의 한정 기술검수를 종료했다.** 실제 영상 분석·납품 품질·회사 승인·새 후보의 기본 전환은 이번 완료 범위에 포함하지 않는다. 게시 완료 여부는 [게시상태](게시상태.json)의 `complete`와 연결된 최종 영수증을 확인한다.

## 이번에 한 일

1. Anthropic Skill Creator의 시험·독립 채점·공식 출력 뷰어 절차로 세 스킬의 새 요청, 실제 파일 쓰기, 저장 실패, 외부 수정, 복구, 순차 인계를 확인했다. 실패는 실제 파일 쓰기와 함께 시험 서비스에서 주입했다. 실제 디스크 고장이나 운영 DB 장애를 일으킨 것은 아니다.
2. R8-4만 보지 않고 R1~R8의 계약·현재 안내·출처·권한·품질/평가계획·고정 참조를 다시 검토했다. 복잡한 통합 판단은 별도 **GPT-6 Astra** 레드팀, 다른 관점은 독립 기술·사용성 검토자가 맡았다.
3. 전체 지적을 모아 1차 보완했다. 독립 재검수에서 발견한 추가 결함을 2차로 고치고 다시 확인했다. 원래 실패·오기·준비 오류·미시행 사례를 보존했다. 통과하도록 과거 기대조건이나 원문 해시를 바꾸지 않았다.

## 실제 시험 결과

| 시험 묶음 | 실제 시행 | 독립 조건 판정 |
|---|---:|---|
| 새 요청3 + 원래 쓰기·실패5 | 8 | 38/38, 보호 계약/오기 한계 별도 |
| 1차 보완 후 정상·실패 분기 | 11 | 42/43, 안내 부재 오보고1건 실패 보존 |
| 큐레이터 → 기록 관리자 → 검토자 실제 순차 인계 | 2 | 8/8, 독립 효과 비교 아님 |
| 2차 경로·상태 보완 표적 회귀 | 3 | 12/12, 이전 자료 재사용 회귀 |

모든 조건을 합쳐 하나의 품질점수나 성공률로 표시하지 않는다. 회귀·순차 인계는 서로 의존하고 시행마다 판본과 목적이 다르다. 원래 실패 1건은 그대로 남기고 수정 후 결과를 별도로 제시한다. 실제 영상 분석 시행은 **0회**, 개인 API/Claude CLI·자동 트리거·D의 실제 영상 기록 수정은 미실시다. 행동 시험의 쓰기는 C 사본에서 수행했고, D에는 이번 지침 보완·안내·상태·검사도구·검증 결과를 게시했다. 준비만 한 `2b` 두 사례는 실행 0회이며 후속 시험으로 대체됐다. 시간/token은 제공되지 않아 null이고 문자수로 추정하지 않았다.

최신 후보는 큐레이터 **0.2.0-draft.3**, 기록 관리자 **0.2.0-draft.5**, 적용성 검토자 **0.2.0-draft.4**다. 마지막 수정은 현재 안내 경로·근거 확인과 부재 보고의 명확화이며 참조·실행 코드를 바꾸지 않았다. 최신 세 판본 모두 표적 회귀를 했지만, 모든 실패 분기를 이 세 판본으로 다시 반복했다고 주장하지 않는다. 전체 분기 근거는 직전 판본 시행과 변경 차이를 함께 본다.

기존 8회 채점 외 별도 한계도 보존했다. 원래 큐레이터는 복구 직전 보호 계약이 불충분했으며 실제 원문 복구 관찰만으로 일반 안전을 입증하지 못했다. 원래 검토자 보고의 ‘나머지 26항목’은 총26−선정11인 **나머지15항목**으로 읽어야 한다. 보완후 검토자 1건의 `partial_write` 상태명도 실제 완전 저장 후 외부 변경 상황에 맞지 않았다. 해당 원출력은 수정하지 않고 주석으로 남겼고, 마지막 역할 시험에서 실제 상태 서술을 다시 확인했다.

검사기는 제한된 로컬 참조 검사다. 미사용 추가 메타데이터의 지수 오버플로 수치 허용은 낮은 우선순위 입력 엄격성 한계로 남겼다. 사용되는 권한/해시 필드와 구분하며, 적대적 입력에 대한 완전한 격리·동시성/원자성·전자서명 인증을 보장하지 않는다.

게시가 실패하면 같은 동결본으로 자동 재개하지 않는다. 실패/부분 상태를 보존한 뒤 원문과 외부 변경을 다시 검토하고 새 게시판정을 받아야 한다. 완료 마커 직전의 재대조가 OS 수준의 배타 잠금까지 대신하지 않는다.

## 종료 범위와 다음 판단

**이번 종료:** R8-4 한정 기술검수 및 요청한 전체 재검수/2차 보완. **그대로 남는 것:** 실제 자료의 내용·시각 품질, 권리 근거, 회사 필수화/승인, 잠금 평가, 후보 기본 전환. 사람의 답이 필요한 실제 대상은 미검수/보류 상태로 보존했다. 자료가 없는 효과나 공식값을 승인된 것으로 넘기지 않았다.

기존 소량 시범 운영 승인은 유지한다. 새 후보는 `06_맞춤스킬/재구성후보/<스킬명>`의 명시 경로에 있고 기존 기본 스킬을 덮거나 전역 설치하지 않았다. R8/Phase00의 포괄 최종 승인 플래그는 false로 남긴다. 후속 선택은 다음 네 가지이며 이번 작업에서 대신 결정하지 않았다.

- **A 권장:** 최신 후보를 명시한 소량 사본 시범 → 실제 출력 사람 확인 후 기본 전환 판단.
- B: 기존 시범 스킬만 유지하고 새 후보는 보관.
- C: 승인된 대상에 한해 스킬 한 개씩 순차 전환.
- D: 대표 실제 자료/정답 준비 후 추가 비교를 먼저 진행.

01-A 구현은 시작하지 않았다. 준비할 영상·시나리오·자료 폴더와 개인정보/권한·예비/잠금 구분은 [자료 준비 안내](../../09_다음단계인계/01-A_자료준비안내.md)를 따른다. 제한 소스 처리·개별 내용 검수·후보 전환은 대상과 근거를 정해 별도로 판단한다.
