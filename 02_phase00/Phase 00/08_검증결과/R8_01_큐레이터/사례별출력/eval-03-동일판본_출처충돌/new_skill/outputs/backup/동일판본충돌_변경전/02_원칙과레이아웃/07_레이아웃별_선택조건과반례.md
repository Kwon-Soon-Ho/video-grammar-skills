## 단일 초점 · LAYOUT-SINGLE-FOCUS

핵심 대상·문장 중심의 구성 — 기존 프로젝트 정의.

관련 정보 관계 후보: 입력 관계에 따라 달라짐 · 모양만으로 자동 부여하지 않음.

- 선택 조건: 핵심 메시지가 하나이며 나머지는 근거·맥락일 때
- 읽는 순서 후보: 요점→대표 대상→필요한 근거
- 구성할 때 판단: 대표 대상, 요점 문장, 보조 설명을 역할로 구분한다. 초점 위치는 중앙·삼분할 모두 후보다.
- 적용 예: 침투수의 주요 경로를 하나의 단면도와 짧은 요점으로 설명한다.
- 오용 반례: 동등하게 비교해야 할 A/B 중 A만 거대하게 배치해 우열을 암시한다.
- 허용되는 변형·복합: 한 문장 옆에 단면도·범례·출처가 함께 있어도 요점 역할이 하나면 후보가 된다.
- 다른 구조를 검토할 때: 핵심이 여러 개면 비교·분할·구간 분절을 먼저 검토한다.
- 한국어·문구 조정: 긴 제목을 영역에 맞춰 의미 단위로 줄바꿈하고 근거 문구와 역할을 나눈다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 대표 대상 위·아래에 요점을 재배치하되 단면과 라벨 대응을 유지한다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 한 요점을 판단할 입력이 없으면 보이는 배치만 남기고 전달 성공은 보류한다.

## 계층 구성 · LAYOUT-HIERARCHY

상하·종속 관계를 배치로 표현 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-HIERARCHY · 모양만으로 자동 부여하지 않음.

- 선택 조건: 상하·종속·구성의 위계가 자료로 확인됐을 때
- 읽는 순서 후보: 최상위 의미→부모/자식 연결→필요한 하위 항목
- 구성할 때 판단: 같은 수준과 상하 수준을 배치·선·명칭으로 구분한다. 단순 중요도 위계와 실제 조직 위계를 나눈다.
- 적용 예: 문서에 확인된 부서와 팀의 상하 관계를 연결한다.
- 오용 반례: 8개 가족사를 이름 확인만으로 모회사·자회사 조직도에 배치한다.
- 허용되는 변형·복합: 같은 크기의 카드로 하위 항목을 표현할 수 있으나 카드 모양이 종속 관계의 근거는 아니다.
- 다른 구조를 검토할 때: 다중 관계·회귀가 있으면 연결 구성, 단순 동등 항목이면 카드·분할을 검토한다.
- 한국어·문구 조정: 긴 법인명은 공식명을 보존하고 약칭은 확인 후 사용한다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 하위 그룹을 나누고 상위 위치 표식을 반복하되 실제 부모를 바꾸지 않는다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 실제 종속·소유·조직 관계 출처가 없으면 계층 주장과 배치 후보를 분리한다.

적용 참고: [Carbon 2x Grid Guidelines](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/guidelines), [NN/G 시각 디자인 5관점](https://www.nngroup.com/articles/principles-visual-design/), [NN/G 근접성 적용 지침](https://www.nngroup.com/articles/gestalt-proximity/). 기존 명칭의 정의 출처는 프로젝트 사전이며 외부 지침이 이14개 명칭을 표준화했다는 뜻은 아니다.

## 연결 구성 · LAYOUT-NETWORK

연결·관계를 배치로 표현 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-CORRELATION, REL-CAUSE, REL-SPACE · 모양만으로 자동 부여하지 않음.

- 선택 조건: 여러 대상 사이의 관계·흐름·인과가 설명의 대상일 때
- 읽는 순서 후보: 노드의 의미→선/방향 범례→핵심 연결→다른 관계
- 구성할 때 판단: 선 종류·방향·라벨로 관계를 표시한다. 겹침을 줄이되 위치가 실제 공간인지 개념 배치인지 나눈다.
- 적용 예: 시나리오가 설명하는 침투 경로와 압력 관계를 관계 라벨이 있는 연결도로 표현한다.
- 오용 반례: 관련 선 하나를 그렸다는 이유로 과학적 인과가 증명됐다고 기록한다.
- 허용되는 변형·복합: 관계를 강조한 개념 위치는 허용하지만 실제 시설 위치와 혼동되면 별도 공간도로 둔다.
- 다른 구조를 검토할 때: 직선 순서가 중심이면 프로세스, 실제 위치가 중심이면 공간 표식을 검토한다.
- 한국어·문구 조정: 노드명·선의 관계명·단위를 분리하고 교차선의 설명이 어느 선에 붙는지 확인한다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 부분 연결을 나눌 때 전체 맥락·공유 노드 식별·돌아가는 연결을 유지한다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 관계 종류·방향·실제 인과 근거가 없으면 관련이라는 관측과 인과 주장을 구분한다.

## 전체와 상세 · LAYOUT-OVERVIEW-DETAIL

전체 맥락과 선택 부분 상세를 함께 표현 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-PART · 모양만으로 자동 부여하지 않음.

- 선택 조건: 전체와 선택 부분의 대응을 유지하며 상세를 설명할 때
- 읽는 순서 후보: 전체 위치→선택 부위→상세→전체에 미치는 관계
- 구성할 때 판단: 선택 위치·연결선·배율 또는 개념 확대 여부로 전체/상세 대응을 드러낸다.
- 적용 예: 교량 전체도에서 특정 접합부를 표시하고 같은 접합부 상세를 옆에 둔다.
- 오용 반례: 상세도와 다른 현장의 전체도를 가까이 두어 같은 부위처럼 보이게 한다.
- 허용되는 변형·복합: 상세의 배율이 달라도 개념 확대 표시와 부위 대응이 있으면 후보가 된다.
- 다른 구조를 검토할 때: 위치 라벨 중심이면 공간 표식, 두 대상의 독립 설명이면 일반 분할을 검토한다.
- 한국어·문구 조정: 상세명·전체 위치명·확대 설명을 구별하고 작은 전체도의 식별성을 확인한다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 전체 위치를 작은 앵커로 남기거나 전후 상태 사이 같은 부위의 식별 정보를 보존한다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 전체/부분 동일성·부위 근거가 없으면 대응의 적합성을 확정하지 않는다.

## 공간과 설명 표식 · LAYOUT-SPACE-CALLOUT

지도·구조·공간 대상에 명칭·주석을 연결 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-SPACE, REL-PART · 모양만으로 자동 부여하지 않음.

- 선택 조건: 위치·시설·부품과 명칭의 대응이 중요한 경우
- 읽는 순서 후보: 기준 공간→대상 위치→라벨·주석→관계 설명
- 구성할 때 판단: 라벨을 대응 대상에 가깝게 두고 혼잡하면 리더라인을 사용한다. 실측 좌표·개념도·투영을 구분한다.
- 적용 예: 시설 도면의 대상에 번호와 명칭을 연결하고 중첩 라벨을 분산한다.
- 오용 반례: 보기 좋게 하려고 실제 위치를 옮기거나 연결선이 다른 시설을 가리킨다.
- 허용되는 변형·복합: 이소메트릭·정면·실사 위 주석은 표현 속성이며 그 자체로 새로운 레이아웃 이름은 아니다.
- 다른 구조를 검토할 때: 세부 확대가 중심이면 전체/상세, 비공간 관계는 연결 구성을 검토한다.
- 한국어·문구 조정: 긴 기술명은 라벨 영역을 늘리거나 번호+범례로 분담하고 부위 이름을 임의 줄이지 않는다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 같은 공간을 유지할지 상세 뷰로 분절할지 선택하고 실제 위치 이동은 피한다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 위치·좌표·도면 버전·라벨 대응이 없으면 실측 공간 정확성을 주장하지 않는다.

## 데이터 시각화 · LAYOUT-DATA-CHART

데이터 관계를 차트로 구성 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-PARALLEL, REL-TIME, REL-PART, REL-CORRELATION · 모양만으로 자동 부여하지 않음.

- 선택 조건: 수치의 비교·변화·분포·부분전체를 읽어야 할 때
- 읽는 순서 후보: 질문·수량 의미→축·단위·범위→데이터→핵심 해석
- 구성할 때 판단: 질문에 맞는 차트 후보를 선택한다. 막대 비교의 기준축, 추세선의 범위, 결측·출처를 구분한다.
- 적용 예: 가상의 공법 비용을 같은 단위·0 기준 막대로 비교하고 값과 조건을 표시한다.
- 오용 반례: 막대 길이의 비율 비교에서0기준을 잘라 작은 차이를 과장하거나, 다른 단위·기간을 같은 막대로 비교하거나, 자료 없는 중간값을 실측처럼 연결한다.
- 허용되는 변형·복합: 추세선의 잘린 범위는 명시하고 검토할 수 있다. 모든 차트에 0 시작을 강제하지 않는다.
- 다른 구조를 검토할 때: 정확한 여러 값 조회는 표 후보, 하나의 값만 강조하면 단일 초점을 검토한다.
- 한국어·문구 조정: 수치·단위·축 라벨을 서로 대응하고 긴 범주명은 방향·차트 종류 변경을 고려한다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 범주/축을 재배치할 때 값·단위·범위·비율을 보존한다. 글자만 줄여 해결하지 않는다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 데이터·단위·기간·척도·보간 구분이 없으면 차트의 사실성 통과를 보류한다.

## 실제 UI와 설명 · LAYOUT-UI-ANNOTATION

제품 화면과 설명·초점·표식을 결합 — 기존 프로젝트 정의.

관련 정보 관계 후보: 입력 관계에 따라 달라짐 · 모양만으로 자동 부여하지 않음.

- 선택 조건: 실제 제품 화면 출처가 확인되고 특정 조작·기능 설명이 필요할 때
- 읽는 순서 후보: 작업 목적→실제 UI 기준 화면→대상 조작→결과
- 구성할 때 판단: 제품 화면의 버전·기능·선택 영역을 유지하고 실제 UI와 외부 주석을 구별한다.
- 적용 예: 제공된 실제 프로그램 화면에서 저장 버튼과 결과 영역을 표식으로 설명한다.
- 오용 반례: 새로 그린 가상 버튼을 실제 제품 기능으로 보여 주거나 클릭 후 결과를 임의 합성한다.
- 허용되는 변형·복합: 실제 UI 주위에 외부 설명판을 추가할 수 있으나 제품 안의 문구로 오인되지 않게 구분한다.
- 다른 구조를 검토할 때: 단순 화면/본문 역할 분리는 분할, 영상 안 작은 실제 화면은 PIP와 복합 가능하다.
- 한국어·문구 조정: 작은 UI 전체를 읽히려 하지 말고 작업에 필요한 명칭과 영역을 확대·설명한다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 전체 메뉴를 유지할 필요와 대상 확대 필요를 비교한다. 버튼 위치·기능을 재디자인하지 않는다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 제품 버전·화면 출처·실제 기능 근거가 없으면 실제 UI 태그·기능 주장을 보류한다.

## 카드 그룹 · LAYOUT-CARD-GROUP

독립 항목들을 카드 형상으로 묶음 — 기존 프로젝트 정의.

관련 정보 관계 후보: REL-PARALLEL, REL-ORDER · 모양만으로 자동 부여하지 않음.

- 선택 조건: 같은 역할의 독립 항목을 반복 구조로 묶으면 읽기에 도움이 될 때
- 읽는 순서 후보: 그룹 제목→항목 명칭→공통 역할 정보→차이
- 구성할 때 판단: 카드의 경계가 그룹을 돕는지 확인한다. 같은 역할은 같은 정보 순서, 서로 다른 관계는 연결·배치로 표현한다.
- 적용 예: 동등한 사업 분야를 명칭·대표 이미지·짧은 설명이 같은 순서인 카드로 정리한다.
- 오용 반례: 한 과정의 원인·결과를 독립 카드로 떼어 놓아 관계를 숨기거나 카드 자체를 항상 금지한다.
- 허용되는 변형·복합: 카드 안에 차트·단계·비교가 있을 수 있다. 카드라는 모양과 관계를 분리한다.
- 다른 구조를 검토할 때: 관계선이 핵심이면 연결 구성, 긴 정밀 비교는 표 후보, 핵심 하나면 단일 초점을 검토한다.
- 한국어·문구 조정: 긴 카드 제목은 영역·줄바꿈을 조절하고 한 카드만 작은 글자를 쓰지 않는다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 개수를 줄여 구간을 나눌 수 있으나 항목이 동등하다는 역할과 전체 개수를 잃지 않는다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 독립·동등한 항목인지 불분명하면 반복 모양만 관측하고 정보 관계는 보류한다.

## 분할 구성 · LAYOUT-SPLIT

서로 다른 역할의 화면 영역을 나눈 구성 — 기존 프로젝트 정의.

관련 정보 관계 후보: 입력 관계에 따라 달라짐 · 모양만으로 자동 부여하지 않음.

- 선택 조건: 화면과 설명 등 서로 다른 역할을 나눠 동시에 참조할 필요가 있을 때
- 읽는 순서 후보: 주 대상→연결된 설명→필요한 추가 맥락
- 구성할 때 판단: 영역의 읽는 역할과 대응을 명확히 한다. 같은 폭·다른 폭을 역할에 따라 후보로 둔다.
- 적용 예: 공법 단면도 옆에 해당 부위의 설명을 두고 색·번호로 대응한다.
- 오용 반례: 왼쪽은 A 공법 사진, 오른쪽은 회사 소개문인데 비교 화면이라고 한다.
- 허용되는 변형·복합: 반반 배치 자체가 비교는 아니다. 동등 비교 항목이 확인되면 비교 태그를 추가한다.
- 다른 구조를 검토할 때: 전체/부분 동일성이 있으면 전체/상세, 작은 중첩이면 PIP를 검토한다.
- 한국어·문구 조정: 긴 본문은 요점·지원 정보를 나누되 사실과 필수 정보는 임의 삭제하지 않는다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 상하 재배열에서 그림과 설명의 대응을 유지하고 본문이 자막과 충돌하지 않게 둔다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 영역 역할과 대응 대상이 없으면 적합한 읽는 순서를 확정하지 않는다.

## 화면 속 화면 · LAYOUT-PIP

주 화면 안에 별도 화면을 중첩 — 기존 프로젝트 정의.

관련 정보 관계 후보: 입력 관계에 따라 달라짐 · 모양만으로 자동 부여하지 않음.

- 선택 조건: 주 화면을 유지하며 보조 화면·발표자·다른 관점을 함께 보여 줄 때
- 읽는 순서 후보: 주 화면의 과제→보조 화면의 역할→둘의 대응
- 구성할 때 판단: 삽입 위치·크기가 주 화면의 필수 정보·자막·조작을 가리지 않게 하고 보조 화면을 읽어야 하는지 확인한다.
- 적용 예: 실제 제품 시연의 주화면 안에 작은 발표자 창을 삽입하고 중요한 버튼·자막이 없는 위치에 둔다.
- 오용 반례: 작은 발표자 창이 제품의 저장 버튼이나 핵심 수치를 가린다.
- 허용되는 변형·복합: 작게 중첩했다고 보조 역할인 것은 아니다. 어느 정보가 핵심인지 입력으로 확인한다.
- 다른 구조를 검토할 때: 두 화면을 모두 상세하게 읽어야 하면 일반 분할이나 구간 분절을 고려한다.
- 한국어·문구 조정: 삽입 화면 속 긴 텍스트는 확대·별도 장면 후보로 검토하고 무조건 작게 유지하지 않는다.
- 가로 화면: 내용 역할을 나눈 영역의 폭을 조절한다. 화면 전체를 꽉 채울 의무는 없다. 핵심·단위·출처가 읽히는 완성 상태를 확인한다.
- 세로 화면: 주/보조 역할을 유지하되 삽입 위치를 옮기거나 별도 장면으로 전환해 가림을 피한다.
- 정사각 화면: 필수 내용·관계·비례를 잃는 중앙 크롭만으로 해결하지 않는다. 손실 없는 크롭·영역 재배치·구간 분절도 후보로 비교하고 실제 문구와 표시 조건을 확인한다.
- 시간·가림 조건: 정보가 완성된 상태와 유지 시간을 별도로 확인한다. 읽기 가능한 대비·가림·배치가 유지되는 구간인지 보고 모션 자체의 길이로 대체하지 않는다.
- 기권 조건: 자막·플레이어 UI·중요 버튼의 위치를 모르면 최종 가림 검수를 보류한다.
