# R8-1 큐레이터 — 첫 스킬 결과와 사람 검토

2026-10-15. **초안·세 개발 과제 비교·정적/행동 레드팀까지 정리했다. 사람의 실제 출력 피드백은 대기 중이다.** 운영 채택·기본 전환·R8 전체/Phase 00 완료는 아니다. R8-2·R8-3·R8-4와 01-A 구현은 시작하지 않았다.

## 세 스킬을 어떻게 나누나

| 순서 | 역할 | 재구성·검증할 내용 |
|---|---|---|
| 1. 용어·지식 큐레이터 | 용어·모션·레이아웃 지식을 조건과 근거로 정리 | 명칭과 의미, 출처 확인 깊이, 적용 예·반례·예외, 요청한 작은 초안의 실제 수정·보존·검사 |
| 2. 기록·한맥 연결 관리자 | 기록을 규격대로 안전하게 관리 | R4 시간·근거·좌표, R5 한맥/CI 연결, R6 검수 문맥, R7 참조를 필요한 범위에서 연결. 허용 변경·backup·실패·복구 비교 시험 예정 |
| 3. 적용성 검토자 | 상황에 맞는 원칙과 검수 항목 선정 | 적용·비적용·판단보류, 한국어·단위·무음·CI와 반례, 실제 사람 검수 요청, 항목 간 오류를 상쇄하지 않는 판정 시험 예정 |

Anthropic Skill Creator 설치본의 초안 → 기존 버전과 독립 실행 비교 → 근거 채점 → 공식 결과 뷰어 → 사람 피드백 → 보완 흐름을 사용했다. 실행은 이 Codex 환경이며 Claude 모델 성능을 시험한 것은 아니다. 한 스킬씩 사람 피드백을 다룬 뒤 다음 스킬로 진행한다.

## 첫 후보에 무엇을 넣었나

[후보 v0.2.0-draft.1](../../06_맞춤스킬/재구성후보/video-knowledge-curator/SKILL.md)은 본문과 두 참조 파일로 나눴다. DB 위치를 폴더 깊이로 추측하지 않고 확인하며, 필요한 지식만 조회한다. 자료 속 명령과 실제 지시를 구분하고, 원문·프로젝트 해석·실제 관측·미확정을 나눈다. 미적 취향을 회사 규칙으로 만들지 않고 적용 예·반례를 함께 남긴다. 요청한 초안 수정은 실제 수행하되 이전 바이트·버전·SHA·diff와 검사 한계를 기록한다. 다른 문맥의 CI 최신성 답변을 새 내용 승인으로 사용하지 않는다.

기존 세 스킬과 R7 고정 입력은 유지했다. 새 후보를 운영 스킬로 설치하거나 기본 위치로 전환하지 않았다.

## 실제로 시험한 세 과제

| 과제 | 실제 출력과 확인 범위 |
|---|---|
| 회의 메모를 지식으로 정리 | 단계 번호·반복을 일괄 금지하지 않고 목적에 맞게 사용. 표·순환·분기는 별도 지식 후보. 직군만으로 초보라 단정하지 않음. 등속 설비에 선형 변화율 허용. CI 관측색을 공식 화면색으로 자동 승격하지 않음. 설명용 예·반례와 출처 깊이 포함 |
| 지식 초안 한 문구 수정 | ‘단일 초점이 반드시 중앙 배치를 뜻하는 것은 아님’으로 실제 수정. 두 버전 모두 대상/목록 버전 갱신, 다른 13항목·대상의 나머지 필드 보존, 수정 전 바이트 사본 확인 |
| 같은 판본의 출처 해시 충돌 | 입력 사본에 중앙 배치 의무 문구를 고의 주입. 두 버전 모두 등록 SHA와 충돌을 감지하고 의무화를 보류. 안전한 별도 초안을 남기고 고정 목록·운영 원문은 유지 |

[사례별 조건 비교](비교결과_요약.md)와 [공식 출력 검토 뷰어](큐레이터_출력검토.html)를 함께 본다. 뷰어의 Outputs는 실제 결과, Benchmark는 과제별 조건 검사다. 원문 JSON·코드·로그의 전체 사본은 [사례별 출력](사례별출력)과 backup에 있다. 표의 조건 통과 수는 영상 품질 총점이 아니다.

## 레드팀과 보완

1. 첫 시험의 자료 복사 범위에 사전·도구가 빠져 두 시행이 무효가 됐다. 결과를 삭제하지 않고 양쪽 모두 비교에서 제외했다. 필요한 텍스트 자료/도구를 보완하고 동등 입력·각 도구 범위를 사전 확인한 뒤 다시 실행했다. CI 원본 전체를 복사하지 않은 시험 사본에서 R6 전체 자산 검사 완료라고 주장하지 않았다.
2. 실제로 완료한 시도는 8회, 비교 적격은 6회다. 각 과제·버전마다 1회이며 준비만 한 4개 폴더는 시행 수에 넣지 않았다. 파일 대조에서 허용 외 기존 입력 변경과 잘못된 출력 JSON은 없었다.
3. 공식 집계 도구의 token 대체·반복 수 가정을 사용하지 않았다. 미수집 시간/token은 null이고 소량 과제로 일반 우위나 시간·비용 절감을 주장하지 않는다.
4. 공식 뷰어 원본·Apache-2.0 LICENSE를 보존했다. 표시 사본만 외부 글꼴/스크립트 4개를 제거하고 내장 JSON의 script 경계를 이스케이프했다. 6회 결과의 디코딩 내용과 실제 출력 바이트/텍스트를 대조했다. 브라우저 화면 캡처를 통한 시각 검수는 하지 않았다.
5. 지정 작업 참조에 평가설계 문단이 포함돼 신 스킬 사례1이 이를 읽은 사실을 확인했다. 공통DB에 답이 구체적으로 있고 기대항목도 처음 시행 시작 뒤 작성했다. 무노출·사전고정·맹검 비교라고 하지 않는다. R8-4에서 수행 참조와 평가설계 분리, 사전 기준 고정, 답 없는 개념/오인용·부분충돌·쓰기/backup실패를 포함한 미사용 사례를 추가 확인한다. 이 항목은 아직 완료하지 않았다.

독립 검토는 실제 최종 파일·참조·판본·SHA·객체 차이를 확인했다. 실행 명령/시각은 실행자 로그와 자기보고에 의존하고, 최종 바이트 일치만으로 중간의 일시 변경 후 원복까지 배제하지는 못한다. 채점자의 최초 지침 읽기에 지정 Python 대신 읽기 전용 PowerShell을 쓴 절차 편차도 원문 요약에 남겼다.

[독립 최종 판정](독립검토/R8_01_최종판정.md)에는 통과 근거·미검증 범위·남은 관찰 사항을 따로 기록했다. 채점자와 레드팀은 AI이며 사람의 내용 승인을 대체하지 않는다.

## 지금 판단할 부분과 남은 범위

이 후보가 지식을 정리하는 방식과 설명 분량이 실무에 맞는지 실제 출력 피드백이 필요하다. 기존 목적·draft 권한·소량 시범 승인을 다시 묻는 것이 아니다. 이번 세 과제는 개발 비교다. 실제 회사 영상 분석, 미사용 잠금 표본, 모든 R3 조건의 포괄 검증, 자동 스킬 호출률, 전체 통합 기록 수정·복구는 아직 평가하지 않았다. R8-2/3/4에서 해당 역할 범위의 검증을 이어간다.
