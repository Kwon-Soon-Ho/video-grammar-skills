# R7-4 1·2단계 검토 보고

2026-10-15 · 현행 대조와 검수 연결/읽기 도구의 한정 범위 검토를 마쳤다. 3단계 등록·읽는 순서·R8/01-A 인계는 다음 검토 대상이다. 전체 Phase 00 완료나 실제 영상 평가 결과가 아니다.

## 1단계 — 이어 쓸 기반 확인

R2의 네 기록 단위, R4 v0.2 시간/근거/좌표 계약, R5 디자인 초안, R6 출처·실제 회신, R7-1~3 품질 항목/평가 계획의 현재 참조를 대조했다. 사용자의 A 선택 원문과 질문 식별자를 별도 보존했다. 기존 130입력과 착수 backup이 일치하고 R6 현재 조회가 정상임을 확인했다. 이 숫자는 바이트/참조 확인 범위이며 130개 문서를 새로 의미 정독한 연구량이 아니다.

독립 검토에서 실제 CI 최신성 회신1건/8회사 확인과 새 R7 내용 검수0건, 과거 예시와 실제 자료, 선택권한 경계를 구분했다. 실제 기록·영상·회사 승인 검수는 수행하지 않았다.

## 2단계 — 결과를 근거·사람 질문에 연결

기존 구조의 필드22곳과 품질 항목26개의 연결 후보, 빈 검수 양식, 필수항목/보류·변경 후 재검토·동일 원인의 연결 규칙을 만들었다. R4/R5 구조 예시의 가상 값을 실제 근거로 쓰지 않으며 필요한 시간/좌표만 연결한다. 동일 원인으로 자막·그래프가 틀려도 영향은 각각 남기고, 고유 원인 묶음으로 R7-3의 고정 평가 분모를 사후 변경하지 않는다.

읽기 도구는 기반 130파일의 고정 SHA/ID·버전·선택 참조와 필드/빈 양식 구조를 확인한다. 고정된 R6 파일 바이트를 대조하지만 R6 조회를 실행하지 않는다. 실제 R4/R5/R7 기록·내용·회사/사용권한·사람 신원과 영상 성능은 검사하지 않는다.

## 레드팀 발견과 보완

실제 사본의 변경은 기존 해시 검사에서 차단됐다. 별도의 메모리 구조 단위검사에서는 필수 입력란/정책 삭제, 예시를 실제 검증 자료로 표시, 0 대신 false 입력, 필드 위치 전체 누락 등 10종을 내부 구조 검사에서도 거부하도록 보완할 필요가 드러났다. 고정 해시를 우회한 공격이나 실제 DB 손상으로 표현하지 않는다.

필수 양식 키와 값 타입, 정책 상수, 자료 범위, 22개 연결 ID와 비어 있지 않은 후보, 건수의 엄격한 정수0 검사를 추가했다. 내용 대조에서 판정 방법/담당 역할 칸도 추가했고, Windows 콘솔에서 특수문자 경로의 오류도 JSON으로 출력되도록 보완했다. 최종 연결 문맥은 v0.1.3, 빈 양식은 v0.1.1이다. 변경 전 후보·코드/목록 해시·최초 실패와 보완 후 반례를 보존한다. 중간 후보는 승인된 정본 판본으로 사용하지 않는다.

보완 후 독립 반례는 정상 대조·파일/참조 어긋남·경로·JSON 파서·양식/정책·끝시점 변경·Windows 콘솔 오류 출력을 확인했다. 조건별 실행 결과는 독립 검토 원문에 남긴다. 문서·구조 단위검사이며 모델/실영상 성적이 아니다. 실제 내용 판단이 필요한 대상은 아직 없어 새 사람 판정을 꾸미지 않았다. R6 기존 회신 범위도 바꾸지 않았다.
