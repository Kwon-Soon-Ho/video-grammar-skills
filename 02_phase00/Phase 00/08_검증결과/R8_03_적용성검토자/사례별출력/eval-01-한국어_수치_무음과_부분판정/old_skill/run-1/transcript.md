## 수행 과정

1. task.txt를 먼저 읽고 격리 범위·지정 스킬·출력 경로·금지 도구를 확인했다.
2. 지정 SKILL.md, references/작업기준.md와 수행사본_범위.json을 읽었다.
3. 검토자료 3개를 원문으로 읽었다. Phase00 아래 파일 경로 목록을 조회해 필요한 제공 근거를 골랐다.
4. 판정운영기준·관련 품질 항목·화면/시간/무음·이식 발췌의 적용 조건을 대조했다.
5. 초안 01~07의 유지·수정 제안을 기록했다. 부정 반전과 수치 1/10 오류는 문서에서 확정하고 화면·음성·시간·난이도 등 필요한 입력이 없는 부분은 별도 판단보류로 남겼다.
6. 실제 사람 질문은 제안만 기록했다. 답변은 null, 발송 false이며 운영 선택은 4개 대안과 추천만 작성했다.
7. 두 결과 파일을 작성했다. 검토기록.json을 ConvertFrom-Json으로 다시 읽어 구문 파싱, 10개 문서 항목·5개 보류, 총점 null, 실영상 검토 false, 실제 회신 null을 확인했다. 이 확인은 공식 검사기·회사 승인·내용 진실성의 통과가 아니다.

## 오류·제약과 처리

- PowerShell 실행마다 InitializeDefaultDrives/FileSystem provider 경고가 있었지만 각 Get-Content·경로 목록·파일 작성/파싱 결과는 정상 반환됐다.
- 첫 다중 파일 조회가 출력 한도에 걸렸다. 필요한 항목별기준 02·03·05를 나누어 재조회했고, 01·04·화면설계 문서를 재조회했다. 재조회 묶음에서도 일부 출력이 생략돼 해당 누락 부분을 전수 검토했다고 주장하지 않는다. 사용한 문서 위치·기준은 표시된 근거에 한정했다.
- 품질항목 정본의 속성 확인에서 cards를 제외하지 못해 JSON 요약 출력이 길어지고 깊이 경고/출력 잘림이 발생했다. 이후 메타데이터와 선택 카드 요약만 명시적으로 재조회해 사용했다. 파일 내용 변경은 없었다.
- 자료검증.py가 제공 경로에 없어 공식 자료/연결 검사는 실행하지 않았다. Python도 사용하지 않았다.
- 품질항목 정본에 있는 전체 26항목을 모든 영상에 의무화하지 않았다. 문서 대조와 실제 영상 평가를 분리했다.
- 별도 스키마는 제공 범위에서 열지 않았고 결과 JSON은 독립 draft 검토기록이다. full R4/R6/R7 구조 통과를 주장하지 않는다.
