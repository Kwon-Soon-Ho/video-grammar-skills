## 과제/기준의 공정성

세 과제는 요청한 기존 지침의 유지/수정/추가 확인을 보고서로 작성하는 범위다. 입력에 알려진 정상 조건과 문제 제안이 함께 있어 전부 거부만 하는 행동과 근거 있는 부분 판단을 구분할 수 있다. 검토 기준은 같은 실제 제공 자료의 의미·위치, 회신 범위, 관측/제안 구분을 묻는다. 신 스킬의 특정 JSON 키·표현·파일 순서만 정답으로 강제하지 않는다.

모든 수행 입력은 지시상 읽기 전용이고 결과/과정기록만 작성한다. 실제 초안 수정·backup 실패/rollback·전사/OCR·실물 CI 검사·실제 영상 성능은 이 과제로 검증할 수 없다. 기대항목도 이를 수행했다고 요구하지 않고 미실시/범위를 지키도록 한다. 실제 사람 질문 도구를 막으면서 질문을 산출물에 제안하는 것은 모순이 아니다.

## 결과 해석의 제한

1. 공통DB는 정상·예외·보류와 회사 회신 범위에 관한 구체적인 지식을 제공한다. 구/신 모두 이것을 검색할 수 있어 이번 비교는 검색을 포함한 수행 관찰이다. 신 스킬 단독 효과·독립 일반화와 분리할 수 없다.
2. 문제 초안의 오류가 비교적 명시적이며 일부 출처 오류는 쉽게 발견할 수 있다. 개발 점검으로는 유효하지만 미사용 도전 자료나 모든 모호한 사례의 대표성을 보장하지 않는다. 공개한 이번 자료를 향후 holdout이라 부르지 않는다.
3. 기술적인 계정/파일 접근 차단은 없다. 과제 지시로 부모 대화·다른run·다른DB·평가표·추가 스킬 열람을 금지한다. 실행 후 실제 읽기/도구 기록을 대조해야 분리 준수의 관측 범위가 정해진다.
4. R3 제공 발췌는 외부 스킬의 실제 원문 전체가 아니라 **R3가 작성한 이식 검토 문서의 지정5절**이다. 이 발췌 대조를 Taste/Impeccable/Lottie 원문/코드의 새 열람이나 원격 최신 검증으로 보고하지 않는다.
5. 전체 R6 선언/원문·R7 고정 입력/검사 도구와 자산 실물이 없다는 제한이 명시됐다. 제공 회신 내용의 범위 검토는 가능하되 full R6/R7 현재성·구조검사 통과라고 할 수 없다.
6. 고정기록의 `evals_sha256`은 경로키가 없었으나 부모의 경로 설명을 받은 뒤 실제 파일 SHA를 독립 대조했다. 기준값은 바꾸지 않았다. 게시시 해당 원본 경로를 함께 적으면 추적이 명확해진다.

위 한계를 유지하면 예정한6회 개발 실행을 진행할 수 있다. 행동 결과와 모든 시행/실패·미실시·과정기록을 보존한 뒤 별도 출력 검토가 필요하다. 이 감사의 판정 근거와 기대항목을 수행자에게 전달하지 않았다.
