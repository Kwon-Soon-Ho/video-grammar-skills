# 게시 스크립트 보완 — 제한 재확인

2026-10-15. 변경된 게시 스크립트, 게시도구 격리시험 코드/결과만 읽었다. 실행자 출력·채점·미완료 과제는 읽지 않았으며 게시/시험 스크립트도 실행하지 않았다.

현재 게시 스크립트 SHA256: `7b9e939ffe9e31e60ba04d5cfe14dc888eb146f08302712388191d5cb5f8e588`. 격리시험 결과에 기록된 대상 SHA와 일치한다.

**앞선 세 권고의 보완을 확인했으며, 이 제한 정적 재확인에서 추가 진행 차단 사항은 없다.** 실제 게시 가능 여부는 별도 최종6회·뷰어·독립 최종판정이 마련된 뒤 판단한다.

| 이전 권고 | 현재 코드에서 확인한 보완 |
|---|---|
| 완료 상태의 선행 저장 | 시작에 in_progress를 저장한다. 최종 보존·R6/R7·링크 확인 뒤 완료형 본문과 진행상태를 저장하며 최종 확인서 뒤 마지막 게시상태 complete를 기록한다. 예외 때 실패/부분반영 기록을 남기고 마지막 본인 쓰기 hash와 일치하는 본문·상태만 실패 표시한다. |
| 복사 원본의 긴 경로 | exact에서 원본과 목적지를 모두 extended IO 경로로 변환해 hash/copy에 사용한다. |
| 새 복사 바이트 대조 | 복사 전 원본 hash를 구하고 복사 후 원본/목적지 hash가 모두 그 값과 같아야 보존 목록에 기록한다. 다른 기존 목적지의 자동 덮어쓰기는 하지 않는다. |

격리시험은 실제 소스 AST에서 exact/실패기록 함수를 꺼내 C 격리루트에서 실행하는 구조다. 제공 결과는294자 복사/원본 roundtrip·재개·기존 충돌 보존·사후 실패 표시·외부 편집 보호·확인서 파일 존재와 게시 유효성 분리·보고 Markdown 정규화를 다룬다. 시험의 `base_save`는 격리용 대체 함수다. 전체 main 게시 실행·원래 save의 backup·D 변경174개 보존·R6/R7 실제 조회를 독립 실행 검증한 결과가 아니다.

남는 한계는 코드의 명시와 같다. 다중파일 원자적 거래나 완전 동시성 보호를 보장하지 않는다. 실패기록 자체가 저장되지 못하면 오류를 stderr에 남기며 시작 마커가 in_progress에 남을 수 있으므로 파일 존재만으로 게시 완료라고 할 수 없다. 게시 완료는 마지막 complete 마커와 연결된 확인서 hash로 판단한다. 일반 source 디렉터리 열거는 기존 Path 경로를 쓰고 있으므로 격리시험의 긴 파일 바이트 복사 검증을 모든 열거환경의 보장으로 확대하지 않는다.

모델/스킬 실제 쓰기 실패 시험·최종6회 결과 검토로 승격하지 않는다. 이 제한 재확인은 종료하며 최종 감사는 별도 요청을 기다린다.
