# 표본 구성과 평가 자료 유출 방지

2026-10-15 · 계획 초안. 실제 표본/잠금 자료는 아직 0건이다. 목록을 만들었다고 데이터 확보·대표성·잠금이 성립하지 않는다.

## 표본의 세 역할

| 역할 | 쓰는 목적 | 지켜야 할 경계 |
|---|---|---|
| 예비/개발·보정 | 단위 정의·정답 루브릭·매칭/허용오차·사람 검수 부담을 배움 | 반복 열람·수정 가능. 학습/프롬프트/지식 수정에 썼다면 최종 독립 검증 자료가 아님. |
| 잠금 검증 | 고정된 기준으로 미리 보지 않은 원본 묶음에서 성능 확인 | 운영 방식 선택 후 필요한 경우 확보. 입력·정답·분할·지표/임계값·반복정책·실행 버전을 평가 전에 고정. 결과를 보고 조정하면 개발 이력으로 옮기고 새 독립 자료 필요. |
| 도전/회귀 | 핵심 수치/부정어·미상/모순·희귀 모션/가림 등 실패를 집중 확인 | 실제 업무 빈도 표본과 분리 보고. 만들어 넣은 오류·가상 기록·손상 입력은 실제 관측/업무 빈도로 세지 않음. |

실제 업무 분포를 아직 모르므로 대표성 있는 모집단/가중치를 주장하지 않는다. 자료 목록을 받은 뒤 포함/제외 기준·프로젝트/영상 수·구간 수·독립 원본 묶음 수·시행 수를 각각 표시한다. 영상 길이나 프레임 개수가 큰 한 영상이 결과를 지배하지 않도록 영상/원본 묶음별 요약도 함께 보고한다.

## 무엇을 다양하게 포함할까

| 축 | 포함/확인할 조건 | 비어 있을 때 |
|---|---|---|
| 정보 과제 | 비교/공정/구조/수치/제품UI·그 밖의 실제 용도 | 누락 유형을 명시. 그 용도까지 일반화하지 않음. |
| 글자·언어 | 한글 긴 명칭·영문/기호·숫자/소수·부정어·단위/첨자·대체글꼴 | 쉬운 큰 제목만으로 OCR/내용 정확도를 주장하지 않음. |
| 시간·모션 | 정지/동시/순차/빠른 공개·가림·카메라/대상 이동·실측/연출 | 모든 모션·부재 검출 성능으로 확대하지 않음. |
| 파일/표시 | CFR/VFR·화면비·크롭/회전·해상도·압축·SDR/HDR/반복·최종 플레이어 | 없는 조건은 미평가로 보고. 별도 포맷 생성/변환은 이번에 하지 않음. |
| 오디오/자막 | 무음·발화/TTS·경보/음악·자막 정합/불일치·대본과 화면 차이 | 자료 부재와 확인된 무음을 구분. 오디오를 안 주고 청취 성능을 평가하지 않음. |
| 회사/자산 | 실제 사용 회사·공동 회사·CI/웹 참고·다른 버전 | 8회사에 영상이 각각 있다고 가정하지 않음. 최신 CI 확인을 새 성능 자료로 세지 않음. |
| 근거 상태 | 충분/불충분/모순·복수 해석·비적용·판단보류가 정답인 경우 | 정답이 쉬운 성공 사례만 고르지 않음. 보류 사례도 따로 평가. |

각 축의 표본 수와 조합은 아직 null이다. 26품질 항목마다 어떤 과제/근거/적용·반례·보류 조건을 포함할지 연결하되 모든 조합의 전수 완비나 임의 고정N을 약속하지 않는다. 예비 확인 후 우선순위·모집 범위·필요 정밀도·담당 가능 시간을 보고 사람에게 표본 수/수치 계획을 검토받는다.

## 원본 묶음 단위로 분리

같은 프로젝트의 핵심 장면/대본·거의 같은 재편집본·파생 클립/프레임·번역/자막 버전·핵심 화면 템플릿을 공유하는 근접 사례는 source_family로 묶어 예비/개발과 잠금 검증을 가른다. 회사명·파일명·해시가 다르다는 이유만으로 독립 표본으로 보지 않는다. 그룹 경계를 정한 근거와 불확실한 중복 후보는 사람 확인 대상으로 남긴다.

공통 로고·폰트·승인된 용어집/일반 원칙을 쓴다는 이유만으로 모든 영상을 한 그룹으로 묶지는 않는다. **평가 목적상 새 내용으로 일반화하려는 핵심 자료의 중복**을 기준으로 한다. 알려진 스타일에 대한 분석과 새로운 스타일에 대한 분석도 별도 조건으로 보고한다. 잠금 입력에 정답·기준답안의 특정 캡처/태그가 담긴 참조가 검색되면 누출 여부부터 조사한다.

분할은 검색 DB·스킬 예시·프롬프트 조정 전에 정한다. 개발자가 이미 본 자료/정답은 미노출 자료라고 하지 않는다. 실제 평가 실행자는 과제 입력을 보지만 개발/조정 담당자는 잠금 정답/평가 사례의 튜닝 이력을 분리해야 한다. 별도 새 실행 문맥에 과제 입력과 허용 참조만 제공하고 정답/이전 답변·피드백을 넣지 않는다. 같은 대화에 공개한 정답을 숨겼다고 가정하지 않는다.

접근 통제/보관 담당·파일 위치·접근/열람 로그·허용 검색 목록을 실제로 마련해야 잠금 운영을 주장할 수 있다. 폴더명·해시만으로 비공개/사람 권한/독립성을 증명하지 못한다. 여건이 안 되면 탐색/회귀 결과로 보고하고 독립 일반화 성적이라고 하지 않는다. 외부 전송 권한은 별도이며 이 계획으로 업로드/API 제공을 승인하지 않는다.

## 필요한 표본 명세

sample_id/version, 실제 원본 ID/해시·파생관계, source_family와 사유, 입력 모드(영상만/영상+대본 등), 목적/포함 조건/제외 사유, 관련 R7-2 항목, 실제/가상·조작 여부, 분할/담당·접근/노출 이력, 기준답안 참조·상태, 필수 근거의 접근 가능 범위, 평가 미실시 이유를 기록한다. 실제 확보 전에는 미기입 템플릿이며 존재하는 영상처럼 등록하지 않는다.

근거: [scikit-learn 누출 설명](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage), [그룹 단위 평가 설명](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)의 독립성 원리를 스킬/영상 평가에 조건부로 옮겼다. 원문은 학습기 평가이고 우리 프로젝트의 대화·검색·원본 그룹 운영은 별도 설계다. 라이브러리나 교차검증은 실행하지 않았다.
