# R7 연결 확인 도구 사용 안내

2026-10-15 · 사용자 A안에 따른 읽기 전용 도구다. 실행은 고정된 기반 파일과 연결표의 구조를 확인하며, 실제 영상·실제 검수 기록을 평가하지 않는다.

## 먼저 읽을 것

[연결 범위](01_현재기반과_연결범위.md) → [검수·보류 연결 규칙](03_검수와보류_연결규칙.md) → [필드 연결표](기존기록_연결표.json) → [빈 작성 양식](품질검수_작성양식.json).

연결표의 R4/R5 입력은 구조를 설명하는 합성 예시다. R6의 기존 CI 회신은 실제 접수 이력이지만 새 R7 품질 검수 답변으로 쓸 수 없다. 26행은 항목별 연결 후보이지 실제 26건의 검수 결과가 아니다. 22개 필드 위치는 모든 검수에서 전부 필수라는 뜻이 아니다.

## 현재 상태 확인

프로젝트의 기존 Python 환경에서 아래와 같이 실행한다. 프로젝트 폴더가 이동하면 두 경로를 함께 바꾼다. 새로운 설치·네트워크·영상 열기·화면 조작은 필요 없다.

```powershell
& 'D:\00작업\2026-10-02_AI 기반 영상 기획·제작 스킬 체계 개발 및 검증\Phase 00\.환경\Scripts\python.exe' -B 'D:\00작업\2026-10-02_AI 기반 영상 기획·제작 스킬 체계 개발 및 검증\Phase 00\07_실행도구\R7_연결확인.py' --base 'D:\00작업\2026-10-02_AI 기반 영상 기획·제작 스킬 체계 개발 및 검증\Phase 00'
```

출력 JSON의 `valid`와 `errors`, 종료 코드를 함께 본다. 정상은 종료 코드 0, 불일치·입력 오류는 1이다. 도구 자체는 파일을 쓰지 않는다. 결과를 별도 저장했다면 실행 시점의 사본임을 표시한다. [저장 결과](../../08_검증결과/R7_04_02_연결확인_저장본.json)는 작성 시점의 기록이므로 현재 판정으로 재사용하지 않는다.

## 무엇을 확인하나

- [고정 목록](현재연결_입력고정.json)의 지정 파일 집합·해시·JSON ID/버전, 지정 내부 참조의 경로·해시·버전이 맞는지 확인한다.
- 품질 항목 26개와 연결표가 대응하고 지정 필드 위치가 기존 구조에 있는지 확인한다. 실제 R4/R5 기록 전체의 스키마·참조 유효성을 검사하는 기능은 없다.
- 빈 양식의 실제 입력란이 비어 있고 승인·운영 허가가 만들어지지 않았는지 확인한다. 이 양식을 복사해 채운 실제 검수 결과를 검사하는 기능은 없다.
- 루트 밖 경로·중복 JSON 키·비정상 수치를 거부한다. 개별 입력은 8 MiB, JSON 중첩 깊이는 100 등 도구의 제한을 넘으면 오류로 남긴다. 잘라 읽어 통과시키지 않는다.
- 읽기 시작과 종료 시점에 파일을 다시 대조한다. 저장 잠금이나 원자적 파일 묶음 읽기를 보장하지는 않는다.

## 네 종류의 확인을 구분

| 확인 | 실행/담당 | 통과가 뜻하는 범위 |
|---|---|---|
| 기반 연결의 현재성 | 이 R7 도구 | 고정 파일·선택 참조·필드 위치가 맞음 |
| R6 선언·회신 문맥 | 기존 [R6 통합 조회](../../07_실행도구/R6_통합조회.py)를 별도 실행 | 해당 고정 문맥의 출처·회신 연결 검사. 이 도구가 대신 실행하지 않음 |
| 실제 R4/R5 기록 | 실제 자료를 받은 뒤 기존 기록 검사 도구 | 그 기록의 지원 범위 내 구조·참조 검사. 예시 필드 대조로 대체 불가 |
| 내용·시청 품질·회사/사용 권한 | 구체 대상·버전에 대해 담당자 검수 | 실제 답변이 확인한 범위만 기록. 위 세 가지 검사로 대신 승인 불가 |

`r6_fixed_files_current`는 고정 목록에 포함된 R6 파일의 바이트가 일치한다는 뜻이다. `r6_live_query_executed`와 `r6_declaration_context_validated`는 이 도구에서 false다. `actual_R4_R5_records_validated`, `actual_R7_review_records_validated`, `content_verified`, `company_approved`도 false이며 `readiness_proposal`은 평가하지 않는다. 이것은 실패를 숨긴 값이 아니라 이 도구가 수행하지 않는 일의 표시다.

## 어긋남을 발견하면

원본·기존 입력 고정 목록·실행 출력과 변경 이유를 보존한다. 오류를 없애려고 현재 파일의 해시로 목록을 자동 갱신하지 않는다. 실제 변경 범위를 검토하고 필요한 내용·권한 검수를 받은 뒤 새 버전의 문맥을 만들며 과거 참조는 유지한다. 저장 결과만 편집해서 정상으로 바꾸지 않는다.

고정 목록과 도구는 전자서명이나 외부 신뢰 기준이 아니다. 양쪽을 함께 악의적으로 교체한 경우의 진본 인증·사람 신원 인증을 보장하지 않는다. 이 도구는 우발적인 파일·참조 어긋남을 찾는 작은 보조 장치다. 전체 DB의 모든 파일, 옛 규격 자동 변환, 미래 실제 검수 양식의 모든 오류를 검사한다고 해석하지 않는다.

실제 영상 분석·OCR·모델 호출과 실제 평가기는 01-A의 별도 구현이다. 기존 세 스킬을 수정하는 작업은 R8에 남긴다.


빈 양식의 `review_method`는 판정에 사용한 방법, `reviewer_role`은 해당 판단의 담당 역할이다. 실제 검수 시 명시하며 사람이 실제로 판단했는지와 자동 구조 검사만 했는지를 구분한다. 개인 신원 인증·회사 승인으로 해석하지 않는다. 현재 양식은 두 칸을 포함해 모두 미기입이다.
