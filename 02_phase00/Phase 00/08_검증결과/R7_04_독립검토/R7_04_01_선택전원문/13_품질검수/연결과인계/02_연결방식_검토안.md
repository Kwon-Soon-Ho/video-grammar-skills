# 품질 기준과 기존 DB를 잇는 방식 — 네 가지 안

2026-10-15 · **검토 대기, A 추천.** 기존 세 스킬 목적·초안 권한·R7 판정/평가 A안은 유지한다. 새 질문은 R7 연결을 어디에 두고 어떻게 현재성을 확인할지다. 실제 영상/품질 결과를 생성하거나01-A를 실행하는 선택이 아니다.

| 안 | 연결 위치와 확인 방식 | 영향 |
|---|---|---|
| A 추천 | R7 별도 JSON 연결 목록·검수 양식·인계 문서 + 작은 읽기 전용 연결 확인 도구 | R4/R5/R6 계약은 그대로 두고 현행 참조/버전/해시·R7 내부 연결의 어긋남을 확인. 내용/승인은 사람 판단. 실제 기록 판정은 기존 검사와 별도. |
| B | R7 별도 JSON 연결 목록·검수 양식·인계 문서만, 자동 확인 도구는 만들지 않음 | 변경 영향이 작지만 현재성/참조 확인을 매번 수동으로 해야 함. 기계 확인 완료라고 주장하지 않음. |
| C | R6 검수 문맥/규격에 R7 품질 항목을 포함하도록 확장 | 기존50파일 고정·회신 문맥/검사 규격을 다시 설계·검증해야 함. 현행 R6 기록과의 이전 방안이 필요. |
| D | R4 통합 기록 안에 품질 결과 필드를 직접 추가 | 한 기록에서 읽기 쉽지만 규격 판본·스킬 호환·구형 이관·검사기 재평가 범위가 커짐. |

모든 안에서 내용검수·사람 회신·회사/권한 승인은 구조/해시 검사와 분리한다. A의 도구는 파일/참조가 고정된 입력과 일치하는지 보는 기반 확인이며 영상 디코딩/OCR·자동 의미 판정/품질 점수·스킬 실행·DB 자동 수정·검수 승인 기능이 없다. R6 조회도 각기 다른 범위를 확인하므로 R7 도구 하나로 R6/실제 기록 검사까지 통과시켰다고 하지 않는다.

A/B에서 앞으로 실제 검수 결과를 기록하게 되면 대상·버전·근거·적용 이유·상태·사람 대기·수정/재검토 이력을 별도 참조로 남긴다. 지금은 미기입 양식/연결 설계이며 실제 사람 검수 접수0건이다. 원문/기록을 바꾸는 기능은 이 선택에 포함하지 않는다.
