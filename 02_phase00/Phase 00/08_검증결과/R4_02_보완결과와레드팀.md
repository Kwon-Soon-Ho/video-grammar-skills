# R4-2 근거·주장 보완 결과와 독립 레드팀

2026-10-15. **독립 기록 규격·적용 예/반례·사람 검수 대기 절차의 합성 검수 범위 완료.** R4 전체와 Phase 00은 미완료이며01-A 분석 구현은 시작하지 않았다. 사용자 A와 “사람 내용 검수가 필요하면 맡기기”를 반영했다.

## 쉽게 보는 결과

자료의 ID/버전/hash·원본과 파생 → 해당 대상/프레임/구간/인용 → 주장 종류/범위 → 지지·반대·문맥 근거 → 측정/한계 → 사람 검수/재검수까지 연결했다. 자동 검사는 연결·시간·형식 오류를 찾고 화면/문장의 의미를 대신 승인하지 않는다.

| 이번에 정리한 것 | 적용 예·반례 |
|---|---|
| 자료/대상/부분의 식별 | 프레임이 어느 영상·시간에서 나왔는지 연결. 재구성 이미지/다른hash·대상은 원본근거로 쓰지 않음 |
| 주장 종류·범위 | 1장으로 ‘제목이 있다’는 표본 가능; ‘등장/가속/구간전체부재’는 다른 요건 |
| 지지/반대/문맥 | 다른시간자료는문맥으로보존. 유효지지 하나로 오류·반대근거를 숨기지 않음 |
| 측정 표본·단위·오차 | 평균속도는2시각,구간평균가속도는3시각 최소. 순간이징/정확성 보장 아님 |
| 원문과 의도 | 대본계획≠렌더발생. 제작자 확인 구절·주체·대상버전 필요 |
| 사람 검수 대기 | 주장의 구체 ID/버전·이유·우선순위·담당역할을 남김. 자료가 없으면 미확인 유지 |
| 재검수 | 근거/대상/시간/문장 또는 규격/검사기가 바뀌면 기존 receipt는stale |

## 단계별 검토와 보완

1. 착수 감사: 기존12개 메모리 실험에서 정상2·원래차단하는3·누락7유형을 확인했다. 새 규격과 기존 DB를 분리해 설계했다.
2. 자료/근거 연결: 원본/파생·정확한snapshot·대상·R4-1시간·텍스트의Unicode위치/인용을 보완했다.
3. 주장/사람검수: 종류별 최소근거·표본·단위·불확실성·지지/반대/문맥과 검수receipt·stale·대기 목록을 보완했다.
4. 독립 레드팀: 기존79검사통과후에도7우회문제를 발견했다. 표본/단위/파생시간/근거범위/검수종류의 독자 입력과 양성대조를 보존해 수정·재검수했고, 종료직전 발견한유니코드반환예외1건도추가수정했다.

| 독립 발견 | 보완과 재검수 |
|---|---|
| quantity=other로 좌표 미확인 우회 | 목적/단위/표본은 보존하되 별도량계약 미확인→사람대기·supported 금지 |
| clip끝점의frame·부모밖자식clip | 원본 파생edge별 시각/범위 포함 검사 |
| 다른원본frame을사본처럼연결 | 동일ref/확인된동일원본identity 별칭만 허용. 미상별칭대기,모순거부 |
| 다른시간opposeclip+해결문구 | support/oppose timedclip/text 모두범위검사. 실제관련부분겹침은양성보존 |
| 명시시간transcript를다른시점에연결 | 자료/selector/대상/주장시간연결 검사 |
| stale로specimen/human 구분우회 | 검수kind를stale 판정전 별도로 검사 |
| 잘못된Unicode문자열/key의예외 | 구조오류로먼저반환. 정상한글/emoji/NFC/NFD/JSON정상pair보존 |

최종 내장 합성 시험 **98/98**, 독립 입력 **27/27**, 실행 예외 **0**. 독립 검토 중 읽은 파일의 hash가 바뀌지 않았고 정상시나리오·정상clip·프레임사본/별칭·유효반대근거·범위밖문맥을 보존했다. 발견한 차단결함은 최종 후보에서 보완 확인했다. 이는 이 검사 집합의 결과이며 모든입력/실측/영상해석 품질을 증명하지 않는다.

## 사람이 해야 할 검수와 잔여 범위

실제 영상/시나리오가 없어 실제 사람의 내용 검수는 수행하지 않았다. [사람 검수 대기 예시](R4_02_사람검수대기_설명용.json)는 합성용이다. 실제자료가들어오면 미검토·수치·모션/부재·의도·충돌·일반화·미해결 주장에 원본/선택부분·대상·측정표·한계를 붙여 사용자/지정 제작자·디자이너에게 맡긴다. 결과를 받기 전 확인된 주장으로 넘기지 않는다. 이것은 외부메시지전송승인이아니다.

내용검수receipt는 선언의일관성만검사한다. 진짜 검수자/행위·파일존재/hash 일치·인용/OCR/추적정확성은 이번에검증하지않았고 fact_verified/human_identity_verified/company_approved/operational_release는 false다. 원본내용확인과실추출은01-A,권한·검수결정연결은R6/R7,회사공통문법은01-B와구분한다.

**기존 최소DB/자료검증.py의 시간누락4건과 근거·주장누락7유형은 아직기존형식에남아있다.** R4-4에서 새계약을통합하고기존예시·검증기이관/회귀를진행한다. 현재새계약을만들었다고기존검사가충분해진것은아니다. R4-3은좌표·회전/크롭/리사이즈·변환근거, R4-4는R2의4단위/5판정/분류·run/metadata·한맥참조와최소DB통합을남겨둔다. 기존3스킬과R2/R3/한맥정본은변경하지않았다.

## 조사한 자료

W3C PROV-DM의 원본/파생/개정, Web Annotation의 대상·부분·원문표현·Unicode위치, NIST의 측정과 불확실성 관련 본문, 기존 R2/R4-1 규격을 확인했다. 선택한 관련절의검토이며전체표준전문/모든코덱/실영상실험이아니다. 내용판정/최소표본/승격제한은프로젝트설계이고PROV·JSON-LD·GUM완전호환구현이아니다.
