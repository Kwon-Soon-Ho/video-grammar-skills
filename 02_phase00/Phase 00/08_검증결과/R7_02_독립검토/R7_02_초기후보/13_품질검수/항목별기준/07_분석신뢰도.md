2026-10-15 · 품질항목 정본 v0.1.0에서 만든 읽기용 문서. 실제 검수 결과·회사 의무 규정이 아니다. 적용 예/반례는 모두 가상 설명이다. 각 항목은 적용 여부를 먼저 정하고 [공통 판정 운영](../03_판정운영기준.md)을 따른다. 원문 요약과 우리 프로젝트의 적용 해석을 구분한다.

## Q-TRUST-01 · 원본·시간·좌표·근거

- **검수 질문:** 관측/수치 주장에 올바른 버전·실제 위치·시간·변환 근거가 연결되는가?
- **적용 조건:** 영상 분석 기록 및 그 기록을 근거로 한 품질 판단.
- **필요 근거:** 원본/파생 버전·R4 시간/프레임·좌표/변환·실제 접근 가능 근거·반대 근거.
- **검토 방법:** 기존 R4 통합 계약과 R6 조회를 사용하고 원본 부분을 내용 대조. 구조 통과만으로 관측 정확성 통과 불가.
- **적용 예:** 관측 대상을 원본 프레임/PTS와 출력 좌표 공간에 연결하고 크롭된 부분의 누락을 명시한다.
- **오용·실패 반례:** 시나리오에 있다는 이유로 실제 등장했다고 쓰거나 미상 오차를0으로 채운다.
- **허용 예외·비적용:** 시나리오 내용 관측은 그 종류로 기록 가능. 렌더 화면 관측이나 실제 구현 근거로 바꾸지 않음.
- **판단보류 조건:** 버전·원본 접근·시간/좌표 변환·내용 대조가 없으면 해당 주장 보류. 구조 오류는 원정보 보완 후 재검사.
- **영향·우선순위:** 분석 신뢰도의 필수 조건. 보기 좋은 원본이 근거 부족을 상쇄하지 않음.
- **사람 검수:** 분석 내용 검수자·기술/디자인 담당자. 실제 내용·의도·시청 품질의 최종 판단은 해당 근거를 제시하고 맡긴다. 현재는 실제 대상 미접수이며 검수 완료가 아니다.
- **기존 지식 연결:** R4/R5/R6 또는 공통 운영 기준. 새 R3 분류를 만들지 않음.

## Q-TRUST-02 · 의도·구현·부재·일반화

- **검수 질문:** 관측을 넘어선 제작 의도·구현 방식·부재·회사 공통 규칙 주장에 별도 근거가 있는가?
- **적용 조건:** 의도/효과/AE구현/미등장/회사 일반 규칙을 진술하는 분석·보고.
- **필요 근거:** 원본 프로젝트/제작자 확인 또는 충분한 관측 범위, 반대 근거·표본 한계, 구체 사람 회신.
- **검토 방법:** 가설과 확인을 구분. 부분 표본의 부재를 전 구간 부재로, 한 영상 관측을 회사 규칙으로 승격하지 않음.
- **적용 예:** 함께 움직임은 관측하되 AE parent 여부는 원본이 없어 미확인으로 남긴다.
- **오용·실패 반례:** 같이 움직였으니 parent 사용, 화면이 세련됐으니 이해도가 상승, 영상1개이니 회사 규칙이라고 확정한다.
- **허용 예외·비적용:** 근거 범위를 밝힌 후보/추정은 가능. 확인 못한 구현을 모른다고 해도 충분한 화면 관측을 삭제하지 않음.
- **판단보류 조건:** 제작자/원본/전 구간·대표 표본 근거가 없거나 반대 근거가 미해결이면 해당 확대 주장 보류.
- **영향·우선순위:** 근거 없는 확정/잘못된 DB 일반화 방지. 회사 문법 승격은01-B의 별도 검수.
- **사람 검수:** 제작자·내용 담당자·회사 규칙 확인 담당자. 실제 내용·의도·시청 품질의 최종 판단은 해당 근거를 제시하고 맡긴다. 현재는 실제 대상 미접수이며 검수 완료가 아니다.
- **기존 지식 연결:** AP-04, MR-07
