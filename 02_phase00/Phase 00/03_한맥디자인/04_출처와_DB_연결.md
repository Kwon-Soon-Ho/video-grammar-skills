## 채택 기준

브랜드·명암 스케일은 Storybook, 강조색·중립색은 Vercel. 흑백 알파·그라데이션·UI 값은 Vercel 관측 참고이며 자동 필수 규칙이 아니다. 출처 선택 확인은 회사 영상 문법 전체 승인과 별개다.

## 기존 DB 명세로 연결

| 정본 컬렉션 | 기존 엔터티 | 키 | 근거·검수 |
| --- | --- | --- | --- |
| color_tokens | DesignRule | profile_id + token.id + profile.version | observations[].source_ref + locator + value / source_selection_confirmed는 사용자 출처 선택 확인. 회사 영상 문법 승인과 별개. |
| rules | DesignRule | rule.id + rule.version | source_refs + origin / user_directed 또는 draft. 자동으로 회사 approved로 승격 금지. |
| gradients/references | DesignRule | profile_id + id + profile.version | source_ref(s) + locator / observed. 회사 필수 규칙 검색에서 제외. |
| sources | Evidence | source.id + retrieved_on | url + locator + version / 라이브 원문 전체 해시 미확보. curated JSON 해시는 로컬 기록 무결성용. |
| issues | Review | issue.id + profile.version | evidence / handling/status. 신규 출처 선택 시 이전 버전 보존. |

requirement는 required(사용자 운영 정책), available(사용 가능 컬러), recommended(영상 해석 권고), reference_only(선택 참고)로 구분한다. 기존 required/recommended 이진 필드에 available/reference_only를 required로 변환하지 않는다. 필요하면 requirement=optional과 usage_policy를 별도 컬럼으로 두고 매핑한다.

source_selection_confirmed는 출처 선택이 확인됐다는 토큰 메타데이터다. 기존 DB의 draft/reviewed/approved 상태에 그대로 넣지 않는다. source_selection 상태를 보조 필드에 저장하고, 회사 문법 승인 Review는 해당 범위·버전·검수자가 있을 때 별도 생성한다. 이 JSON에서 reviewer=null은 미기록을 뜻한다.

## 기본 로딩·기획 흐름
1. 기본은 global_color_library와 required 정책을 반환. available는 색 선택 가능, 매 장면 사용 의무가 아님.
2. UI·표면·CENTER reference_only는 명시 요청 시만 반환, 회사 필수 검수에서 제외.
3. 관측 분석 시 원본을 기록하고 profile match는 별도 판정. 기획 시 내용·출력 조건을 먼저 확인.
4. 프로젝트 예외는 원래 토큰 수정 대신 project_overrides에 이유·범위·검수 상태를 기록.
5. 변경은 profile version 증가, 기존 장면은 과거 버전 유지. 자동 소급 적용 금지.

한 장면의 예시 계약:

~~~json
{
  "profile_ref": "hanmac-video@0.1.0",
  "palette_role_bindings": {
    "background": "HM-COLOR-GREEN-500",
    "main_text": "HM-COLOR-NEUTRAL-GREEN-100",
    "secondary_text": "HM-COLOR-NEUTRAL-GREEN-200",
    "emphasis": "HM-COLOR-YELLOW"
  },
  "optional_style_refs": [],
  "context": "데이터 구조 설명용 기획 예시. 과거 회사 영상 사례/승인된 템플릿 아님.",
  "project_overrides": [],
  "observation_storage": "관측 pixel RGB, 원본 색공간, 프레임/PTS 및 토큰 대응 추정은 별도 필드."
}
~~~

색은 값 복사 대신 token_id로 연결한다. UI가 필요한 장면만 optional_style_refs에 HM-REF-UI 등을 명시한다. 관측 분석의 원본 픽셀값과 추천 색의 차이는 그대로 남긴다.

## 재생성·검증

Node.js에서 이 폴더의 문서생성.cjs를 실행한다. ID 중복, 출처 참조, 사용자 선택값 일치, 역할 연결, 필수/UI 분리, 30개 전역색·16개 선택 알파·18개 표면 레시피를 확인하고 파생 문서·CSS·대비표·manifest를 생성한다. 토큰 변경은 한맥디자인정본.json에서 수행한다. 실제 영상 렌더 검증과 회사 문법 승인 검사는 후속 작업이다.

현재 범위는 디자인 정제 데이터와 DB 입력 기반이다. 전체 Phase 00 운영 DB, SQL 검색 인덱스, 영상 분석 스킬을 구축 완료했다고 기록하지 않는다.
