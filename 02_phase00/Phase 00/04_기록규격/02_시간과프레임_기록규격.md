# 시간·프레임 기록 규격 — R4-1

2026-10-15, 독립 계약 v0.1.0. 사용자 A 반영. 기존 `최소기록_스키마.json`/`자료검증.py`를 대체하지 않는다. 최종 DB에 연결하는 일은 R4-4이며 실제 영상 값을 획득하는 일은 01-A다.

## 읽는 방법

사람은 “영상 시작부터 3초”로 읽는다. 기계 기록은 초의 분자·분모 `{num: 3, den: 1}`로 저장한다. 29.97을 대충 입력해서 30000/1001과 섞지 않는다. 숫자는 정수 범위 내에서 기록하고 원본 64비트 PTS는 문자열로 보존한다. 큰 수를 지원하려면 후속 버전에서 계약을 확장한다. UI 표시 반올림은 원본 값을 덮어쓰지 않는다.

### 1. 시간축

`timeline`은 정확한 자산 ID/버전/hash와 영상 스트림 번호에 연결한다. 같은 영상 이름이라도 버전·스트림이 다르면 같은 시간축이 아니다. duration은 재생 0초 기준 길이이며 근거 참조를 붙인다. 모르면 null + 설명으로 보존하고 검수 미해결로 표시한다. 0초 길이는 프레임을 담을 수 없다.

원점 `origin.pts`와 `time_base` 및 확인 근거를 보존한다. 단순 오프셋이 확인된 경우에만 `elapsed=(frame_pts-origin_pts)×time_base`로 변환한다. 음수 원본 PTS도 유효할 수 있으나 변환된 재생 시간은 음수가 될 수 없다. 원점은 ‘무조건 첫 디코드 프레임’이 아니다. 편집 목록·속도 변경·불연속 타임스탬프·멀티스트림 매핑이 있어 단순 오프셋을 확인할 수 없으면 origin=unknown, frame=unmapped로 남긴다. 그 변환을 구현하는 코드는 01-A다. 프레임의 time_base와 원점 time_base는 동일 스트림 시간 단위로 확인되어야 한다.

FPS는 부가 메타데이터다. VFR/unknown에서 FPS×초로 프레임 번호를 만들지 않는다. 확인된 CFR만 nominal_fps를 등록한다. 프레임 ordinal은 선택 영상 스트림 전체의 0부터 시작하는 **표시 순서** 번호이며 패킷 번호·추출 이미지 일련번호와 다르다. 전체 프레임 수가 확인됐으면 ordinal<frame_count를 검사한다. 디코딩이 불완전하면 null을 허용한다.

### 2. 구간과 순간

구간은 `[시작, 끝)`이다. 0~3초 다음에 3~5초가 있으면 정확히 3초는 두 번째 구간에 속한다. start<end, end≤duration이다. 0길이 range는 거부하고 단일 순간은 `instant`, end=null로 기록한다. 마지막 끝점 duration 자체는 프레임/instant로 등록하지 않는다. 모르면 `unknown`, start/end=null, 이유 필수다. null은 0초와 다르다.

부모 구간에 연결된 자식의 시간축은 같고 범위는 부모 안에 있어야 한다. 부모가 unknown이면 자식 기록을 보존하되 포함 검사는 미해결이다. 순환 참조·instant 부모 아래 range·없는 시간축/부모 참조는 오류다. R2의 화면 상태/동작 의미 판정은 여기서 자동 수행하지 않는다.

uncertainty는 초 단위 최대 ±오차의 명시값/미상이다. 큰 오차를 적어 경계 밖 명목 시간을 합법화할 수 없다. 오차가 경계를 가로지르면 해당 소속은 미해결로 남긴다. 합리적 오차를 실제로 측정했다는 것은 별도 근거 검토 대상이다.

### 3. 프레임

requested(보고 싶었던 시점)와 actual(실제로 선택한 프레임 표시 시작)을 분리한다. mapped 프레임은 원본 PTS/time_base·원점 변환이 맞아야 한다. best_effort_estimate는 추정 타임스탬프이며 original_pts와 같은 확정 근거로 승격하지 않는다. 미매핑 프레임은 actual=null + limitations를 보존하고 시간 기반 주장에는 사용하지 않는다.

selection_policy는 nearest/at_or_after/at_or_before/manual/unknown이다. 이 규격 검사기는 방향 관계만 확인한다. nearest가 진짜 가장 가까운 프레임인지·미선택 프레임·프레임 표시 지속시간·PTS중복 여부는 전체 프레임 인덱스/영상 없이는 증명할 수 없다. timestamp와 ordinal이 대응하는지는 01-A의 실제 추출 검수가 필요하다.

구간 끝의 프레임을 안쪽 근거로 쓰면 오류다. 경계 전후 비교용이면 context_before/context_after로 따로 표시한다. context 프레임의 이유는 limitations에 적고 해당 구간 안에서 관측했다는 근거로 사용하지 않는다. context도 전체 영상 바깥을 가리킬 수 없다. 구간 연결 없는 프레임은 unassigned이고 소속 검사가 미해결이다.

## 적용 예와 반례

| 상황 | 기록/검사 |
|---|---|
| 원본 시작 PTS=90000, time_base=1/90000, 프레임 PTS=360000 | 재생 시간 3초. 원본 PTS를 그대로 4초로 착각하지 않음 |
| `[0,3)`에서 actual=3초 | within_period는 거부. 경계 비교라면 context_after로 표시 |
| 10초 영상에 actual=100초 | 거부. uncertainty=100을 붙여도 허용하지 않음 |
| start=9초, end=1초 | 거부. range start=end도 거부 |
| VFR의 프레임 간격이 0.04→0.06초 | 각각 PTS로 재생 시각 확인. 평균 FPS에서 ordinal 추정 금지 |
| 원본 시작 -90000, 프레임 -45000, time_base=1/90000 | elapsed=0.5초는 유효. 음수 원본을 무조건 삭제하지 않음 |
| 원점 미확인 | 원본 PTS 보존, actual=null, 미해결. 0초로 채우지 않음 |
| `[0,3)` 끝 근처 ±0.1초 오차 | 명목 소속과 별개로 경계 소속 미해결 표시 |
| 합성 시험에서 hash가 0으로 채워짐 | 인위적 형식 검사일 뿐 파일 존재·진실성·분석 품질 증명이 아님 |

## 출처와 적용 범위

[W3C Media Fragments 4.2.1](https://www.w3.org/TR/media-frags/#naming-time)에서 시작 포함/끝 제외와 재생 시간 의미를 확인했다. DB에 range/instant/unknown을 따로 둔 것과 불확실성·검사 정책은 우리 설계다. W3C URI의 생략 기본값을 DB의 null에 적용하지 않는다.

[FFmpeg AVFrame 7.1](https://ffmpeg.org/doxygen/7.1/structAVFrame.html)에서 PTS/time_base와 best_effort_timestamp의 추정 성격을 확인했다. FFmpeg 7.1을 실행하거나 설치한 것이 아니며 향후 실제 도구 버전을 run에 기록해야 한다.

[JSON Schema 2020-12 Validation](https://json-schema.org/draft/2020-12/json-schema-validation)에서 형태와 format 설정의 한계를 확인했다. 필드 간 크기 비교·원점 변환·포함 관계는 별도 의미 검사다. 스키마 통과는 회사 승인이나 사실 판정이 아니다.

파일: [독립 스키마](시간프레임_스키마.json), [설명용 기록](시간프레임_설명용기록.json), [규격 검사기](../07_실행도구/시간프레임_규격검사.py). R4-2에서 근거 ID/대상/시점/버전을 실제로 해석하는 계약, R4-3에서 프레임 변환 좌표, R4-4에서 기존 DB 이관을 연결한다. 현재 evidence_refs의 문자열 목록은 존재·진실 검증 전 단계다.


추가 경계: [FFmpeg 시간 상수](https://ffmpeg.org/doxygen/7.1/group__lavu__time.html)의 AV_NOPTS_VALUE는 미정 타임스탬프 표시다. -9223372036854775808을 원점/프레임의 유효 음수 시간으로 사용하지 않고 null/unknown으로 변환한다. 타임코드(HH:MM:SS:FF/드롭프레임)는 표시용 라벨이며 PTS·초의 계산 근거를 대신하지 않는다. 라벨을 해석하는 구현은01-A에서 계약에 따라 추가한다.

독립 레드팀 보완: 이 단순 원점 계약은 자산 버전 하나의 영상 스트림마다 시간축 하나만 허용한다. 같은 스트림에 ID만 바꾼 중복 시간축은 값이 같아도 거부한다. 재편집/리타이밍/파생 영상은 별도 자산과 변환 계약으로 R4-3/4에서 연결하며 원본 시간축을 덮어쓰지 않는다. 확인된 duration=0 또는 frame_count=0인 시간축에는 미매핑 프레임도 둘 수 없다. instant는 부모 구간으로 쓰지 않으며 unknown 자식도 예외가 아니다. PTS는 공백·줄바꿈 없는 정규 정수 문자열만 허용한다. 승인 전 초안 v0.1.0의 변경은 x-draft-revision·backup·해시로 추적하고 R4-4에서 통합 스키마 버전과 이관을 확정한다.

원본 PTS를 정상 매핑한 프레임 중 선언된 ordinal을 비교하여 같은 번호의 시각 충돌·표시 순서의 시간 역전을 차단한다. 서로 다른 ordinal이 같은 PTS를 갖는 상황은 임의 금지하지 않는다. 이 내부 모순 검사는 실제 프레임 인덱스의 정확성을 입증하지 않으며 추정 PTS/미매핑 기록은 미해결로 보존한다.
