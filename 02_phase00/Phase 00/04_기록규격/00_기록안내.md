# 최소 기록 규격

스키마는 JSON Schema 2020-12다. 형식 검사는 필수 필드·타입·날짜·범위를, 별도 의미 검사는 ID·출처·분류 축·증거·한맥 연결·승인 상태를 확인한다.

설명용_단계구성_예시.json은 영상·시나리오→상태/모션→근거/주장→디자인 참조의 구조를 보여주는 가상 예다. 파일·타임코드·프레임·측정값은 null/빈값이며 관측하지 않은 수치를 채우지 않는다. 회사 문법으로 승인·검색하지 않는다.

## 미정과 사실의 구분
실제 내부/외부 관측 기록은 파일 경로·해시·시간축·실제 근거가 필요하다. 제공되지 않으면 실제 관측이라 표기하지 않는다. 원본 프레임·추정 수치·의도 확인·가설·설명용 예는 다른 support_mode다. 재구성 이미지는 원본 근거가 아니다.

## 01-A로 넘기는 계약
00은 기반 데이터의 정합성을 검사한다. 프레임 추출·OCR·PTS 획득·시나리오 매칭·수치 추적·실영상 정확도는 구현하지 않았다. 시간·좌표·metadata/run의 최소 기록 계약은 R4에서 확정한다. 실제 도구로 값을 획득하고 상세 출력에 대응시키는 구현은 01-A다. 새 규격은 버전을 올리고 이전 기록을 보존한다.

## 한맥 연결
profile_ref=hanmac-video@0.1.0과 기존 token ID를 참조한다. available는 색 선택 가능, reference_only는 선택 참고다. optional_style_refs와 회사 required 검수는 별개다. 기존 JSON 값과 ID는 변경하지 않는다.


## 수치 추정의 구체 규격

numerical_estimate의 measurement는 방법·측정량·단위·숫자(또는 숫자 벡터)·0 이상 절대 불확실성·원본 추출 프레임 참조·한계·가정으로 구성한다. 불확실성은 value와 같은 단위의 최대 편차로 기록한다. 확인되지 않은 값을 null 객체로 채워 수치 추정으로 통과시키지 않는다. 측정이 없으면 hypothesis 등 미확정 모드로 남긴다. 측정량·표본·방법/근거 참조의 최소 계약은 R4-2에서 보완한다. 실제 곡선 피팅 알고리즘·도구별 확장은 01-A에서 해당 계약에 맞춰 구현한다.

scenario_supported는 script 근거가 original_scenario/transcript 대상 ID에 연결돼야 한다. OCR·설명용 요청·브랜드 프로필을 실제 시나리오로 승격하지 않는다. 문장의 실제 내용 일치 판단은 사람 검수·01-A가 맡는다.

현재 schema_version 0.1.0은 승인 전 초안 계약이며 구체 타입 검사를 보완했다. x-draft-revision과 변경 전 backup으로 개정을 추적한다. 설명용 예는 회사 승인이나 실측값을 포함하지 않는다.


## 2026-10-15 R4 보완 현황

기존 v0.1.0은 호환용 초안이다. 프레임 범위·근거시간 역전/영상범위 누락4건을 착수 감사에서 재현했다. [시간·프레임 독립 규격](02_시간과프레임_기록규격.md)은 별도 검수를 마쳤으나 아직 기존 최소 DB/검증기에 통합하지 않았다. [단계 안내](01_R4_단계별진행안내.md)에 따라 근거·좌표를 검토한 뒤 R4-4에서 통합/이관/회귀한다. 형식 검사가 통과해도 기존 기록의 시간이 충분히 검증된 것으로 판정하지 않는다.


[R4-2 근거·주장 계약](03_근거와주장_기록규격.md)은 자료/대상/범위/근거역할/측정/사람검수대기를 독립 규격으로 보완했다. 합성 검수는 마쳤지만 아직 기존 최소기록에 통합하지 않았다. 내용미검토·충돌·미확인은 사람에게 전달하고 검수 전 확인된 사실로 승격하지 않는다.
