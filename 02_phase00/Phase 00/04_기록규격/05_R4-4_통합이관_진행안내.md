# R4-4 통합·이관 — 단계별 진행안

2026-10-15. 현재 **1단계 착수 감사·연결 설계**다. 구현·이관·통합 종료는 아직 아니다.

## 무엇을 연결하는가

영상 전체 → 설명 구간 → 화면 상태를 식별하고, 짧은 동작은 설명 구간에 속하면서 여러 화면 상태를 참조할 수 있게 한다. 프레임 한 장은 화면 상태 자체가 아니라 그 상태를 확인하는 표본이다. 상태/동작은 시간 범위가 겹칠 수 있고, 서로 다른 범위의 분류를 자동 상속하지 않는다.

이 구조에 ‘언제’를 설명하는 시간 규격, ‘무엇으로 확인했는가’를 설명하는 근거 규격, ‘어느 화면의 어느 부분인가’를 설명하는 좌표 규격을 붙인다. 한맥 디자인·용어 사전은 현재 정본 ID/버전/hash를 참조한다. 디자인 규칙 재정의는 R5다.

| 진행 단계 | 쉽게 설명하면 | 완료 근거 |
|---|---|---|
| 1. 착수 감사·연결 설계 | 현재 파일·빈칸·겹치는 정보를 확인하고 연결표를 만든다 | 원문 snapshot, 이관 대상 목록, 반례, 독립 설계 레드팀, 이관 정책 선택 |
| 2. 통합 기록 계약 | 4단위와 세 규격·분류·실행 기록을 한 기록으로 묶는다 | 스키마, 참조/버전/범위 검사, 예·반례, 레드팀과 수정 |
| 3. 기존 자료 이관 | 원문을 보존하고 옮길 수 있는 값과 확인이 필요한 값을 나눈다 | 이관 보고, 원문/hash, 값별 대응, 누락·불명확 항목, 재실행 안전성, 레드팀 |
| 4. 기본 도구·인계 정리 | 앞으로 어느 파일·검사기를 쓸지 통일한다 | 기본 검사 진입점, 버전별 결과, 과거 시험 보존, 정합성/회귀, 최종 레드팀 |

단계마다 보고하고 반례를 보완한다. 앞 단계 완료만으로 R4-4 전체를 완료 처리하지 않는다. 실제 영상 추출/분석/OCR/추적/픽셀 가공은 01-A다.

## 착수에서 확인한 것

Phase 00의 backup·환경 폴더를 제외한 독립 구형 기록 JSON은 5개다. 설명용 정본 1개, 스킬 시험 입력 1개, 과거 평가 입력/전후 산출물 3개이며 모두 synthetic_example이다. 다른 폴더·미디어 전체의 회사 운영 DB까지 조사한 결과가 아니다. 이번 단계에서 실제 영상은 읽지 않았다.

기존 정본 예시에는 원본 영상 버전/hash·실행 기록·화면 상태가 없다. 레이아웃 태그는 구간에 붙어 있지만 R2는 화면 상태 단위로 정했다. 이런 태그를 보고 실제 화면 상태를 자동으로 만들어낼 수 없다. 스킬·과거 평가의 입력을 새 규격에 맞춘다는 이유로 고치면 과거 비교 근거가 달라지므로 원문 보존과 현행 예시 갱신을 구분해야 한다.

## 고정해서 유지하는 사용자 결정

- R2: 영상/설명 구간/화면 상태/짧은 동작 4단위. 컷은 보조 정보.
- R4-1: 재생 0초 기준과 원본 PTS·변환 근거 보존. 미상을 0으로 대입하지 않음.
- R4-2: 근거·주장 분리, 필요한 내용 검수는 사용자/지정 담당자에게 맡김.
- R4-3: 좌측 위 화면 경계 (0,0), raster px 기본, 픽셀 중심은 (0.5,0.5)부터.
- 맞춤 스킬: 초안 작성·검증, 의미 병합·회사 필수화·승인은 검토 제안. 실제 재구성과 재평가는 R8.
