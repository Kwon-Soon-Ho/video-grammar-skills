# 구형 기록 접수와 이관 규칙 — 사용자 A

2026-10-15. 단계3 후보. 새 통합 규격 v0.2를 기본으로 삼고, 부족한 구형 기록은 **원문과 누락 목록을 접수함에 보존**한다. 실제 파일 접수 결과는 별도 보고한다.

## 접수와 통합을 구분한다

`기록접수.py --source <Phase 00 안의 단일 JSON 경로>`는 원문 bytes를 11_기록접수함에 복사하고 접수기록.json을 남긴다. source.path/원문 JSON hash/bytes/역할/기록버전, snapshot 경로/hash, 누락·재검수 항목, 접수 이력을 기록한다. JSON hash는 **이 JSON 원문 보존값**이며 영상 hash가 아니다. 원문은 수정하지 않는다. 같은 원문·출처의 재실행은 같은 접수 결과를 반환하고, 같은 경로의 다른 내용/동일ID의 다른 파일은 별도로 보존한다. 기존 원문·메타에 다른 내용을 덮어쓰지 않는다.

접수함 schema는 별도다. 분석/회사 문법 검색 허용과 사실/회사/운영 승인 flag는 모두 false다. unknown·미작성·판정불가·구형 검사의 오류를 통합 규격 통과로 해석하지 않는다. 구문 오류·중복 key·비유한수·잘못된 UTF8/문자도 원문을 보존하되 invalid_json으로 격리한다.

미확보 영상 버전/hash·원점·대상·화면 상태·근거·검수 context를 추정하지 않는다. 기존 분류 문구/시나리오/계획은 원문에 보존하지만, 실제 관측 분류·화면 상태·모션을 생성하지 않는다. 아직 식별하지 못 한 원본에 0해시를 채우거나 JSON hash를 영상 hash로 쓰지 않는다.

## 현재 이관 범위

이번 Phase 00 인벤토리에서 찾은 구형 5파일은 설명용 정본 1, 스킬 시험 1, 과거 평가 입력/변경 전후 3이다. 모두 합성 예시이므로 실제 회사 영상 분석 기록으로 옮기지 않는다. 원문/누락을 별도 접수하고 원래 파일과 과거 평가 결과를 보존한다. 새로운 v0.2 합성 예시는 계약을 설명하는 별도 자료이며 구형 예시의 누락값을 채운 이관본이 아니다.

현재 원문에는 새 계약의 대상·범위·근거 역할과 정확한 identity가 없다. 따라서 **구형 의미 전체를 자동 변환하는 도구는 만들지 않는다.** 이 단계의 자동 도구는 원문 접수·누락 진단·검사다. 원본과 대응이 확인된 이후 새 통합 초안을 작성하고, 실제 시간/근거/좌표 연결을 새 검사기로 검수한다. 기존 정보가 충분한 경우에도 새 계약의 의미 대응과 검수 범위를 명시해야 한다. 이관을 사람의 내용 승인과 혼동하지 않는다.

## 이후 실제 기록의 절차

1. 원문 접수 → 누락/충돌 목록 확인.
2. 사용자 또는 지정 담당자가 원본 영상/시나리오의 identity·대상/시간/근거 대응을 확인. 필요한 정보가 없으면 접수 대기 유지.
3. 확인된 값만 새 v0.2 초안으로 작성. 예전 review/approved는 자동 이전하지 않고 새 통합 context를 적용.
4. 자료검증.py --record <새 기록>으로 구조·연결 검사. 미해결·사람 검수 항목을 담당자에게 인계.
5. 실제 내용·권한 검수/운영 승인은 R6/R7 및 실제 자료 확보 후 별도 처리. 01-A는 추출·분석 구현이다.

접수 기록 검사는 원문 사본의 bytes/hash와 메타·누락 진단이 일치하는지를 확인한다. 원문 내용의 사실성·실제 접수 주체 인증·회사 승인 증명이 아니다. 접수함·backup·환경 폴더를 다시 접수하는 재귀 작업과 지정 Phase 00 밖으로의 출력은 거부한다. 다른 프로젝트 실제 DB는 대상 범위를 확인한 뒤 사본 기반으로 별도 이관한다.
