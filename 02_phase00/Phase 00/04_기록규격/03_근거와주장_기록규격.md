# 근거·주장 기록 규격 — R4-2

2026-10-15. 승인 전 독립 계약 v0.1.0. 사용자가 A와 “사람의 내용 검수가 필요하면 넘기지 말고 맡기기”를 선택했다. **자동 검사는 연결 오류를 찾으며 내용을 대신 승인하지 않는다.** 기존 최소 DB/검증기를 대체하지 않는다. 합성 예시는 실제 자료가 아니다.

## 1. 먼저 자료와 대상을 정한다

materials는 영상·원본 추출 프레임·클립·시나리오·전사·OCR·확인 문서 등의 정확한 ID/버전/hash와 위치를 보존한다. parent_ref와 방법 설명으로 원본→파생을 추적한다. 같은 이름으로 덮어쓴 파일, 최신 웹주소, 생성한 재구성 이미지는 원본 근거를 대신하지 않는다. 저장 hash가 실제 파일과 같은지는 이 검사기가 파일을 읽지 않으므로 확인하지 않았다. availability=present도 입력자의 선언이다.

targets는 영상 전체/설명 구간/화면 상태/동작 및 보조 object ID를 구분한다. object는 관측 대상의 식별자이고 R2의 새로운 분류 축이 아니다. 프레임 표본은 화면 상태 자체가 아니다. 해당 영상 버전과 부모·시간 구간을 붙이며 R2의 전체 분류와 5판정 상태는 R4-4에서 통합한다.

evidence는 자료 snapshot과 분석 대상을 연결하고 selector로 해당 프레임/클립 구간/텍스트 구절을 지정한다. 시간은 R4-1 ID를 참조한다. frame 자료의 원본 frame_ref와 selector를 일치시키며 생성/재구성 경유 자료를 원본으로 세탁하지 않는다. clip은 선택 부분이 원본 파생 범위 안에 있어야 한다. 공간 ROI/좌표는 R4-3에서 연결한다.

텍스트는 **고정한 UTF-8 plain-text 표현**에서 Unicode code point 기준 start 포함/end 제외를 사용한다. 원문 인용 exact와 위치가 맞아야 한다. emoji를 UTF-16 단위로 세면 인용이 달라질 수 있다. HTML 정제·PDF 추출·NFC/NFD 변환은 검사 중 몰래 하지 않는다. 어떤 표현으로 바꿨는지 method_note로 기록하고 그 표현과 자료 버전을 고정한다. 텍스트의 실제 원본 일치·OCR 정확성은 내용 검수/01-A에서 확인한다.

## 2. 주장은 작게 나눠 범위와 근거 역할을 붙인다

statement는 사람이 읽는 문장이다. support_mode/aspect/scope는 어떤 종류의 주장인지 정한다. ‘그림이 보임’과 ‘등장 움직임’, ‘구간 평균 가속도’와 ‘순간 이징 곡선’을 한 문장으로 합치지 않는다. scope에는 대상 버전·시간 구간·instant/sampled/continuous/whole_asset/unspecified를 붙인다.

| 주장 종류 | 최소 근거 조건 | 충분하지 않은 예 |
|---|---|---|
| rendered_observation 정적 외관 | 해당 시점의 원본 frame 또는 해당 시점을 포함한 clip | 다른 대상·다른 시간·재구성 이미지 |
| rendered_observation 시간 변화 | 범위 clip 또는 서로 다른 원본 시각 2개 이상. 표본이면 sampled | 한 프레임/같은 프레임의 사본 2장 |
| 연속·영상 전체·구간 내 부재 | 주장 범위를 덮는 원본 clip + 사람의 가림/표본/범위 확인 | 1초에 없었다고 전체 영상에 없다고 확장 |
| numerical_estimate | 방법·량·입력/결과 단위·오차 종류·표본·가정 | FPS에서 임의 시각 환산·단위 혼용·한 표본의 속도 |
| scenario_supported | 원문/전사의 해당 text 구절·대상 버전 | OCR/프롬프트를 원문으로 사용·계획을 렌더 사실로 승격 |
| intent_confirmed | 제작자/기획 책임자의 확인 구절·해당 대상 버전·확인 범위 | 아무 기획 문서 또는 화면 인상으로 의도 확인 |
| hypothesis | 근거 없음도 보존 가능. 확인된 사실로 승격 불가 | 회사 필수 문법/구현 방법 확정 |
| not_observed_example | spec_test 전용. 실제 기록과 분리 | 합성 자료를 실사례/사람 승인으로 등록 |

위 수는 **누락을 막는 최소 구조 조건**이다. 2표본이 장면 전체 변화·정확한 속도·동일 물체 추적을 보장하지 않는다. 장면 복잡도·가림·카메라 이동·컷 전환·표본 간격은 사람이 검수한다. 연속성/부재를 기계가 증명했다고 출력하지 않는다.

evidence_links는 support(지지), oppose(반대), context(문맥)를 구분한다. 문맥 링크는 확인 근거 수에 포함하지 않는다. 대상/시간이 다른 자료는 문맥일 수 있으나 반대 근거로 혼합하지 않는다. 지지 근거 하나가 맞더라도 다른 잘못된 지지 링크를 숨기지 않는다. 반대 근거를 버리지 않고 충돌 해결/기권 사유를 기록한다.

## 3. 수치 기록과 예

measurement에는 method, quantity, sample_unit, unit, value, uncertainty/uncertainty_kind, samples, assumptions, limitations를 넣는다. 표본마다 원본 프레임·support 근거·동일 대상·입력값을 연결한다. count/위치 등 정적량은 최소 1표본, average_speed/duration은 서로 다른 시각2개, average_acceleration은 3개가 필요하다. 다른 시간축·같은 시각만 반복한 표본을 시간량으로 세지 않는다. 현재 core는 원본 프레임에 연결된 스칼라 표본이며 색 벡터·오디오 분석·카메라 3D 추정 등은 별도 계약 없이 기록하지 않는다.

예: t=1초,x=10px → t=2초,x=30px에서 `(30−10)/(2−1)=20px/s`는 **그 구간의 평균 속도**다. 모든 프레임의 순간 속도·AE 키프레임 이징을 확정하는 값이 아니다. t=0,1,2초에 x=0,10,30px이면 두 구간 평균 속도는10과20px/s이고 구간 중점0.5→1.5초의 속도 차이 추정은10px/s²다. 이 방법/표본을 기록해야 하며 화면에서 정확히 추적했다는 검수는 별개다. 계산 알고리즘·자동 추적은 구현하지 않았다.

불확실성 종류는 absolute_bound(명시한 절대 상한), standard_uncertainty(표준편차 성격), unknown을 구분한다. unknown 값은 null이며 0으로 채우지 않는다. 표준 불확실성을 시간 포함 관계의 보장 상한으로 바꾸지 않는다. 불확실성 값·합성 opacity 가정·단위 변환의 실제 타당성은 사람에게 맡긴다. AI confidence 점수는 측정 오차를 대신하지 않는다.

공간량 표본의 coordinate_space_ref는 R4-3에서 실재·단위·변환을 확인해야 한다. 지금은 참조가 있더라도 좌표 검증을 수행하지 않았으므로 사람 검수 대기/미해결로 남기며 supported로 통과시키지 않는다. 사내 한맥 profile/color 토큰을 움직임/기술 구현의 근거로 사용하지 않는다. 디자인 적용 계약은 R5다.

## 4. 사람에게 검수를 맡기는 절차

검사 결과의 human_review_queue에 주장 ID/버전, high/normal 우선순위, 구체 이유, 대기 상태를 남긴다. 실제 자료 확보 후 사용자 또는 지정 제작자/디자이너에게 해당 원본·선택 부분·주장·지지/반대 근거·측정표·한계를 전달해야 한다. 이것은 외부에 메시지를 보내는 작업의 승인이 아니며 이번에는 실제 영상이 없어 자동 생성한 목록도 **설명용**이다.

움직임/부재/수치/의도/반대 근거/구현/회사 일반화는 우선 검수한다. 원문 인용이나 정적 외관도 실제 의미가 확인되지 않으면 대기에 둔다. 자동 검사는 텍스트 내용이 문장과 맞는지 판단하지 않는다. 예를 들어 ‘실제로 등장했다’라는 문장을 scenario_content로 잘못 선언하면 구조상 연결될 수 있으므로 **반드시 내용 검수**한다.

사람 검수 receipt에는 대상 주장 ID/버전, 담당자, 시각, context_sha256, supported/refuted/inconclusive, 판단 사유와 반대 근거 해결 내용을 남긴다. 검수 당시 패키지의 자료/대상/근거/시간과 주장 내용을 hash로 고정한다. 버전 번호를 안 바꾸고 내용을 바꿔도 stale로 재검수한다. 패키지의 무관한 자료를 추가해도 보수적으로 stale가 될 수 있다. DB 전체가 아니라 이 영상/기록 패키지 범위이며 R4-4 이관에서 의존성 범위를 최적화하더라도 누락 방지는 유지해야 한다.

누락/미상 시간·접근 미확인·좌표 미검증·범위 미지정·구조 오류를 사람이 supported라고 적어 우회할 수 없다. 원본 값/연결을 보완한 뒤 다시 검사한다. 반대 근거는 conflict_resolution 없이 supported로 선언할 수 없다. unresolved/inconclusive/stale는 검수 대기에 유지한다. **사람 이름과 receipt JSON은 정체성·진짜 검수 행위를 증명하지 않는다.** 이 검사기는 declared_supported 등 선언 일관성만 확인하고 fact_verified/human_identity_verified/company_approved/operational_release는 항상 false다. 실제 권한·검수 결정 확정은 R6/R7과 연결한다.

spec_test는 모든 자료가 합성이고 specimen receipt만 허용한다. 구조 시험의 rendered_observation/numerical_estimate는 **그 종류의 규격을 시험하는 선언**이며 실제 관측이 아니다. 실제 draft로 목적만 바꾸면 합성 자료 혼합을 거부한다. 예시·검사 입력은 회사 문법 검색/실사례에 등록하지 않는다. 실제draft분기 시험도 메모리 가짜자료이고 운영DB에 저장하지 않는다.

R4-3 좌표/변환·R4-4 최소DB/기존예시 이관을 남겨둔다. 기존자료검증.py의 시간/근거/주장 누락이 이번 독립계약으로 자동 수정된 것은 아니다. 01-A는 원본 추출·OCR·추적·실측 구현과 정확성 시험,01-B는 사내 공통 문법 검수를 담당한다. 기존3스킬/R2/R3/한맥 정본을 변경하지 않았다.

출처: [W3C PROV-DM](https://www.w3.org/TR/prov-dm/)의 원본/파생/개정 구분, [Web Annotation](https://www.w3.org/TR/annotation-model/)의 대상·부분·표현과 문자 위치, [NIST 불확실성 기본](https://physics.nist.gov/cuu/Uncertainty/basic.html)·[결합](https://physics.nist.gov/cuu/Uncertainty/combination.html)의 측정과 오차 구분을 참고했다. JSON-LD/PROV/GUM 완전 호환을 구현한 것이 아니다. 분류·최소 표본 수·사람 검수/승격 제한은 우리 프로젝트의 안전한 기록 설계다. [조사 깊이와 미검토](../05_출처와검토/R4_근거주장_조사기록.json).


검수 재현 조건: context hash에는 근거 계약 스키마·근거 검사기·시간 검사기의 SHA256도 포함한다. 입력이 같아도 계약/검사 코드가 바뀌면 재검수한다. hash 계산은 제공한 Python 함수의 sort_keys/UTF-8/유한수 직렬화 규칙을 사용하며 RFC8785/JCS 구현이라고 주장하지 않는다. 다른 런타임에서 임의로 다른 직렬화를 사용하지 않는다. 원본/파생 지원 자료 또는 시간 메타의 접근·원문이 미확인이면 supported 선언을 차단한다.

원본 자료의 ID/버전/hash를 모르는데 가짜0해시로 채우지 않는다. 이 계약은 식별된 자료를 연결하는 규격이다. 미확보 자료는 별도 준비/조사 대기에 남기고 주장도 hypothesis로 둔다. availability=missing/unknown은 이전에 식별해둔 자료에 접근할 수 없다는 선언이며 hash를 추측하라는 뜻이 아니다.


독립 레드팀 후속 보완: frame←clip의 프레임 시점과 clip←clip의 자식 범위를 부모 시간에 포함시킨다. frame←frame은 같은 frame_ref 또는 **확인된 동일 시간축/표시ordinal/원본PTS/time_base**의 별칭만 허용한다. 원본 identity가 미상인 별칭은 보존·대기, 선언이 모순되면 오류다. 동일PTS만으로 다른ordinal을 같은 원본으로 합치지 않는다. R4-1의 동치 프레임ID는 이 조건 아래 계속 허용한다.

지지와 반대 근거의 clip 및 명시시간 text는 모두 주장 시간과 연결해야 한다. 자료/selector의 time 범위가 다르거나 주장에 겹치지 않으면 오류이며 범위 밖 자료는 context로 기록할 수 있다. 사람의 해결 문구로 시간 모순을 덮지 않는다. receipt의 human/specimen 구분은 stale 여부와 별개로 검사한다.

사용자 정의 quantity=other는 측정 목적·단위·표본을 강제 기존량으로 재분류하지 않고 보존한다. 적용량/단위/좌표/표본의 별도 계약이 미확인이므로 사람 검수 목록에 남기고 supported로 선언할 수 없다. 필요한 확장량의 규격을 따로 검토·정의한 뒤 내용 검수를 다시 받는다. 이번 완료 판정은 core량 계약이며 모든 가능한 측정량을 검토했다는 의미가 아니다.

문자 안전성: JSON의 surrogate만 남은 잘못된 문자열/key는 UTF-8 표현 불가능한 구조 오류로 먼저 거부한다. 입력을 삭제·치환·정규화하지 않는다. 오류 출력에서만 안전한 이스케이프 표기를 사용하며 정상 emoji와 NFC/NFD 한글 원문은 그대로 보존한다.
