# 재시험·버전 비교·회귀 계획

2026-10-15 · 실제 실행은 하지 않았다. R8/01-A 이후 실행 담당자가 사용할 계획이다.

## 실행 전에 함께 고정할 것

과제/입력 모드·허용 도구/검색 자료·원본/파생/표본 분할과 노출 이력·기준답안/검수 상태·R7-2 적용 항목·정규화/매칭/허용오차·지표/분모·필수 조건·모델/스킬/프롬프트/도구/스키마·환경/의존성·사람 검수 방법·시행/재시도/시간 제한·예산/성공 조건·실패/미완료 처리·중단/자료 제외 규칙을 기록한다. 합격 조건/표본 수·허용오차 등 미정 값은 예비 후 검토받고 잠금 평가 전에 고정한다.

모델의 구체 버전·설정·seed가 제공되면 기록하고 제공되지 않으면 미상으로 남긴다. 같은 이름의 모델/API가 항상 같은 출력을 낸다고 보장하지 않는다. 가용한 입력/도구 요청·응답·산출물·보이는 판단 근거/실행 로그·측정 시간/비용을 보존하되 API키/비밀·모델의 비공개 내부 추론은 수집하지 않는다. 개인정보/회사 자료는 R6 사용범위 안에서 다루고, 접근 제한/마스킹 때문에 재현할 수 없는 부분은 한계로 남긴다.

## 무엇이 바뀌면 얼마나 다시 볼까

| 변경 | 재검토 범위 | 주의 |
|---|---|---|
| 정답/원본/시나리오·시간/좌표 변환 수정 | 영향받은 정답/주장·파생 자료와 관련 지표, 비교 후보 모두 재채점 | 불리한 결과만 지우거나 이전 후보를 구정답으로 남겨 두지 않음. |
| 스킬/프롬프트/지식 검색·모델/도구 변경 | 목표 능력 과제+기존 회귀+관련 보류/부당 비적용/실패/핵심 오류 | 수정된 예시와 같은 원본으로 일반화 개선을 선언하지 않음. |
| 스키마/검사기/출처 또는 회사 참조 버전 변경 | 구조/연결 재검사와 영향받은 내용·사람 판단 재검토 | 기존 receipt/평가 통과의 적용 가능 범위를 확인. 필요한 현재 근거 없이 승계 금지. |
| 평가 규칙·매칭/허용오차/필수항목 변경 | 새 평가 버전으로 양쪽 후보를 같은 조건에서 재평가 | 후하게 바뀐 기준으로 수치만 좋아졌다면 모델 개선과 구분. |
| 실행/환경 장애·시간 초과 | 실패 이력 보존 후 사전 재시도 정책에 따라 별도 시행 | 정상 결과만 골라 원래 시행을 대체하지 않음. |

영향 관계가 불확실하면 그 범위는 더 넓게 다시 본다. 필요한 구조/내용 검수를 못 하면 판단보류와 이유를 남긴다. 필요한 회귀에 실패했는데 다른 새 능력이 좋아졌다는 이유로 상쇄하지 않는다. 변경의 위험/후속 단계에 맞는 필수 회귀 조건은 예비 후 검토에서 정한다.

## baseline·새 버전 비교

같은 과제·허용 입력·자료/기준답안·평가 규칙·모델 설정/도구/예산을 맞춰 같은 원본 묶음에서 비교하고 차이를 명시한다. 스킬만 비교하려면 스킬 유무 외 조건을 맞추고, 모델까지 바꾸면 ‘스킬 하나의 효과’로 해석하지 않는다. 실행마다 새 문맥/분리된 작업 상태를 사용해 이전 답·도구 잔여 파일·캐시가 정답을 주지 않게 한다.

시행 수·재시도 조건·첫 시도/재시도 후 결과·조건별 변동을 계획에 포함한다. 결과가 마음에 들 때까지 반복하거나 최고 결과만 고르는 것을 금지한다. 같은 과제의 여러 시행은 출력 변동이지 새로운 독립 영상 표본이 아니다. 원본 묶음별 결과와 시행별 결과를 구분해 보고한다. 반복 수/통계 방법은 지금 고정하지 않고 예비 자료·변동·비용을 보고 검토한다.

[Anthropic 평가 설명](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)의 task/trial 구분과 능력/회귀·여러 평가자 조합을 참고했다. 한 번 성공과 반복해서 안정적으로 성공은 다른 질문이다. 실제 운영에서 사람 선택·재시도를 허용한다면 그 절차/실패/비용을 포함한 별도 지표를 정의한다. pass@k 등의 숫자를 독립 영상 수나 일상 성공률로 바꾸지 않는다. 이 문서는 해당 지표를 구현/실측하지 않았다.

## 잠금 자료를 본 뒤 고쳤다면

잠금 결과를 보고 프롬프트·검색 지식·정답 정의·허용오차·임계값을 고쳤다면 해당 자료는 노출된 개발/회귀 이력으로 표시한다. 실패 사례를 회귀 자료에 더할 수는 있지만 같은 원본 묶음을 새 잠금 성공으로 세탁하지 않는다. 고정 버전의 최종 확인에는 다른 적합 원본 묶음의 자료가 필요하다. 새 자료가 없으면 노출 자료의 개선/회귀 결과만 보고하며 독립 일반화를 주장하지 않는다.

잠금 자료를 반복 열어 집계 숫자만 보고 튜닝해도 누출 위험이다. ‘정답 파일을 안 봤다’만으로 독립성을 보장하지 않는다. 미리 정한 잠금 평가 계획·접근/열람 로그·평가 예산과 피드백 시점을 지키고 변경을 기록한다. 순차 검정/반복 탐색의 통계적 보정은 설계하지 않았으므로 반복 평가 후 유의한 우월성을 주장하지 않는다.

## 실제 시청/업무 효과는 후속 별도 평가

읽기·청취·이해/오류 과제와 실제 대상/표시·시간 조건을 정하고 baseline/새 방식의 결과를 비교해야 한다. 같은 사람이 같은 영상을 두 번 보면 익숙해져 빨라질 수 있으므로 순서/학습 효과를 관리하고 가능한 비교 과제·순서를 설계한다. 검수/수정·재작업·실패·대기 시간을 포함한 실측을 남긴다. 단순 생성 시간이나 전문가의 미관 선호만으로 시청자 이해/전체 업무시간 개선을 선언하지 않는다. 현재 대상자·실측·동의/권한은 미확보다.
