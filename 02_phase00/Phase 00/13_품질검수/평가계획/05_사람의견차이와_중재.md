# 사람 간 의견 차이와 기준답안 검수

2026-10-15 · 검수 운영 제안. 실제 검수자 배정·독립 답안·중재는 아직 없다.

## 독립 초기 답 → 차이 비교 → 근거 중재

예비 단계에서는 같은 입력·정의·평가 범위를 받은 두 검수자의 독립 초기 답안을 확보하는 방식을 권고한다. 이는 미래 인력 운영 제안이며 현재 두 사람이 배정/동의했다는 뜻이 아니다. 역할·가용 시간·자료 권한은 실제 접수 전에 정한다. 한 사람만 가능하면 단독 검토 초안으로 표시하고 사람 간 신뢰도를 산출했다고 하지 않는다. 두 AI 응답이나 레드팀 에이전트를 두 명의 실제 사람으로 세지 않는다.

1. 원본/대상 버전·허용 입력·항목·정의·필수 여부를 같은 상태로 전달한다. 업무 사실 담당·디자인/모션 검수·시청 대상의 역할을 구분한다.
2. 초기 답안은 상대 답/모델 출력에 맞추지 않고 독립 기록 후 시각·버전을 고정한다. 후보 시스템 평가 시 시스템명을 숨기고 순서 편향도 관리한다. 블라인드가 불가능하면 제한을 기록한다.
3. 차이를 원본 판독/정의·경계/시간축·단위/적용 범위/사전 지식/취향·허용 대안/원문 충돌로 분류한다. 전사 사실과 전달 적합성의 차이를 섞지 않는다.
4. 기준 정의·원본을 다시 보고 해당 업무/기술/디자인 판단을 맡을 사람에게 확인한다. 필요시 제3 검토 역할을 지정하되 단순 다수결로 기술 사실이나 회사 권한을 승인하지 않는다.
5. 합의/근거로 해결한 범위만 새 기준답안 버전으로 남긴다. 유효한 대안이면 복수 허용, 자료 부족/미해결이면 R_U로 유지한다. 판단보류가 적절함을 확인했다면 이유가 있는 R_H로 별도 기록한다.

중재자가 있다는 사실만으로 원본 근거가 생기지 않는다. 기획 의도는 제작자 확인 등 별도 근거가 필요하고, 회사·권한 승인 범위를 디자인 합의로 대체하지 않는다. 사람 회신은 R6처럼 대상·버전·근거·질문과 확인 범위를 보존한다. 실제 사람에게 외부 메시지를 보내는 승인은 이 계획에 포함하지 않는다.

## 합의 정도를 무엇으로 볼까

초기 독립 답안의 공동 판정 가능 수·빠진 판정 수·라벨별 분포·혼동 표·일치 수/분모·불일치 유형·중재 후 변경 수·미해결 수를 먼저 보고한다. 두 사람이 둘 다 판단한 고정 단위에서만 단순 일치율을 계산한다. 미응답/누락은 일치도 불일치도 아니며 평가 가능 쌍의 수와 별도로 공개한다. 명시 보류는 판정 범주이고 누락은 아니다. 서로 다른 변수를 무작정 한 라벨로 합치지 않는다.

원하는 레이아웃·복수 태그·시간 경계·사실 정확성은 같은 척도가 아니다. 미리 단위를 맞추지 못한 사건은 사건 매칭/누락 차이를 먼저 보여준다. 매칭된 사건만의 라벨 일치율을 전체 구간 분할 신뢰도로 부르지 않는다. 시간 경계는 경계 차이 분포와 정의/허용구간을 보고하며 단일 명목 라벨 일치도로 대체하지 않는다.

[Krippendorff 저자 문서](https://www.asc.upenn.edu/sites/default/files/2021-03/Computing%20Krippendorff%27s%20Alpha-Reliability.pdf)의 alpha는 여러 검수자·결측·척도에 관한 선택 근거다. 실제로 사용할 경우 단위·척도·결측 처리·관측 가능 쌍·라벨 분포·선택한 차이 함수와 소프트웨어/버전을 먼저 정한다. 모든 유형에 명목 alpha를 적용하거나0.8 같은 고정 회사 합격선을 도입하지 않는다. 쌍이 없거나 기대 차이 분모가0이면 산출 불가/null과 이유를 남긴다. 작은 표본/편향된 라벨·누락 구조의 한계도 함께 본다. 현재 계수는 계산하지 않았다.

합의 후 수정된 답안으로 ‘초기 일치율100%’를 만들지 않는다. 두 사람이 같은 오답에 동의할 수도 있으므로 높은 일치가 내용의 사실성·회사 승인·시청 효과를 입증하지 않는다. 모델 기반 평가를 쓰게 되면 검수된 사람 판단으로 보정하고 판정자/모델 버전을 기록한다. 모델 판정만으로 기술 사실·사람 검수 대기·권한을 자동 해제하지 않는다.

## 중재 기록에 필요한 것

case_id/version·source_family·원본/허용 입력·항목/정의·각 사람의 역할/실제 응답·초기 답안/해시/시각·비교 가능한 단위·차이 원인·추가 근거·중재자 역할과 이유·해결/복수 대안/미해결·새 기준답안·영향받은 과거 결과·재채점 필요를 보존한다. 사람의 이름만 적힌 파일은 실제 검수 행위나 권한을 증명하지 않는다. 현재는 템플릿만 설계한다.

**가상 예:** 한 검수자는 첫 픽셀의 출현을 등장 시작으로, 다른 사람은 문구를 식별할 수 있는 시점을 시작으로 삼았다면 원본 이징을 탓하기 전에 사건 정의 차이를 기록한다. 정의를 보정하면 기준답안 버전을 바꾸고 양쪽 후보 결과 모두 같은 정의로 다시 비교한다. 다른 구도가 모두 메시지를 보존한다면 하나를 강제 정답으로 만들지 않는다.
