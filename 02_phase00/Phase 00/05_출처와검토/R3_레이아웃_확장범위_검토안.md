# 레이아웃 14개 밖의 구조를 다루는 범위

기존14개는 화면을 기록하기 위한 프로젝트 분류다. 표·순환·조건 분기처럼 실무에 유용하지만 별도 명칭이 없는 구조도 있다. 그림이 비슷하다는 이유로 표를 카드 그룹, 순환을 선형 프로세스라고 강제로 기록하면 의미가 달라진다.

| 선택 | 이번 구축 범위 | 영향 |
|---|---|---|
| A · 14개 유지 + 확장 후보 별도 관리 (추천) | 14개 판단 기준을 마무리하고 표·순환·분기 등의 적용 예·반례를 지식 후보로 보존. 기존 명칭이 실제로 맞는 경우만 기존ID로 연결, 맞지 않으면 미분류/후보 유지 | 기존R2 계약을 보존하며 부족한 범위를 드러낸다. 새 분류ID·회사 규칙은 자동 생성하지 않음 |
| B · 분류 명칭도 지금 확장 | 표·순환·조건분기에 새ID·정의·판정예·기록계약을 추가하고R2 회귀까지 재검토 | 상세 검색에는 유리하지만R2/조회/검증/인계 개정 범위가 늘어남 |
| C · 14개만 이번 범위 | 14개 심화와 화면비·문구 스트레스 예까지만 마무리. 새 구조는 후속 목록으로 남김 | 범위가 가장 작으나 표·순환·분기 선택 지식은 후속 검토 필요 |
| D · 실제 자료 확보 후 확장 | 14개 초안을 유지하고 새 구조는 실제회사영상 빈도를 확인한 뒤 구축 | 회사 문법에 더 맞출 수 있으나 현재실영상이 없어 후속 단계까지 대기 |

추천은A다. 후보로 지식을 보존하는 것과 정본 분류를 늘리는 것은 다르다. 같은 정보의 가로·세로·정사각 변형과 한국어·숫자 검수는 어느 선택이든 기존14개 안에서 진행한다. 선택 전에는 새 구조의 별도분류ID를 만들지 않는다.


## 사용자 결정

A를 선택했다. 기존14개ID·정의는유지하고표·순환·조건분기3개지원지식후보를별도보존한다. 새분류ID·회사규칙승인은없다.
