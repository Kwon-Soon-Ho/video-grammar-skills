# R4-4 기존 기록 이관 정책 — 사용자 검토안

2026-10-15. **사용자가 A안을 선택했다.** 아래 비교는 선택 당시 검토 기록이다. 새 시간·근거·좌표 규격은 원본 영상 ID/버전/hash와 명확한 대상·시간·파생 연결을 요구한다. 구형 설명용 기록은 이 정보가 부족하다. 부족한 값을 임의로 채우지 않는 원칙은 유지하며, **얼마나 엄격히 현행 DB와 분리할지**를 선택한다. 아래는 구현 전 비교안이다.

| 안 | 처리 방식 | 장점과 부담 |
|---|---|---|
| **A. 새 통합 규격을 기본으로, 미완 기록은 접수함에 보존 — 추천** | 새 기본은 v0.2 후보. 필요한 정보와 연결이 갖춰진 기록만 통합 초안으로 이관. 부족하면 원문·누락 보고를 별도 접수함에 보존하고 분석/회사 문법 검색에서 제외. | DB 의미가 선명하다. 기존 설명용 예시는 계획자료로 보존하고, 통합 동작은 별도 합성 예시로 보여줘야 한다. |
| B. 당분간 구형을 기본으로 두고 새 규격을 병행 | 기존 스킬의 구형 입력 흐름을 우선 유지하고 새 통합 검사·기록은 별도 경로에서 사용. 기본 전환은 R8 재평가 때 한다. | 기존 호출부 변화가 적다. 두 경로의 차이를 관리해야 하며 기본 DB 통합 완료는 전환 전까지 유보된다. |
| C. 부족한 기록도 한 DB의 ‘부분 초안’으로 수용 | 누락 identity와 아직 연결 못 한 내용을 허용하는 별도 부분 초안 구조를 새 통합 규격 안에 추가. 정식 분석 기록과 상태별 조회를 강제 분리. | 한곳에서 자료를 찾기 쉽다. 엄격한 세 계약 바깥의 부분 초안 경로와 오용 방지 검사도 설계해야 하므로 범위가 커진다. |
| D. 구형 기록의 자동 이관 없이 건별 사람 확인 | 새 통합 규격·검사기는 구축하되 기존 기록의 실제 이관은 사람이 원본·누락값을 확인한 건부터 수동으로 진행. | 사람 확인을 먼저 받을 수 있다. 자동 이관 도구보다 점검표·작업 지시 위주이며 초기 이관 속도는 느리다. |

**추천 A의 현재 자료에 대한 결과:** 설명용 정본은 실제 영상 근거로 바꾸지 않고 원문과 설계 아이디어를 보존한다. 스킬 시험 입력·과거 평가 산출물은 과거 검증 자료로 그대로 유지한다. 새 통합 예시는 합성임을 명확히 표시해 별도로 만든다. 실제 영상 준비가 없어도 규격·이관 도구·반례 검수는 진행할 수 있다.

어느 안도 영상 hash를 JSON hash로 대체하거나, 파일 이름에서 회사/영상 버전·시간·화면 상태를 추정하지 않는다. 관측·계획·추정과 사람 내용 검수는 구분한다. 회사 정본·과거 평가 원문 삭제/외부 배포/01-A 분석 구현을 포함하지 않는다.
