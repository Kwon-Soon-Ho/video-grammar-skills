# 사람 검수 답변을 기록하는 방식 — 4안 비교

2026-10-15. **사용자 A 확정(2026-10-15).** 구체적 대상·버전·근거·판단범위를 제시한 대화의 사람답변을 수동접수하고 확인범위만 기록한다. 아래4안은 당시 비교이력이다. 기존 draft권한·스킬3개·R5 관측색 정책을 다시 승인받는 질문이 아니다. R6에서 앞으로 개별 내용검수 답변을 어떤 절차/근거로 기록할지 정한다.

| 안 | 접수 방식 | 영향 |
|---|---|---|
| A (추천) | 이 대화에서 대상·버전·근거·판단범위가 특정된 사람 답변을 접수하고 확인한 범위만 기록. 회사/사용권한 승인은 별도 근거 | 지금 협업에 맞고 작은 검수부터 가능. 단순 ‘A로 진행’ 같은 작업정책 답변은 내용검수로 쓰지 않음 |
| B | 개별 검수서에 필수 항목을 채운 자료로만 접수. 대화 답변은 메모 | 문서 관리가 명확하지만 짧은 확인도 검수서 작성 필요 |
| C | 대화·문서 모두 미확인 선언으로 우선 접수하고 두 번째 사람 확인 뒤 검수결정으로 활용 | 확인 절차가 더 강하지만 담당자/회차 부담 증가 |
| D | 검수자와 담당 권한명단·등록절차를 먼저 정하고 등록된 검수자의 기록만 접수 | 조직 운영에 맞출 수 있으나 명단/권한 근거가 없는 현재는 준비가 더 필요 |

모든 안에서 실제 사람 신원 인증·회사 직무 권한/권리 보증·디지털서명을 구현한 것처럼 표시하지 않는다. 기록의 hash와 reviewer 이름이 실제 검수행위/권한을 증명하지 않는다. 담당자가 확인할 수 없는 내용은 추가자료 필요/기권/대기 상태로 남긴다.

A가 선택돼도 파일 안의 reviewer=human 또는 채팅ID 문자열만으로 자동 신뢰하지 않는다. 사용자의 실제 답변 문맥을 대조하는 수동접수 절차와 원문/범위 이력을 남기고, 기계 검사는 연결·버전·모순을 검사하는 범위에 둔다. 실제 검수답변이 없으면 내용/회사 승인 기록은0건 그대로다.
