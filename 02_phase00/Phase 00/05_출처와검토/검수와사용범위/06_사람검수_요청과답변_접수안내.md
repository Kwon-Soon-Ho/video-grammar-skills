# R6-3 사람 검수 답변 접수 안내

2026-10-15. 사용자 A: **이 대화의 구체적인 대상 답변을 수동 접수하고 확인한 범위만 기록한다.** 회사·사용권한 승인은 별도 근거다. 사용자 작업정책 선택은 개별 내용 검수로 재사용하지 않는다.

## 현재 물을 것과 아직 물을 수 없는 것

| 대상 | 상태 | 이유 |
|---|---|---|
| 8회사 CI 최신 자료·가이드 확인 상태 | 최신 자료8회사 사용자 확인 / 추가 가이드 범위 미확인 | 실제 회신1건 접수. 산하 AI원본 부재도 사용자 확인. 회사/사용권한 승인으로 확대하지 않음 |
| 삼안 선언후보4개의 공식 화면값/변환 조건 | 추가자료 필요 | 가이드·프로필 등 없이 공식 sRGB값으로 확정하지 않음 |
| 외부 스킬 직접 채택 파일/행위의 조건 | 채택 시 검토 | 실제 직접 복사/실행을 선택하지 않았음. 현재 정적 검토·실행 보류 유지 |
| 실제 영상 내용·측정·기획 의도 | 원자료 필요 | 실제 영상/시나리오/주장 근거가 없음. 합성 예시를 실제 사람 검수로 바꾸지 않음 |

## 접수 순서

1. 요청ID·버전, 대상과 근거의 파일/버전/hash/선택부분, 포함·제외 범위, 질문과 4개 선택지/추천을 고정한다.
2. 대상이 바뀌면 답변 전에 요청 버전을 바꿔 재질문한다. 자료 없음은 needs_material, 아직 채택 전은 not_due다. unknown을 비적용으로 바꾸지 않는다.
3. 사용자의 실제 답변을 이 대화에서 확인한 뒤 원문과 접수 문맥을 수동 대조한다. `raw_reply`와 대화 위치 설명·접수일·기록자를 남긴다. JSON 안의 human/이름/대화ID만으로 실제 답변이 발생했다고 인증할 수 없다.
4. 답변은 `limited_statement` / `needs_material` / `unable_to_determine` / `disagrees` / `not_applicable`로 범위를 제한해 남긴다. 확인한 범위/제외 범위와 partial/full을 기록한다. 기권·자료 필요·미답변은 승인으로 바꾸지 않는다.
5. 답변 원기록은 덮어쓰지 않고 correction/withdrawal 이벤트로 이전 이벤트를 가리킨다. 날짜 역행은 거절한다. 다른 요청·이전 버전·오래된 근거/권한 문맥의 답변을 재사용하지 않는다. 검수 문맥에는 전체 고정 입력 hash를 포함한다. 대상/근거를 개정할 때는 과거 대장 전체와 입력을 backup에 고정하고 새 문맥 대장을 만든다. 현재 검사기는 다른 문맥의 옛 이벤트를 한 현대장에 섞어 역사조회하지 않는다. 이전 파일은 별도 snapshot 조회용이고 현재 판정에 재사용하지 않는다.
6. 새 회사 승인/사용권한을 이 답변 규격에 넣지 않는다. 담당 권한과 승인 문서는 별도로 확인해야 하며 이 규격은 조직 승인 시스템·법적 판정·전자서명을 구현하지 않는다.

## 적용 예와 반례

- **적용**: 사용자가 ‘한맥기술만 최신 가이드 확인, 나머지는 미확인’이라고 답하면 해당 회사/범위만 partial 선언으로 남기고 다른 회사는 검수 대기를 유지한다. **반례**: 같은 모음 AI에 들어 있으므로8회사를 모두 승인한 것으로 기록한다.
- **적용**: 원문 CI 또는 대상 질문이 바뀌면 이전 답변은 과거 이력으로 보존하고 새 문맥에서 재확인한다. **반례**: 대상ID/파일명이 같다고 예전 검수를 재사용한다.
- **적용**: 담당자가 확인하기 어렵다고 답하면 기권/추가자료 필요로 남긴다. **반례**: 대답이 없거나 기권했다고 문제 없음으로 처리한다.
- **적용**: 승인 가능한 역할/근거를 별도로 확인한다. **반례**: ‘내가 확인함’ 또는 reviewer=human으로 회사 승인·외부 API 업로드 권한을 생성한다.
- **적용**: 합성 시험 이벤트는 spec_test 사본에서만 검사하고 실제 답변 수에는 더하지 않는다. **반례**: 시험용 사람 역할 이름을 실제 검수 대장에 옮긴다.

## 도구의 경계

검사기는 필수 필드·연결/현재 입력·요청/문맥 해시·정정/철회 순서를 검사한다. 실제 답변 발생·사람 신원·내용의 참/거짓·담당 권한은 인증하지 않는다. 모든 통과에도 identity_authenticated / content_verified / company_approved / permission_granted / operational_release는 false다. `declared_answer_recorded`는 대화에서 수동 접수한 선언이며 승인된 사실/권한으로 표시하지 않는다. 사용자 A선택은 업무 절차에만 반영한다.

각 질문은 coverage_units로 대상별 확인 범위를 나눈다. 첫 CI질문은 최신 자료8/사용 가이드8의16단위다. 이벤트에서 covered/unresolved/not_applicable ID를 겹침 없이 전체 분할하고 unresolved가 있으면 partial·사람 후속 확인을 유지한다. 자연어 속 ‘일부 확인’을 기계가 진실로 판정하지는 않는다. spec_test는 이벤트의 origin/provenance에도 표시해 실제 대장으로 단순 복사되지 않게 구분한다. 이 표식을 모두 위조하는 행위의 신원 인증을 구현한 것은 아니다.

한맥 디자인 시스템은 기존 정본과 참조 대화 원본의 해시가 동일함을 확인했다. [한맥 대화 근거](한맥디자인_대화근거.json)와 [작업정책17건](작업정책_연결목록.json)에 브랜드·명암 Storybook/강조·중립 Vercel/UI선택참고 결정을 연결했다. 이번에 현재 웹을 재조사하거나 새 공식 CI·회사 승인으로 승격한 것은 아니다. 원정본·R4/R5 규격·스킬은 변경하지 않았다.

실제 답변1건의 포함/제외 범위와 한맥 디자인 정본 연결은 [확인 현황](07_한맥디자인과_CI_확인현황.md)을 따른다. 최신 자료 확인과 한맥 공통 컬러·선택UI 참고가 이미 확보됐다는 점을 유지한다. usage_guide의 잔여 범위는 CI 보호공간/최소크기/허용형 등 아직 자료에 없는 세부사항이며 한맥 디자인 시스템 전체가 미확보라는 뜻이 아니다.

실제 답변에는 원문 회신의 별도 JSON과 질문 제시 당시 snapshot/내용hash를 연결한다. 후속 연결 문맥 전체를 사용자가 검수한 것으로 간주하지 않는다. 철회된 답변은 이력을 보존하되 현재 covered 목록에서 빼고 재검수 상태로 반환한다. 실제 답변 수는 역사상 접수 수이며 active_declared_answer_count로 현재 유효한 선언 수를 따로 본다.
