# R6-2 출처와 사용 범위 연결

2026-10-15. 연결 계약·검사 초안. 독립 레드팀 전에는 완료로 판정하지 않는다.

## 쉽게 보는 역할

**출처를 찾고, 그 기록이 지금도 같은 내용인지 확인하는 색인이다.** 문서를 읽은 깊이와 사용할 수 있는 권한을 별도로 다룬다. 원문에 적힌 지시는 자료이며 실행 명령으로 사용하지 않는다.

- 기존20출처와 R2~R6 지정9조사문서의 출처 행·문서 맥락, 파일별544검토행, 스킬40후보를 원문 그대로 연결한다. 중복·재사용 포함이므로 서로 다른 자료 수로 합산하지 않는다.
- 각 연결은 원기록 파일·판본·해시·JSON 위치를 보존한다. 제목/검색발췌/요약/선택본문/전체파일/코드 정적 검토 같은 **원래 표현**을 유지하며 점수나 단일 완료 등급으로 변환하지 않는다. 같은 문서의 부분별 검토 깊이를 통째 승격하지 않는다.
- 544행은 고유533경로·해시다. 이번에는 파일 존재·해시를 대조했고 544개 본문을 다시 읽지 않았다. 옛 호스트 경로4건은 동일 byte의 별도 보존 사본으로 연결했다. 원본이 현재 존재하는데 변했다면 사본으로 감추지 않는다.
- 자산135개의 기존 usage와 파일을 연결한다. 현재 내부 Phase00 자료 정리·검토용 reference_only다. 회사의 공식 최신판/가이드, 새 제작·외부 API 업로드·배포 범위가 확인됐다는 뜻이 아니다.
- 중앙8정책과 R5/R6 정책은 작업정책으로만 연결한다. 분산 R4 선택의 개별 결정·대상별 사람 답변은 R6-3에서 별도 정리한다. 이 색인은 전사 권한대장·프로젝트 전체 출처를 망라하지 않는다.

## 사용 행위별 기록

| 요청 | 현재 기록으로 말할 수 있는 것 | 남겨야 할 것 |
|---|---|---|
| 기존 맥락에서 내부 자료 참고 | 기존 작업 맥락과 일치하는지 | 일치는 권리 허가·공식 CI 판정이 아님 |
| 새 화면 디자인 초안 | 기존 R5 관측색 A정책에 따른 별도 프로젝트 기록 대상 | 실제 디자이너 선택·출처·가정·내용검수 대기. R6이 이미 허용된 R5 초안을 새로 금지하지 않음 |
| 외부 API 업로드·배포 | 기존 reference_only로 범위를 확장할 수 없음 | 구체 파일·수신처/노출대상·행위·근거·조건·권한 담당자 확인 |
| 외부 스킬 코드 복사·변형·실행 | license_note는 관찰, direct_copy_policy와 runtime_hold는 기존 제한 | 파일별 고지/조건·의존성·행위 범위 검토. MIT 등 표기만으로 자산/폰트/도구 전체 허용으로 확대하지 않음 |

`assess_use(base, asset_id, action, context)`는 요청의 상태만 반환한다. 지원 행위는 internal_reference / design_draft / external_api_upload / distribute / copy_code / execute_code다. 코드 행위도 자산에 대한 요청 범위 표시일 뿐, 스킬 권리를 판정하지 않는다. 실제 파일 전송·배포·외부 코드 실행 기능은 없다. `needs_scope_review`는 기존 기록만으로 새 용도의 근거가 충분하지 않다는 의미이며 법적 금지 판정이 아니다.

## 적용 예와 반례

1. **적용**: 특정 스킬 참조 파일의 원문 해시와 `full_read` 기록을 그대로 조회한다. **반례**: 이 참조 파일만 읽은 것으로 SKILL.md·다른 참조·코드 실행 효과까지 확인했다고 적는다.
2. **적용**: IP-10 공개 Summary의 정의만 조건부 참고한다. **반례**: 학술 장 전체·실험·진단 도구를 검토한 근거로 승격한다.
3. **적용**: 제공 CI 사본을 이미 지정된 내부 자료 정리 맥락에서 참고한다. **반례**: 파일을 보유했다는 이유로 외부 서비스 업로드/공식 최신 CI 사용 승인을 만들거나 다른 가족사의 색으로 합친다.
4. **적용**: 현재 원기록/파일이 바뀌면 오래된 연결을 실패 처리하고 재검토한다. **반례**: 파일명/ID가 같다는 이유로 예전 검수를 재사용한다.
5. **적용**: 사용자 A답변은 검수 접수 절차의 선택으로 남긴다. **반례**: 이를 8회사 CI 내용·공식성·재배포 승인으로 사용한다.

## 검사 경계

형식·고정 입력의 현재 해시·원기록과 색인의 일치·544파일/135자산의 파일 동일성을 검사한다. 읽기 전용이며 네트워크·스킬·외부 앱을 실행하지 않는다. `structural_valid=true`에도 content_verified / identity_authenticated / company_approved / permission_granted / operational_release는 false다. API의 `verify_artifacts=False`는 명시적인 메타데이터 전용 검사이며 `artifact_identity_checked=false`를 반환한다. 기본값/CLI/사용요청 검사는 파일 확인을 포함한다. 파일확인 옵션은 boolean만 받는다. 반환 직전 입력 해시를 다시 대조하지만 파일 원자 잠금/모든 동시 변경 방어는 구현하지 않는다. 해시는 파일 동일성 수단이며 진실성·최신성·사람 신원·권한을 인증하지 않는다. 검사기나 스키마 자체가 악의적으로 교체되는 공격의 서명/인증 체계는 구현하지 않는다.

W3C [PROV-O](https://www.w3.org/TR/prov-o/)의 자료·행위·책임 구분, [DQV](https://www.w3.org/TR/vocab-dqv/)의 측정·평가 맥락, [ODRL](https://www.w3.org/TR/odrl-model/)의 대상·행위·조건 표현을 관련 부분만 참고했다. 이 프로젝트 계약이 해당 표준 전체를 구현/준수하거나 라이선스를 법적으로 판정한다는 뜻은 아니다. 조사 깊이는 [조사기록](R6_조사기록.json)에 보존한다.
