# 원문·참조 — 선별과 조건

각 항목은 이식 설계안이다. 모든 외부 명령을 수행하거나 회사 필수값으로 등록하지 않는다. 관측·저자 휴리스틱·자체 적용 해석·추정·미확정을 구분한다.



## Taste / design-taste-frontend

기본 카드·중앙 스택을 반복하는 이유를 되묻고 내용에서 구조를 도출하는 절차 검토

선별 후보: 실제 입력·대상·정보 목적을 먼저 확인 / 주장과 근거를 연결 / 자체 의도보다 보이는 결과를 검토 / 대체안의 정보 적합성을 설명

제외·수정: 8~12개의 고유 소재 의무·무작위 방향 강제 / 4사진·8움직임의 최저 수량과 Awwwards 점수 캡 / 두 줄·32영문자·웹px·폰트 수·선·번호·특정 색·동일 모듈 일괄 금지

적용 예: 기술 원리를 설명할 때 먼저 입력 근거와 관계를 정리하고, 개념도/단면 중 무엇이 맞는지 이유를 기록한다.

반례: 7개 절차를 단계 번호 없이 장식 사진 4개와 움직임 8개로 바꾸면 과정과 읽기 시간이 손상된다.

미검증: 웹 갤러리의 저자 보고·모델 평가; 회사 영상·한국어·사람 대상 효과 미검증 / library 레코드는 전수 의미 검토/영상 후보 등록을 하지 않음



## Redesign / redesign-existing-projects

같은 저장소 안의 상충 규칙과 수정 권한 검토

선별 후보: 기존 기능·브랜드·값 보존 / 실제 줄바꿈·정렬·원문 전달 확인 / 국소 변경 범위 명시

제외·수정: 숫자·날짜를 자연스럽게 보이도록 임의 변경 / 회사 글꼴을 취향으로 교체 / 항상 grain·glass·spring·smooth scroll 추가 / 주 Taste의 flat/무그라데이션 규칙과 병용 강제

적용 예: 회사명이 긴 비교 표를 현재 회사 글꼴로 재배치하는 수정 제안만 한다.

반례: 47.2%처럼 그럴듯한 값을 만들거나 블로그 날짜를 무작위로 바꾸는 조항은 실제 회사 자료 정리에 사용할 수 없다.

미검증: 원문 두 스킬의 표면·모션·레이아웃 규칙은 서로 상충하므로 패키지 전체를 단일 기준으로 채택할 수 없음



## Impeccable 선택 참조

레이아웃·타이포·정보 이해 목적과 감각 판단/기계 검사 분리

선별 후보: layout: 관계·읽기 순서·그룹·밀도·반복의 목적 / typeset: 역할·실제 언어·내용 극단·대체 글꼴 / operate: 친숙함과 일관성 / critique: 구체 근거·우선순위·해당 없는 항목 분리

제외·수정: 런처 자동 다운로드·hooks·doctor·live 주입 / new-work 창작/방향 경쟁/이미지/컴포넌트 구현 / 정본 DESIGN 교체·자동 추출/마이그레이션 / 항상 4항목 이하·시선효과 보증·웹 수치 강제

적용 예: 같은 조건의 공법 두 개를 같은 구조로 비교하는 반복은 인정하고, 라벨과 척도·언어 가독성만 검토한다.

반례: 반복이 뻔하다는 이유로 비교 두 화면의 구조를 다르게 만들면 비교가 어려워진다. 과업 UI의 200ms를 설명 화면의 읽기 시간으로 쓰지 않는다.

미검증: 모든 명령·호출 가지·엔진 바이너리/이미지 생성/폰트 전수 검토 미완료 / 선택 참조의 native/live/new-work 연결은 제외된 경로로 기록
