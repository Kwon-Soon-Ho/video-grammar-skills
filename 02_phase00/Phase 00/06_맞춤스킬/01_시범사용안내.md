# 소량 DB 정리 시범 사용

2026-10-14 사용자 A안 확정. 세 스킬의 목적과 draft 권한은 유지한다. 이 결정은 회사 규칙 승인이나 실영상 성능 승인과 다르다.

## 한 번의 작업 순서

1. 대상과 요청을 좁힌다. 처음에는 용어·지식 몇 개 또는 기록 한 건으로 시작한다. 대상 ID·정본 버전·출처·한맥 프로필을 읽는다.
2. 작업 ID와 로그를 만든다. 요청·사용 스킬·대상 파일/ID·입력 버전·해시·시각을 기록한다. 해당 SKILL.md 절대 경로를 명시해 읽는다.
3. 변경 전 backup/날짜_작업ID에 대상 파일을 보존하고 원본과 해시가 일치하는지 확인한다. 검토만 수행한 경우는 '정본 변경 없음'을 기록한다.
4. 요청한 정리만 draft로 처리한다. 원문 근거·프로젝트 해석·미확정 값을 분리한다. 의미 병합·회사 필수화·승인은 검토 제안으로 남긴다.
5. 해당 파일의 구조·ID·출처·버전·한맥 참조를 검증한다. 명령·종료코드·원시 stdout/stderr·오류와 변경 diff를 저장한다. 검사 실패는 실패로 기록하고 원문에 없는 값을 채워 통과시키지 않는다.
6. 내부 레드팀 관점에서 잘못된 병합·숫자 발명·승인 승격·01-A 범위 침범·불필요한 규칙 강제를 점검한다. 결과·보완·보류·정본 변경 여부를 보고한다.

기록은 08_검증결과/시범사용 아래 남긴다. 요청 범위의 draft 정리에 반복 승인을 받지 않는다. 의미·필수화·목적 판단이 필요한 경우에만 최소 4지선다와 추천안으로 검토한다.
