# R8-4 — 독립 확인을 세 묶음으로 진행

2026-10-15 · 착수. 세 후보는 그대로 고정하고 아직 기본 사용 위치를 바꾸지 않는다.

## 1. 새 요청과 현재 문맥

큐레이터는 새 개념·같은 ID의 여러 판본·없는 근거를 구별하는지, 기록 관리자는 모순 없는 기록을 불필요하게 고치지 않는지, 적용성 검토자는 정상 표현을 유지하면서 인용문이 실제로 지지하지 않는 주장·다른 판본의 사람 회신만 보류하는지 확인한다. 기존 개발 사례와 다른 합성 자료를 사용한다. 후보 확인 시험이며 기존 대비 개선량을 측정하는 실험은 아니다.

원래 R6/R7 고정 문맥은 별도 읽기 감사한다. 평가/재구성 문단이 들어 있는 원본 전체를 수행자에게 주면서 '답안 분리'라고 하지 않는다. 역할 수행 사본과 고정 문맥 감사는 다르며, 제외·변환·원본/사본 해시를 남긴다.

## 2. 실제 파일 쓰기와 실패

실험 사본에서만 실제 초안 수정·백업·저장 후 검사 실패·여러 파일 일부 저장·외부 수정 개입·복구 불가를 나눈다. 도구가 실패를 반환했을 때 원문을 복구했는지 또는 타인 바이트를 보존하고 미복구로 보고했는지 본다. 후보 지침의 실제 행동과 시험 도구 자체의 결정론 검사는 별도로 보고한다. 주입한 실패가 실행되지 않으면 미시험이다.

외부 명령의 인수·종료·stdout과 도구의 작업 전후 해시는 기록하되 전체 OS 이벤트·모델 생각·모든 임시 쓰기를 수집했다고 주장하지 않는다. 시간/token 미제공은 null이다. 실제 운영 D 파일에는 실패를 주입하지 않는다.

## 3. 스킬 사이의 전달과 전환 판단

큐레이터 → 기록 관리자 → 적용성 검토자로 넘길 때 대상/버전/해시·근거·설명용 상태·미해결·사람 검수 범위가 유지되는지 각각 새 수행자로 확인한다. 한 수행자가 세 스킬을 동시에 읽어 역할 효과를 섞지 않는다. 앞 단계 산출물을 본 다음 단계 시험은 독립 효과 시험이 아닌 실제 순차 인계 확인이다.

R8-1/2 뷰어의 원래 과제 표시도 확인하고 결함이면 원본과 이력을 보존한 별도 정정본을 만든다. 이전 R7 pin은 유지한다. 후보 기본 사용 위치·새 R8 조회 문맥은 실제 결과를 보여준 뒤 최소4안과 추천안으로 검토받는다. 자동 전환·전역 설치·실영상 성능/회사 승인·Phase00 완료 선언은 하지 않는다.

## 검토와 보완 순서

각 묶음은 시험 전 기대항목 고정 → 실제 실행 → 독립 채점/레드팀 → 발견 보존·필요 보완 → 결과 보고로 진행한다. 실패 뒤 같은 사례 재시험은 보완/회귀 시험으로 표기하고 새 미사용 시험이라고 부르지 않는다. 내용 판단이 필요한 실제 대상은 구체 질문으로 사람에게 남긴다.
