# R8-4에서 반드시 보완할 독립 확인

2026-10-15 · 계획만 정리했다. R8-4는 아직 시작하지 않았다. 이 문서를 시험 통과나 후보 채택으로 해석하지 않는다.

R8-1 세 개발 과제에서는 구·신이 모두 같은 조건을 충족했다. 지정 작업 참조에 R8 평가설계 문단이 포함돼 신 사례1이 읽었고, 기준은 최초 실행 시작 뒤 작성했다. 공통DB가 답을 구체적으로 제공하므로 이 결과만으로 새 스킬의 독자효과·일반화를 판단하지 않는다. 동작/파일 보존 관찰과 사람 피드백용 결과로 보존한다.

## 확인 전에 준비할 것

1. 수행용 사본에서 평가 문단을 분리한다. 정본은 삭제·재고정하지 않는다. 시험 전 사본 변환 목록과 원본/사본 SHA·누락/대체 근거를 기록하고 양쪽 조건이 같은지 확인한다.
2. 미사용 요청·자료와 기대항목/판정 경계를 실행 전에 고정한다. 부모 근거가 여러 파일에 연결돼도 되는지, 사람 질문의 대상·판본·범위가 어디에 있어야 하는지 명시한다. 이름 붙인 두 스킬을 동시에 로드하지 않는다.
3. 답이 DB에 이미 있는 정상 검색 외, 답 없는 새 개념/근거 부재·실제 오인용/부분 충돌·복수 같은 ID와 판본·과거 등록 바이트가 있는 경우를 포함한다. 허위 근거가 존재하는 경로/SHA만 맞춰 통과하지 않도록 내용과 연결을 함께 확인한다.
4. 담당 역할에 맞는 실제 쓰기·backup 실패와 복구 사례를 포함한다. 테스트용 사본만 이용하고 실패 결과·허용 변경·원상복구 바이트를 보존한다. 큐레이터에게 통합 영상 기록 수리 등 다른 역할의 과제를 억지로 수행시키지 않는다.
5. 외부 관측 가능한 명령/종료코드·stdout/변경 이력 수집 범위를 미리 정한다. 수집하지 못한 과정·시간/token은 미수집으로 남긴다. 최종 해시 대조만으로 실행 중 일시 변경 후 원복 부재까지 인증하지 않는다.

실제 영상 분석·회사 문법 승인·납품 품질 수치·01-A 구현은 이 확인의 범위가 아니다. 실제 영상 평가의 표본/정답·예비 보정과 잠금 확인은 R7/01-A 후속 계획을 따른다. R8 전체를 마치기 전에 이 보완의 실행 결과와 사람 피드백을 별도로 검토한다.

## R8-2에서 추가로 확인할 잔여

기록·한맥 연결 관리자의 개발시험에서는 정상 수정, 지정 backup 경로 충돌, 명시 checkpoint 복구와 구형 읽기검사를 확인했다. 실제 저장 후 검사 실패가 난 자동 rollback, 여러 파일 중 일부만 저장된 실패, backup 뒤 외부 변경과 복구 실패 분기는 아직 실행 검증하지 않았다. R8-4의 별도 미사용 사례에 포함한다. R6/R7 완전 현재 문맥·스킬 간 전달도 수행 자료와 평가 설계를 분리한 경계에서 별도로 확인해야 한다.

연결 메타데이터 변경도 각 소유 기록의 새 판본이 필요하다는 R1 규칙을 반례에 포함한다. 초기 판본 누락과 보완 후 결과는 [R8-2 보고](../08_검증결과/R8_02_기록관리자/00_결과안내.md)에 보존했다. 이 항목은 계획 추가이며 R8-4 완료가 아니다.


## R8-3에서 남긴 확인 범위

적용성 검토자는 이번에 입력 읽기와 검토 보고만 수행했다. 새 미사용 정상 후보/국소 보류, hash가 일치해도 인용문이 주장을 지지하지 않는 경우, 대상/판본이 달라진 회신 재사용을 추가 확인한다. 지식 draft 실제 수정/저장 실패 복구 기능을 채택 범위에 둘 때에는 그 실제 쓰기·실패 분기도 별도 실행 검증한다. 전체 R6/R7 현재 문맥·스킬 간 전달·기본 전환 검토는 여전히 남아 있다. R8-1/2 기존 뷰어도 원래 과제 표시와 출력 원문의 대응을 통합 검수한다.

이는 계획 추가이며 R8-4 실행/통과가 아니다. [R8-3 보고](../08_검증결과/R8_03_적용성검토자/00_결과안내.md)의 개발 사례를 새 미사용 자료로 부르지 않는다.
