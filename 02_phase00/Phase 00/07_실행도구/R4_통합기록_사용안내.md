# 현재 기록 검사와 구형 호환 안내

2026-10-15. 기본 기록 규격은 **v0.2 통합 최소 기록**이다. 기본 도구 전환·자체/독립 검수를 마쳤다. 기록 계약 범위의 완료이며 실제 내용/회사 승인과 구분한다.

| 경로 | 용도 |
|---|---|
| 자료검증.py | 현재 기본. v0.2는 통합 구조/연결 검사, v0.1은 needs_migration·valid=false |
| 통합기록_규격검사.py | v0.2의 4단위·분류·시간·근거·좌표·실행/검수 context 검사 |
| 기록접수.py | 사용자 A의 구형 원문·누락 보고 copy-only 보존. 읽기 검사와 분리된 명시 작업 |
| 구형기록_보존검사.py | 구형 형태의 역사 진단. 새 DB 통과나 회사 승인에 사용 금지 |
| 반례검사.py / 최종반례검사.py | 같은 통합 회귀를 실행하는 진입점 별칭. 독립 시험으로 중복 합산하지 않음 |
| 구형_v0.1_반례검사.py / 구형_v0.1_최종반례검사.py | 과거 기대값·보존 진단용. 현재 지식 정책/통합 규격의 종료 근거가 아님 |

프로젝트의 .환경/Scripts/python.exe를 사용한다. 신규 패키지/영상 도구를 설치하지 않았다. jsonschema와 그 기존 의존성 referencing을 사용해 현재 기본 스키마의 URN 참조를 로컬에서 등록한다. 검사를 위해 원격 스키마/웹/API에 접속하지 않는다.

```powershell
# 현재 합성 설명 예시의 구조만 검사
& '.\.환경\Scripts\python.exe' -B '.\07_실행도구\자료검증.py'

# 새 기록 검사
& '.\.환경\Scripts\python.exe' -B '.\07_실행도구\자료검증.py' --record '<v0.2 기록 경로>'

# 구형 원문 접수 — 위의 읽기 검사와 별도 명시 작업
& '.\.환경\Scripts\python.exe' -B '.\07_실행도구\기록접수.py' --source '<Phase 00 안의 구형 JSON 경로>' --role '자료 역할'
```

CLI 종료코드 0은 v0.2 구조 통과, 2는 구형 이관 대기, 1은 구조/입력 오류다. unresolved·사람 검수 대기·회사/운영 승인과는 별개다. 기존 validate_record(data)의 list 반환도 유지하되 구형은 오류/이관 대기 목록을 반환한다. 빈 목록은 구조 오류가 없다는 뜻이며, 검수/회사 승인이 아니다. 상세 상태는 inspect_record/inspect_file 결과를 사용한다.

--output은 Phase 00/08_검증결과 안에만 저장한다. 같은 결과는 보존하고 다른 내용은 hash 접미어의 새 파일에 저장한다. 원문/과거 결과를 덮어쓰지 않는다. CLI 출력의 saved_result_path에서 실제 결과 위치를 확인한다. 기본 검사 자체는 구형 자료를 접수하거나 원문을 수정하지 않는다.

최소기록_스키마.json은 현재 v0.2 정본을 가리키는 로컬 참조 진입점이다. 정본은 통합최소기록_스키마_v0.2.json이다. 구형 스키마는 구형최소기록_스키마_v0.1.json과 변경 전 backup에 보존했다. 버전별 검사를 섞지 않는다. 일반 JSON Schema 도구에서 URN을 자동 해석한다고 가정하지 말고 제공한 기본 검사기를 사용한다.

세 맞춤 스킬 본문·참조·평가 입력/결과는 그대로 보존했다. record-steward의 구형 입력은 이제 기본 검사에서 이관 대기다. 구형 fixture를 새 규격에 억지로 통과시키지 않는다. v0.2 쓰기/기권/로그/backup 재평가는 R8에서 하며 과거 11/12·8/8을 새 규격의 효과/호환 성적으로 사용하지 않는다.
