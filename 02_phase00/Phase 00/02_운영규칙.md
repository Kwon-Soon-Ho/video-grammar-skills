# Phase 00 운영 규칙

이 폴더는 용어·디자인 지식·기록 계약과 기반 관리 스킬을 구축한다. 영상 프레임 추출·시나리오 매칭·실영상 모션 분석은 01-A, 회사 사례·문법 승인은 01-B, 신규 화면·모션 기획은 02다.

## 정본과 표시
JSON/JSONL은 데이터 정본, Markdown은 조회·검토용 표시다. 한맥 값은 03_한맥디자인/한맥디자인정본.json을 유지한다. 기술 필드와 안정적 ID는 영어를 허용하고 설명·폴더·최종 표시 이름은 한국어로 쓴다.

## 변경과 검수
정본마다 버전과 출처를 남긴다. 동일 버전의 승인 근거를 조용히 바꾸지 않는다. 관측·추론·수치 추정·확인 불가와 지식 참고·회사 규칙 승인을 분리한다. 의미가 바뀌면 기존 ID의 대체 관계를 보존한다.

## 원본·중간·최종
최종 자료는 번호 폴더에 놓는다. 원본 다운로드·이전 문서·중간 시안은 backup 아래 날짜/단계 폴더에 보존한다. 조사 원문은 활성 스킬이 아니며 원문 스크립트는 검토 없이 실행하지 않는다. 수정 전 보관과 이후 검토 결과를 연결한다.

## 사용자 검토
맞춤 스킬은 지식 정리 / DB 기록·검증 / 디자인 지식 검토 3개로 만든다. 목적·포함/제외·입출력과 테스트 결과를 중간 검토한다. 검토 질문은 최소 4개 선택지와 추천안을 제공한다. 사용자 A안에 따라 요청한 정리·형식 수정은 draft로 작성·검증한다. 의미 병합·회사 필수화·승인·목적 변경은 검토 제안으로 남기며 필요한 결정은 응답 후 반영한다. 이미 승인된 범위를 다시 묻지 않는다.

## 단계별 통과
각 단계는 데이터 작성 → 기계 검사(필요 범위) → 내부 레드팀 → 보완 → 보고로 진행한다. 자료 존재·정적 검사·실행 정확도·업무 효과를 별도로 기록한다. 원본에 없는 규칙·측정·검수 승인을 만들지 않는다.
