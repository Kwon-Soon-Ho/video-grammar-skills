# Phase 00 완료 범위와 01-A 준비 안내

2026-10-16 기준. 첨부한 Company Video Grammar Analyzer 계획과 실제 Phase 00 결과를 비교한 안내다.

**Phase 00의 기반 구축과 R8-4 기술검수는 마무리했다. 새 스킬을 평소 기본 도구로 바꾸는 결정과 사람의 포괄 완료 확인은 남았다.** 실제 영상을 분석하는 기능은 01-A에서 만들고, 분석한 사례를 회사 문법으로 승인하는 일은 01-B에서 한다.

첨부 텍스트는 초기 계획을 비교하는 자료로 사용했다. 그 안의 다운로드·착수 지시를 새 실행 지시로 받아 분석 개발이나 설치를 시작하지 않았다.

## 현재 완료와 남은 일

| 구분 | 상태 | 쉬운 설명 |
|---|---|---|
| 공통 용어·자산·원칙·기록·검수 기준 | 기반 구축 마무리 | 앞으로 자료를 같은 방식으로 정리할 공책과 작성 규칙을 마련했다. |
| 관리용 세 스킬의 재구성·실패 시험·인계 | R8-4 한정 기술검수 완료 | 공책을 정리하는 보조자들이 잘못 쓰거나 복구에 실패했을 때 어떻게 처리하는지 시험했다. |
| 새 스킬의 기본 전환 | 미실시 | 새 보조자를 매번 쓰는 기본 담당자로 지정하는 결정은 남았다. |
| 영상 분석 스킬과 실제 영상 성능 | 01-A에서 개발·검증 | 영상을 보고 화면·움직임을 기록하는 분석기는 아직 만들지 않았다. |
| 실제 사내 문법 DB | 01-B에서 구축·승인 | 참고 지식과 기록 형식은 있지만 실제 회사 영상에서 검수한 문법을 축적한 단계는 아니다. |

현재 상태 파일에는 `R8_4_technical_complete=true`, `Phase00_complete=false`, `new_candidate_adopted=false`가 함께 기록돼 있다. 앞의 값은 기술검수 종료, 뒤의 값은 포괄 완료 확인·기본 전환을 아직 대신 결정하지 않았다는 뜻이다. 자료 준비는 지금 할 수 있다. 모든 회사 가이드와 미래 영상의 정답을 먼저 확보해야 준비를 시작할 수 있는 것은 아니다.

새 원칙과 사례를 계속 수집하는 일을 00의 종료 조건으로 늘릴 필요는 없다. 지금부터는 소량 시범과 실제 영상 검증에서 확인된 부족을 골라 보완하는 편이 목적에 맞다.

R8-4 실제 실행은 24회다. 최초 8회 38/38조건, 1차 보완후 11회 42/43조건, 순차 인계 2회 8/8조건, 마지막 표적 회귀 3회 12/12조건으로 기록했다. 과거 실패 1건은 지우지 않았다. 이 시험은 관리용 스킬·저장·복구·인계에 관한 것이며 실제 영상 분석 시행은 0회다. 서로 의존하는 조건을 합쳐 하나의 품질 성공률로 표현하지 않는다.

## 프로젝트가 향하는 곳

전체 흐름은 유지됐다.

**00 공통 언어와 기록 규칙 준비 → 01-A 분석기 개발 → 01-B 회사 영상 사례와 문법 검수 → 02 새 영상 기획 → 후속 제작 도구 연결·효과 검증**

이를 책 만들기에 비유하면 00은 단어장·독서노트 양식·검사 방법을 준비하는 일이다. 01-A는 영상을 보고 독서노트를 쓰는 분석기를 만드는 일, 01-B는 노트 중 믿을 만한 내용을 회사 참고서로 묶는 일, 02는 그 참고서를 보며 새 영상의 기획안을 쓰는 일이다.

예를 들어 SW 소개의 ‘데이터 처리 5단계’와 회사 소개의 ‘사업 수행 4단계’는 주제가 달라도 ‘현재 단계를 강조하며 순서를 설명한다’는 표현을 공유할 수 있다. 이런 공통 표현을 찾아 새 내용에 맞게 재사용하는 목표는 처음과 같다.

| 단계 | 쉬운 설명 | 가상 예시 |
|---|---|---|
| 00 | 노트의 분류와 작성 규칙 준비 | ‘현재 단계 강조’의 뜻과 근거를 적는 칸을 정한다. |
| 01-A | 영상을 보고 노트를 쓰는 분석기 개발 | 영상15초에 두 번째 카드가 밝아진 사실과 해당 프레임을 기록한다. |
| 01-B | 검수한 노트를 회사 참고서로 정리 | 여러 실제 사례의 단계 강조 표현과 사용 조건을 사람이 검수해 문법으로 묶는다. |
| 02 | 참고서를 보며 새 영상 기획 | 새 6단계 공정 설명에 맞는 화면 배치와 강조 순서를 제안한다. |

## 첨부 계획에서 구체화되거나 달라진 점

| 항목 | 첨부 계획과 현재의 차이 | 이유 | 예시 |
|---|---|---|---|
| 00의 작업량 | 처음에는 사전·규격 중심의 짧은 준비를 제안했다. 지금은 원칙·반례·외부 스킬·CI·출처·검수·복구 시험까지 보강했다. | 진행 중 사용자가 조사 깊이와 스킬 검토, 단계별 레드팀을 요구했고 실제 검수에서 누락을 발견했다. | 용어가 잘 정리돼 있어도 다른 사람이 고친 파일을 옛 백업으로 덮으면 안 되므로 복구 규칙까지 마련했다. |

| 디자인 지식·회사 자료 | Taste·문서 구조 참고에 더해 발표·편집·화면 설계 자료를 선별하고 한맥 디자인·8회사 CI를 먼저 연결했다. | 같은 회사 자료를 나중에 다시 수집하는 일을 줄이고, 웹 화면 취향을 영상 의무로 옮기지 않기 위해서다. | 로고에서 확인한 색을 보존한 뒤 프로젝트 배경색으로 쓸지는 실제 화면에서 검토한다. |

| 외부 스킬 도입 | 후보 이름과 기능 비교를 원문·참조·코드·의존성·파일별 사용 조건 검토로 구체화했다. | 이름이 유용해 보여도 전체 코드를 그대로 가져올 수 있다는 뜻은 아니기 때문이다. | 특정 PPTX 원문은 사용 범위가 미확인이라 직접·파생 이식에서 제외했다. Anthropic Skill Creator 사용과는 다른 사안이다. |
| 평가 방식 | 초기 2~3편 테스트 제안을 예비 보정과 다른 원본 묶음의 잠금 평가로 구체화했다. 단일 품질 총점도 쓰지 않는다. | 연습했던 영상만 잘 분석하는 문제와 중요한 오류가 총점에 가려지는 문제를 막기 위해서다. | 같은 영상의 짧은 편집본을 따로 떼어 ‘처음 보는 시험 영상’으로 세지 않는다. |
| 제작 도구 연결 | 00~02와 구분한 후속 제작 검증 자리를 두었다. | 기획안을 만들 수 있는지와 AE·동료 편집기에서 실제로 구현할 수 있는지를 따로 확인해야 한다. | ‘3개 카드가 순서대로 등장’ 기획을 만든 뒤 선택한 제작 도구에서 실제 결과와 수정 시간을 확인한다. |

화면·모션을 관찰할 때 근거를 남기기, 회사 문법 우선 검색, 외부 대안으로 보완하기, 신규 문법을 사람이 검수하기는 첨부 계획에도 있었다. 이 원칙들은 새 방향으로 뒤집힌 것이 아니라 실행 가능한 규격으로 구체화됐다.

API를 활용하려는 방향도 유지한다. 파일 읽기·프레임 추출은 PC의 일반 도구가 맡고, 화면 해석은 허용된 AI·API 경로를 선택하는 구성을 검토한다. 실제 도구·모델·비용·자료 전송 범위는 01-A 착수 때 정한다.

| 평가 표본과 수치 | 표본 수·반복 수·시간/좌표 오차·누락과 보류의 허용 범위 | 예비 시험 후 네 가지 대안과 추천안을 제시하고 잠금 시험 전에 정한다. |
| 회사 공통 문법 승인 | 어떤 표현을 회사 공통·프로젝트 한정·단일 사례로 둘지 | 01-B에서 실제 사례와 반례를 보고 확인한다. |

**이미 확인한 사항:** 제공한 8회사 CI는 최신 자료이고 산하종합기술은 원래 Illustrator 원본이 없다는 사용자 답변을 기록했다. 이를 반복 요청하지 않는다. 한맥 웹 디자인 정제본도 이미 연결돼 있다.

## 새 스킬 기본 전환 전에 확인할 것

최신 후보는 큐레이터 `0.2.0-draft.3`, 기록 관리자 `0.2.0-draft.5`, 적용성 검토자 `0.2.0-draft.4`다. 각각 지식 초안 정리, 기록/참조/복구, 적용성·근거·사람 질문을 맡는다. 이 세 스킬에 영상 분석·새 화면 창작·회사 승인 권한을 추가하지 않았다.

1. **출력을 사람이 확인:** 정상 결과뿐 아니라 실패·부분 저장·미복구 보고가 이해되는지 본다.
2. **쓸 판본과 범위를 지정:** 최신 후보 경로를 명시하고 이전 스킬을 보존한다.
3. **소량 사본에서 실무 확인:** 실제 용어·지식 몇 건을 정리하며 수정 내용·백업·보류·검수 부담을 본다.
4. **안전과 쓸모를 함께 확인:** 요청 밖 수정·외부 변경 덮어쓰기·근거 없는 승인 없이 처리하고, 사람이 다시 정리하는 부담도 감당할 만한지 확인한다.
5. **전환과 복귀 방법을 기록:** 기본 경로 변경은 별도로 결정하고 문제가 있으면 이전 판본으로 돌아갈 수 있게 한다.

24회 시험과 마지막 12/12조건은 위 결정을 돕는 근거다. 최신 판본으로 모든 과거 분기를 다시 시험하거나 실제 업무 효율·자동 호출까지 입증한 결과는 아니다.

| 선택 | 범위 |
|---|---|
| **A 추천** | 최신 후보 세 개를 명시한 소량 사본 시범 후 출력·검수 부담을 보고 기본 전환 결정 |
| B | 기존 시범 스킬을 유지하고 새 후보는 보관 |
| C | 큐레이터 등 한 스킬부터 시범·전환 여부를 순차 판단 |
| D | 추가 사례 비교를 먼저 하고 시범 사용 판단을 뒤로 미룸 |

이 안내를 만든 것만으로 어느 선택을 실행하거나 기본 경로를 변경하지 않았다.

## 01-A 전에 사용자가 준비할 자료

처음에는 아래 한 묶음이면 된다.

| 자료 | 준비 방법 | 예시 |
|---|---|---|
| 대표 최종 영상1편 | 가능한 원래 납품/배포본 MP4·MOV 전체 파일. 보고 싶은 구간은 메모 | 기술 설명 영상 전체와 ‘중간의 도표 등장 구간을 보고 싶다’는 메모 |
| 대응 시나리오 또는 콘티 | 현재 가진 형식 그대로. 영상과 대응하는 버전 표시 | 최종 영상v03에 사용한 시나리오v02. 차이가 있으면 차이라고 적기 |
| 짧은 자료 설명 | 목적·시청자/환경·최종본 여부·버전 대응·확인 담당자·외부 AI/API 처리 가능 범위 | 사내 기술교육용, 대형화면, 내용 담당 김OO, 외부 프레임 전송 확인필요 |

시나리오가 없으면 ‘없음’이라고 적는다. 실제 발화·화면 문구에서 대체 기록을 만들 수 있지만 원래 제작 의도는 확인되지 않은 상태로 둔다. 원래 대본을 AI가 완성 영상에 맞게 고쳐 원본처럼 보관하지 않는다.

AE 원본과 연결 자산, SRT/VTT, 수정 피드백, 잘된/문제 구간 메모는 있으면 도움이 되는 선택 자료다. 원본 프로젝트를 제공한다면 연결 자산의 상대 경로를 유지한다. 사용자가 FPS·프레임·타임코드·OCR·좌표·파일 해시를 수작업으로 정리할 필요는 없다.

처음 1편은 입력 경로와 분석 기준을 보정하는 데 쓴다. 이후 다른 정보 구조의 자료를 추가하고, 잠금 시험용 다른 원본 묶음은 선정/고정 전에 일괄 분석하지 않는다. ‘1편+추가1~2편’은 출발 제안이며 성능을 입증하는 최종 표본 수가 아니다.

## 권장 폴더 구조

아래는 준비할 폴더안이다. 현재 프로젝트 루트에는 Phase 01-A 폴더를 만들지 않았다.

```text
2026-10-02_AI 기반 영상 기획·제작 스킬 체계 개발 및 검증/
├─ 00기획/
├─ Phase 00/                         기존 기반과 검증 결과
└─ Phase 01-A/                      이후 착수 시 생성
   ├─ 00_진행안내/
   ├─ 01_입력자료/                   사용자가 먼저 준비
   │  └─ 영상001_프로젝트명/
   │     ├─ 00_자료설명.md
   │     ├─ 01_최종영상/
   │     ├─ 02_시나리오/
   │     ├─ 03_내레이션과자막/        선택
   │     ├─ 04_프로젝트원본과자산/    선택
   │     ├─ 05_검수메모/              선택
   │     └─ 06_회사디자인참고/        선택
   ├─ 02_분석작업/                   Codex가 추출자료와 기록 생성
   ├─ 03_분석스킬/                   01-A에서 개발
   ├─ 04_검증자료/                   교정자료·사람 정답·잠금자료 구분
   ├─ 05_결과보고/
   └─ backup/
```

**사용자는 우선 `01_입력자료`의 최종 영상·시나리오·자료 설명만 채우면 된다.** 원래 파일명을 유지해도 된다. Phase 00의 사전과 디자인 정본을 이 폴더에 복사해 따로 고치지 않고 원래 ID·판본으로 연결한다.

자료 설명에는 아래 정도를 적으면 된다. 모르는 내용은 ‘미정’으로 남긴다.

```text
프로젝트명:
영상 파일명과 버전 / 최종본 여부:
대응 시나리오 파일과 버전 / 없음:
목적과 핵심 메시지:
시청자와 시청 환경:
시나리오와 최종 영상의 차이:
보고 싶은 장면과 이유:
내용·디자인 확인 담당자:
외부 AI/API 처리 가능 여부와 범위: 가능 / 불가 / 확인필요
```

## 01-A의 첫 작업

사용자 착수 지시 후 입력 묶음·처리 조건 확인 → 영상 분석용 외부 스킬/도구 심층 검토 → 분석 스킬 개발 → 예비 자료의 사람 검수와 기준 보정 → 평가 수치 검토 → 별도 원본 묶음으로 확인 순서로 진행한다.

착수 때 확인할 질문의 예시는 ‘이 글자가 몇 초에 등장했나’, ‘대본의 어느 문장과 대응하나’, ‘가로 카드 배치라고 판단할 근거 프레임은 무엇인가’다. 회사 필수 문법 승인과 새 영상의 화면 창작은 각각 01-B·02에서 이어간다.
