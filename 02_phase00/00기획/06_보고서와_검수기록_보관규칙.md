# 보고서와 중요 검수 기록 보관 규칙

2026-10-16 사용자 지시. 프로젝트 루트의 `작업 보고서(pdf)`를 보고서 진입점으로 사용한다.

1. `01_제출보고서/단계명/`: 사용자가 PDF 출력까지 요청한 제출 보고서를 단계별로 저장한다.
2. `02_중요검수기록/단계명/날짜_주제/`: 별도 저장 요청이 없어도 보존 가치가 있는 단계 검토·레드팀·수정 근거·최종 파일 검사를 분류해 기록한다. 검토 원문 md/json과 확인한 PDF를 구분하며, 모든 기술 로그를 새 PDF로 복제하지 않는다.
3. 실행 코드·stdout/stderr·실패 당시 파일·해시·사본·백업은 각 Phase의 backup에 보존하고 결과 보고서에서 찾을 경로를 안내한다.
4. 사용자가 반드시 읽어야 하는 제출/결정 자료와 선택적으로 보는 검수 기록을 구분한다. 기록 존재가 사람 검수·회사 승인·기본 전환을 뜻하지 않는다.
5. 기존 보고서를 조용히 덮지 않는다. 보완본은 날짜/판본 또는 별도 보완 이력으로 보존하고 최신 안내에서 연결한다.
6. `02_중요검수기록/Phase 00/00_과거단계별/`에는 기존 R1~R8의 대표 검수 보고를 당시 원문 그대로 사본 보관했다. 이번에 내용을 새로 전수 검수했다는 뜻은 아니다. 과거 상태·수치는 현재 `Phase 00/14_스킬재구성/R8_현재사용안내.md`와 `현재상태_정정표.json`의 범위에 따라 해석한다. 과거 보고의 완료 표현을 새 회사 승인·기본 전환으로 옮기지 않는다.

`00_기존기획자료/`에는 기존 `00기획/초기 기획 pdf/`의 PDF를 원래 판본·backup 구분 그대로 사본 보관했다. 원본은 옮기거나 변경하지 않았으며 이번 작업에서 그 내용까지 새로 검수했다는 뜻은 아니다. 사본별 원래 경로·SHA는 게시 완료기록에서 찾을 수 있다.

현재 제출: `01_제출보고서/Phase 00/Phase00_기반구축_결과와_다음단계_준비보고서.pdf`
현재 중요 검수: `02_중요검수기록/Phase 00/2026-10-16_소량사본시범/`
실행 원문: `../Phase 00/backup/2026-10-16_소량사본시범/실행원문/`
