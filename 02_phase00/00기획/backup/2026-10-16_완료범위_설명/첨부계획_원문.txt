# PHASE 01 — Company Video Grammar Analyzer 구축 계획

PHASE 01부터 PHASE 02까지 사용할 공통 지식 체계를 먼저 설계하고, 그 위에 영상 분석 스킬을 만드는 방향을 추천합니다. 말씀하신 대로 영상 분석을 시작하기 전에 레이아웃·모션 용어와 DB 구조를 정해 놓아야 나중에 같은 자료를 다시 분류하는 일을 줄일 수 있습니다.

다만 중요한 구분이 있습니다.

처음부터 완성해야 하는 것은 디자인 스킬 전체가 아니라, 디자인 지식을 저장하고 분류하는 공통 규격입니다.

외부 레이아웃 사례 수백 개를 먼저 수집할 필요는 없습니다. 대신 회사 영상과 외부 사례가 같은 용어·분류 체계로 저장되도록 기반을 만들면 됩니다.

이를 위해 프로젝트를 다음 네 단계로 세분화하는 것이 좋겠습니다.

PHASE 00 — 사전 기반 구축

공통 디자인 언어·자산 구조·DB 스키마 설계

영상 분류 체계, 화면 레이아웃 명칭, 모션 명칭, 정보 전달 목적, 검수 기준 확립

PHASE 01-A

영상 분석 스킬 개발

GitHub 스킬 조사·분해·재구성 → Anthropic Skill Creator를 활용한 커스텀 스킬 제작 → 테스트

PHASE 01-B

사내 영상 분석 및 회사 문법 DB 구축

영상+시나리오 입력 → 장면·화면·모션 분석 → 공통 문법 추출 → 검수·승인

PHASE 02

외부 지식 확장 및 영상 기획 스킬

외부 디자인 사례 추가 → 사내 문법 우선 검색 → 화면·모션 후보 생성 → 실제 기획

PHASE 00은 별도의 장기 연구가 아니라, 처음 한 번 결정해야 하는 규격을 만드는 사전 작업입니다. 이후 필요한 지식과 사례는 계속 추가하는 구조입니다.

## 1. 가장 중요한 설계 원칙: 영상 종류와 표현 문법을 분리하기

말씀하신 소프트웨어 소개 영상과 회사 소개 영상의 관계가 이 프로젝트에서 매우 중요합니다.

예를 들어 다음 두 시나리오가 있다고 가정해 보겠습니다.

시나리오 A — SW 소개 영상

"데이터 수집부터 분석, 보고서 작성까지 다섯 단계로 진행됩니다."

시나리오 B — 회사 소개 영상

"기획에서 설계, 시공과 유지관리까지 전 과정을 수행합니다."

두 영상의 주제는 다르지만, 전달하려는 정보 구조는 같습니다.

- 여러 단계를 순서대로 설명한다.
- 전체 과정을 먼저 보여준다.
- 현재 설명하는 단계를 강조한다.
- 다음 단계로 시선을 이동시킨다.

따라서 다음처럼 저장해야 합니다.

SW 소개 영상

데이터 처리 5단계

회사 소개 영상

사업 수행 4단계

공통 표현 패턴 — 단계별 포커스 전환

전체 구조 제시 → 현재 단계 강조 → 다음 단계 전환

화면 구성

수평 카드 / 타임라인 / 연결형 다이어그램

모션

순차 강조 / 탈강조 / 포커스 이동

핵심은 영상 유형으로 검색할 수도 있지만, 표현 목적과 정보 구조로도 검색할 수 있어야 한다는 것입니다.

이를 위해 원본 영상 사례와 재사용 가능한 디자인 패턴은 별도로 관리하고 서로 연결해야 합니다.

이 구조가 만들어지면 PHASE 02에서는 새로운 외부 사례를 추가하더라도 분류 체계를 다시 만들 필요가 없습니다.

## 3. PHASE 00에서 먼저 만들어야 할 공통 지식 자산

처음부터 모든 디자인 사례를 스킬에 넣기보다는 분류 사전, 디자인 원칙, 사례 기록 규격을 분리해 두는 것이 좋겠습니다.

여기서 용어가 혼동되지 않도록 여섯 가지 영역을 구분할 것을 권합니다.

| 분류 축      | 분석 질문               | 예시                             |
| --------- | ------------------- | ------------------------------ |
| ① 영상 유형   | 어떤 종류의 영상인가?        | 회사 소개, SW 홍보, 기술 설명            |
| ② 전달 목적   | 시청자에게 무엇을 이해시킬 것인가? | 단계 설명, 비교, 변화, 인과              |
| ③ 정보 구조   | 정보들이 어떤 관계인가?       | 순서, 계층, 병렬, 부분과 전체             |
| ④ 화면 레이아웃 | 어떤 공간 구성으로 표현했는가?   | 카드, 타임라인, 분할, 흐름도              |
| ⑤ 모션 기능   | 움직임은 무엇을 전달하는가?     | 시선 이동, 단계 진행, 관계 연결            |
| ⑥ 모션 구현   | 실제로 어떻게 움직였는가?      | Position, Scale, Opacity, Mask |

여기에 컬러, 폰트, 재질, 그래픽 스타일과 같은 아트디렉션을 별도 속성으로 관리합니다.

이렇게 해야 '시선 이동'이라는 모션 목적과 '스케일 확대'라는 구현 방법을 혼동하지 않습니다.

### 용어 사전 예시

| 표준 ID                | 한국어 명칭  | 설명                     |
| -------------------- | ------- | ---------------------- |
| `EXPLAIN_PROCESS`    | 단계 설명   | 일련의 절차를 이해시키는 목적       |
| `ORDERED_STAGES`     | 순차 정보   | 순서가 있는 정보 관계           |
| `HORIZONTAL_PROCESS` | 수평 프로세스 | 단계를 가로 방향으로 배치         |
| `SHIFT_FOCUS`        | 포커스 전환  | 현재 주목할 대상으로 시선을 이동     |
| `SCALE_CHANGE`       | 크기 변화   | 개체의 시각적 크기를 변화         |
| `EASE_OUT`           | 감속 모션   | 종료에 가까워질수록 속도가 느려지는 형태 |

위 ID는 이번 프로젝트용 초기 명명안입니다. 외부 표준 규격으로 이미 확정된 명칭은 아닙니다.

코덱스가 이후 사내에서 '페이드인', '투명도 등장', 'Opacity In'이라는 용어를 발견하더라도 하나의 표준 ID와 연결해야 합니다.

반대로 서로 다른 의미라면 비슷한 명칭이라도 합치지 않아야 합니다.

중요한 것은 원본 사례 하나를 분석한 다음 레이아웃·모션 문법을 직접 복사해서 별도 파일을 계속 만드는 방식이 아니라, 패턴 ID로 서로 연결하는 방식을 사용하는 것입니다.

예를 들어 `P-COMM-0001`이라는 '단계별 포커스 전환' 패턴에 SW 소개 영상의 샷 3개와 회사 소개 영상의 샷 2개가 연결될 수 있습니다.

그렇게 되면 PHASE 02에서 같은 패턴을 조회할 때 실제 사용된 서로 다른 화면 디자인 다섯 개를 함께 비교할 수 있습니다.

또한 개별 패턴에는 다음 사항도 저장해야 합니다.

- 적합한 정보 구조와 사용 목적
- 실제 적용된 화면 사례와 타임코드
- 선택할 수 있는 레이아웃 변형
- 모션의 역할과 관찰된 타이밍
- 적용이 어려운 조건과 제작상 제약
- 실제 영상에서 확인한 내용과 AI가 추론한 내용의 구분

이 방식이라면 PHASE 02에서 외부 사례를 추가할 때 기존 데이터 형식 그대로 `source_type`만 내부/외부로 구분해 확장할 수 있습니다.

## 5. Company Video Grammar Analyzer의 실제 분석 순서

스킬은 단순히 영상을 요약하는 수준이 아니라 아래 절차를 수행하도록 제작해야 합니다.

1. 영상 및 시나리오 입력

   원본 영상의 FPS, 해상도, 길이, 타임스탬프와 시나리오를 확인합니다. 전체 영상의 유형·전달 목적을 먼저 분류합니다.
2. 영상의 시퀀스·샷 구조 분석

   장면 전환을 후보로 검출하고, 실제 컷과 동일한 화면에서 정보만 전환되는 구간을 구별합니다.
3. 샷별 대표 이미지 추출

   모션 시작, 전체 레이아웃이 보이는 순간, 핵심 강조, 종료 상태를 추출합니다. 실제 영상에 존재하지 않는 모션 전 완성 화면은 추출 불가로 표시하거나 별도 재구성 자료로 관리합니다.
4. 모션 분석

   개체별 등장·퇴장, 이동, 확대·축소, 오퍼시티 변화, 순서, 유지 시간, 겹치는 움직임을 분석합니다. 가감속 곡선은 신뢰할 만한 추적 데이터가 있는 경우에만 추정합니다.
5. 시나리오와 표현 목적 연결

   시나리오의 특정 문장 또는 전달 내용이 어떤 화면과 모션으로 표현되었는지 연결하고, 실제 관찰과 추론을 구별합니다.
6. 공통 문법 검색 및 분류

   기존 문법 DB에 동일한 구조가 존재하는지 확인하고, 동일 유형·변형 유형·신규 후보로 분류합니다.
7. 보고서 작성 및 검수

   이미지와 모션 타임라인을 확인할 수 있는 HTML 보고서, AI 검색용 JSON, 사람이 편집하는 Markdown을 생성합니다. 신규 패턴은 검토를 거쳐 승인합니다.

실제 대량 분석 단계에서는 모든 프레임을 동일한 밀도로 AI에 투입하는 방법은 피하는 것이 좋습니다.

전체 구성을 파악할 때는 저밀도로 분석하고, 움직임이 있는 구간에서만 고밀도로 추출해야 처리 시간과 분석 비용을 줄일 수 있습니다. 구체적인 FPS와 추출 기준은 첫 샘플의 결과를 보고 정하는 것이 안전합니다.

## 6. 스킬을 만들기 전에 검증해야 하는 것

스킬을 완성한 뒤에 문제가 발견되면 수정 범위가 커지므로, 처음부터 다음과 같은 테스트 자료가 필요합니다.

| 테스트                 | 확인 목적                     |
| ------------------- | ------------------------- |
| 일반적인 카드·텍스트 모션      | 기본 요소와 타이밍을 정확히 분석하는가     |
| SW 소개와 회사 소개의 공통 표현 | 영상 카테고리를 넘어 동일한 문법으로 묶는가  |
| 연속적으로 움직이는 화면       | 모션을 실제 컷으로 잘못 분리하지 않는가    |
| 복잡한 전환·페이드          | 추정할 수 없는 수치를 임의로 확정하지 않는가 |
| 시나리오와 최종 영상의 차이     | 기획된 내용과 실제 표현의 불일치를 발견하는가 |

또 하나 중요한 것은 최종 납품 영상이라고 해서 모든 표현을 회사의 정식 문법으로 자동 승인하지 않는 것입니다.

원본 영상은 승인된 산출물이지만, AI가 추출한 문법과 해석은 아직 승인되지 않은 분석 결과입니다. 이 둘의 상태를 구분해야 합니다.

먼저 스킬과 도구들의 소스를 검토하고 구현 계획을 승인한 뒤, 첫 영상 한 편으로 분석 정확도를 검증하도록 작업을 나누었습니다.

## 8. 최종적으로 추천하는 착수 순서

| 순서 | 할 일                                  | 중요한 완료 기준                  |
| -- | ------------------------------------ | -------------------------- |
| 1  | 공통 용어 사전 및 DB 스키마 v0.1 수립            | 내부·외부 사례에 공통 적용 가능한가       |
| 2  | 영상 분석 GitHub 스킬 비교·분해                | 재사용 기능과 신규 구현 기능이 구분되는가    |
| 3  | Anthropic Skill Creator 기반 커스텀 스킬 개발 | 영상+시나리오 입력으로 보고서 생성 가능     |
| 4  | 서로 다른 유형의 영상 2\~3편 테스트               | 공통 문법을 동일 패턴으로 찾아내는가       |
| 5  | 최신 사내 영상 확대 분석                       | 대표 문법과 변형 사례가 충분히 축적되는가    |
| 6  | PHASE 02 착수                          | 회사 문법을 검색해 새로운 기획에 활용 가능한가 |

여기서 PHASE 00의 사전 자산 구축에 너무 많은 시간을 사용하지 않는 것도 중요합니다. 용어 체계는 충분히 체계적이어야 하지만, 실제 사례를 보기 전에는 무엇이 필요한지 모두 알 수 없습니다. 따라서 핵심 분류 축을 먼저 고정하고 세부 용어는 영상 분석 과정에서 확장·병합할 수 있도록 설계하는 편이 좋습니다.

제가 보기에 이번 프로젝트에서 장기적으로 가장 가치가 큰 자산은 스킬 코드 자체보다 다음 세 가지입니다.

첫째, 어떤 전달 목적에 어떤 화면·모션 표현이 사용되었는지 연결한 사례 데이터.

둘째, 영상의 장르와 무관하게 재사용할 수 있도록 추상화된 회사 영상 문법.

셋째, 사내 문법으로 충분하지 않을 때 외부 사례와 디자인 지식을 비교하여 새로운 표현을 판단할 수 있는 공통 분류 체계입니다.

이 세 가지를 제대로 구축한다면 PHASE 02에서는 기존 자료를 재분석하는 대신, 사내 문법 DB를 그대로 활용하는 새로운 기획 스킬을 개발하는 작업에 집중할 수 있습니다.
