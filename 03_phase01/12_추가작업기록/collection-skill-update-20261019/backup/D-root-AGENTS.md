# 프로젝트 PDF 보관 규칙

사용자 지시(2026-10-19): 이 프로젝트에서 생성하는 모든 PDF는 다음 보관함에 반드시 기록한다.

`D:/00작업/2026-10-02_AI 기반 영상 기획·제작 스킬 체계 개발 및 검증/작업 보고서(pdf)`

- 제출 보고서·조사 보고서는 `01_제출보고서/<단계 또는 주제>/`, 중요한 검수 보고서는 `02_중요검수기록/<단계>/`, 검수용 변환 PDF는 `03_검수용변환PDF/<업무>/<판본>/`에 보관한다. 미리보기·초안·이전판도 판본을 구분해 남긴다.
- 작업용 PDF를 로컬에 만들어도 최종 응답 전에 위 보관함에 사본을 저장하고 SHA-256 일치를 확인한다. 기존 원본·실패 결과·동결 판본은 이동·삭제·덮어쓰지 않는다.
- 새 PDF는 `tools/archive_pdf.py`로 접수한다. 프로젝트의 번들 Python으로 `tools/archive_pdf.py <PDF 절대 경로> --category <보관함 아래 상대 폴더> --name <보관 파일명.pdf>`를 실행하면 PDF 사본·전체 목록·접수 기록을 함께 만든다. 준비만 확인하려면 `--dry-run`을 쓴다.
- 원본 참고 PDF와 외부 저장소 예시는 생성 보고서와 구분한다. 기존 문서·기술 로그를 보관을 위해 새 PDF로 변환할 필요는 없다.
- D: 쓰기가 샌드박스로 제한되면 허용된 로컬에서 준비를 마친 뒤 정상 승인 경로로 실제 보관한다. 보관 실패를 완료로 보고하지 않는다. 접근 불가가 지속되면 로컬 임시 경로와 미보관 사실을 명시한다.
- 사용자가 결과를 찾을 링크는 보관함의 파일을 우선한다. `00_PDF_전체목록.html`과 `00_PDF_전체목록.json`을 함께 유지한다.
- 사용자 지시(2026-10-19 추가): 사용자가 작업 내용을 기록하라고 요청했거나, 조사 결론·설계 선택·검증 결과 등 중요한 분기점이 생기면 이해하기 쉬운 PDF를 작성해 `01_제출보고서/<단계 또는 주제>/`에 넣는다. 결정 이유, 바뀐 점, 확인한 결과, 아직 확인하지 않은 점과 다음 작업을 적는다. 단순 중간 로그마다 제출 PDF를 만들지는 않는다.

이 규칙은 PDF의 보관 위치와 이력에 관한 것이다. 기록 보관이 내용 재검수·사람 확인·회사 승인·다음 단계 착수를 뜻하지 않는다.

## 스킬 수정 진행 방식

사용자 지시(2026-10-19): 작업은 큰 카테고리별 단계로 묶어 진행한다. 세부 작업마다 승인을 받거나 지나치게 작은 단계로 쪼개지 않는다. 실제 사용자 판단이 필요한 선택에서는 추천안을 포함한 사지선다 질문을 한다. 선택마다 영향과 차이를 쉬운 말로 설명하고 사용자 답변을 결정 이력에 남긴다. 답변이 필요한 부분 외의 독립 작업은 계속 진행한다.
