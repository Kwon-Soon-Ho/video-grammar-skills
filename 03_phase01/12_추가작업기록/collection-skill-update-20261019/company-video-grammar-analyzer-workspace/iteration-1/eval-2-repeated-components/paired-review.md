# 두 화면 반복 부품 수집 결과 짝 비교

검토 대상: `with_skill/outputs/collection.md`와 `old_skill/outputs/collection.md`. 두 파일 전체와 각 `execution.md`, 시험 `input.md`, 원본 PNG 2장을 직접 대조했다. 스킬 본문·기존 분석·다른 평가 결과는 읽지 않았다.

이 검토는 fresh-context AI 출력 검토다. 판본 라벨이 보이므로 블라인드 판본 연구가 아니며, 사람의 내용 승인이나 원본 영상 전편의 정밀 검수가 아니다.

## 판정

두 실행 모두 주어진 6개 기대 조건을 실질적으로 충족했다(각 6/6). 단순 제목·파일 존재가 아니라 실제 정보 관계, 8개 회사 목록, 그리드와 가로열, HALLA/피티씨 순서 차이, 장 표식 반복, 정지 표본의 모션 한계를 대조했다. **이 표본의 이진 기준에서는 동률이며 새 판본의 전반적 개선을 입증하지 않는다.**

## 직접 확인한 공통 성과

- 134초: 상단 장 표식과 우상단 제목/설명, 좌 가족사 사업의 2열×4행 로고, 우 전문인력 참여/두 BIM 항목/모니터 묶음, 가운데 파랑 요청(좌→우)·초록 지원(우→좌)을 모두 기록했다.
- 172초: 23.7억 원과 산정 설명, 중앙의 원근 로고 한 줄, 우측 TDC 건물/기단과 BIM 지원·BIM 설계·디자인 지원·해외사업 지원의 네 위치를 기록했다.
- E01 셋째 행의 피티씨/HALLA가 E02에서 HALLA→피티씨로 읽히는 구체적 순서 차이를 두 실행 모두 포착했다.
- 같은 로고 내용/문구와 동일 원본 파일/동작의 확정을 분리했다. 두 장 사이 38초를 연속 관측이나 그리드→가로열 모핑으로 만들지 않았다.
- 회사 로고 각각, 서비스 표지 각각, 잎·반사선·창문마다 별도 패턴을 남발하지 않았다. 공식 회사 스타일·자산·산정법의 승인을 주장하지 않았다.

## 실행 한계와 귀속

`execution.md`는 실행자 자기보고이며 전체 도구 transcript가 아니다. 어느 스킬 문서를 실제로 읽었는지, 반환 해상도, 다른 자료를 열지 않았는지, 전역 파일 무생성 여부를 독립 입증할 수 없다. 평가자는 두 PNG의 해시를 직접 재계산하여 input.md와 일치함을 확인했다.

이전 실행은 ROI 보강에서 base64 출력 잘림·sharp import 오류·자동 승인 검토의 `Selected model is at capacity`를 자기보고했다. 오류 자체는 전체 transcript 없이 독립 검증하지 못한다. 결과가 작은 글자를 미확정으로 남긴 것은 확인했다. 이 실패를 스킬 결함으로 자동 귀속하거나 새 판본의 우월성 근거로 사용하지 않았다.

두 outputs에는 Markdown 두 파일씩만 있다. 새 실행의 timing.json은 평가 메타데이터다. 새 디자인/영상/PDF나 사용자에게 불필요한 기계 출력은 확인되지 않았다. 실행 전역에서 다른 위치에 아무 파일도 만들지 않았다는 사실은 전체 기록 없이 보장할 수 없다.

새 실행 timing.json은 212초와 null 토큰을 담고 있다. 이전 실행에는 검토 시 timing.json이 없었다. 자기보고 시각·도구 대기·자원 경합이 있으므로 속도·비용 우열을 도출하지 않았다.

## 평가 기준의 한계와 후속 활용

현재 기준은 핵심 성공 여부를 검사하는 데 유효하지만 두 결과의 가독성·검색성·미세 전사 정확도를 판별하는 점수표는 아니다. 원본에 대한 최소 대조 항목(화살촉, 회사 수와 순서, 핵심 수치, 네 라벨 위치)을 명시하고, ID에서 정의와 현재 occurrence로 왕복 조회할 수 있는지를 검사하면 표면 통과를 줄일 수 있다. 전역 무생성/실제 도구 사용은 전체 실행 기록이 있을 때 별도 판단해야 한다.

이번 비교가 지지하는 결론은 두 판본 모두 이 입력의 정적 수집 요구를 충족했다는 것이다. 새 결과의 부품 묶음 등록과 전환 공백 표시는 유용한 구체 개선 후보지만, 이전 결과의 전체 사례·반복 분류·관계 조회도 충분하다. 추가 사례와 직접 정확도 검증 없이 새 판본 전반의 품질 향상, 회사 승인 또는 실제 재사용 성공으로 확대하지 않는다.
