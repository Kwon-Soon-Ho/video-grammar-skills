# 합성 자료 진단과 해석 한계

2026-10-16 · 고정 도형 자료만 사용. 회사 영상·시나리오·API를 입력하지 않았습니다.

## 시험 자료와 결과

- 96×64 손실 없는 FFV1/Matroska 4프레임 2개. CFR 입력 시각은 0/40/80/120ms, VFR은 1000/1030/1090/1140ms로 생성 전에 고정했습니다.
- 알려진 사각형을 자른 뒤 시계방향 90도→2배 확대→패딩. 픽셀 경계 최종 사각형 예상 `[56,26,88,74]`, 실제도 같았습니다. PNG를 직접 시각 확인했습니다.
- 설정되지 않은 PTS/time_base, 회전 메타데이터 부재, 영상이 아닌 바이트 파일도 진단했습니다.

| 묶음 | 확인한 항목 수 | 결과 |
|---|---:|---|
| CFR·VFR 각각 | 8 | 정수 PTS×실제 time_base, 음성 트랙 없음, GENPTS 비트 해제, 알려진 도형 픽셀 |
| VFR 추가 | 3 | 명시 원점 1초와 재생0 분리, nearest 동률 시 이른 화면 선택, FPS 역산과 실제 간격 차이 |
| 미설정/부재 | 4 | None time_base, 0/1 time_base, PTS 없음, 회전정보 없음과 값0 분리 |
| 좌표·정보 손실 | 2 | 순서별 변환 사각형, 크롭한 픽셀이 패딩으로 복원되지 않음 |
| 손상/비영상 입력 | 1 | 명시적 FFmpeg 오류 |
| **재시험 합계** | **18** | **18 통과** |

요청 60ms는 VFR 샘플의 30/90ms 중간이므로 정책에 따라 30ms를 선택하고 요청/실제 시각을 분리했습니다. 요청 시각에 프레임이 있었다고 만들지 않았습니다.

## 실패와 수정

첫 실행 17항목 중 1항목 실패. stable 문서의 ‘미설정 time_base는 falsy AVRational’ 설명만 믿고 `None`이 아닐 것이라고 기대했습니다. 실제 19.0.1 `av/frame.py`는 num이 없으면 반환하지 않아 None이 됐습니다.

실패 결과·당시 코드를 `backup/01_첫진단_실패보존`에 보관했습니다. 처리 기준을 **None 또는 falsy는 모두 미확인**으로 보완했고, 0/1 입력을 별도 진단에 추가해 18항목을 재실행했습니다. 정답 시각·도형 위치를 성공에 맞춰 바꾸지 않았습니다.

## 이 결과가 증명하지 않는 것

같은 FFmpeg 기반으로 만들고 읽은 self-roundtrip입니다. 독립 디코더/다른 생성기로 검증한 결과가 아닙니다. 손실 없는 도형이라 실제 압축 영상·한국어 문구·작은 도표·화면 전체의 의미를 대표하지도 않습니다.

실제 MP4, edit list, B-frame, 비정방 SAR, 회전 메타데이터가 존재하는 파일, 음성/영상 동기·전사, 큰 파일의 메모리/속도·타임아웃·악성/외부 참조 입력은 미시험입니다. 손상 파일 1개가 실패했다고 모든 손상 유형을 안전하게 처리한다는 뜻이 아닙니다.

GENPTS 옵션을 해제한 열기 결과는 확인했지만 원본 PTS의 진위·native 단계의 모든 시간 추론을 입증하지 않았습니다. 좌표 시험은 Pillow의 알려진 픽셀 변환이며 AI가 좌표를 맞게 인식한다는 평가가 아닙니다. 구조 확인을 회사 영상 정확성 평가로 바꾸지 않습니다.

## 재현 기록

`합성자료_기술진단.py`는 임의 영상 경로나 CLI 인자를 받지 않습니다. 자체 생성한 로컬 파일만 읽습니다. 이 코드를 회사 영상 추출기로 재사용하려면 별도 설계·구현 검수가 필요합니다. 격리 runtime의 원본 wheel 해시·빌드 정보와 실행 코드를 백업에 보관했습니다.
