# Company video grammar analyzer

영상에서 보이는 사실을 다음 기획에 넘길 분석 초안으로 만든다. 현재 판본은 **0.1.0-draft.9 개발 후보**다. `video-observation-0.4` 출력 계약을 사용한다. 과거 형식이나 실패 기록은 수정·자동 승격하지 않는다.

## 입력과 근거

원본 경로·해시·분석 구간과 문서 유형(제작 전 원고/재구성 원고/없음)을 고정한다. 사용자가 준 구간 안에서 먼저 작업한다. 오디오를 실제로 듣거나 전사하지 않았다면 음성/싱크는 미검수다.

[근거 계약](references/evidence-and-records.md)을 읽고 시간·좌표·주장 범위를 지킨다. 기존 추출 로그와 PNG가 있으면 `scripts/evidence_catalog.py --logs <log...> --out <catalog.json>`으로 파일 해시·표시시각을 확인한다. 로컬 실행 문맥에서 제공한 검증된 제한 추출기를 사용해 부족한 구간을 보충한다. 이 스킬은 범용 디코더를 번들하지 않는다. 추출기가 없으면 제공된 근거의 범위에서 분석하고 미확보 부분을 적는다. 한 장만 보고 이동/이징을 확정하지 않는다.

## 관찰

[모션 관찰](references/motion-review.md)을 읽고 다음 세 범위를 따로 살핀다.

- 화면 전체: 상태/전환, 주요 대상, 문구, 정보 관계.
- 대상 주변: 작은 선·테두리·커서·빛·가림·잔상 등 주요 대상과 별도로 변하는 요소.
- 대상 내부: 화면 속 UI, 데이터, 선택 상태, 내부 그림/질감. 외곽이 멈췄다고 내부도 정지라고 기록하지 않는다.

시간순으로 한 번 훑은 뒤 정착 화면의 각 요소가 어떻게 만들어졌는지 역으로 추적한다. 두 관찰에서 목록이 다르면 해당 경계를 촘촘히 확인한다. 개요 시트에서 작은 요소를 못 읽으면 원본 크기 ROI를 보고, 보이지 않은 이유를 확인하기 전 ‘없음’으로 닫지 않는다. 시작·변화 중·종료와 중첩 표본을 연결한다.

대상 목록을 먼저 만들고 대상마다 실제로 해당하는 속성을 `required_properties`로 정한다. 문구·정체·정보 관계도 필요한 대상에 포함한다. 각 요구 속성의 구간을 `observation_rows`로 연결한다. 정지·해당 없음·아직 안 봄·판독 불가를 구분한다. 제외한 속성은 이유를 남기며, 요구 목록 자체의 누락은 원본을 다시 보는 발견 검수로 확인한다.

이름을 붙이기 전 `shape_description`에 보이는 특징을 적는다. 글자·숫자·수치·부정어처럼 틀리면 의미가 바뀌는 식별은 원본 크기 ROI와 같은 대상의 다른 시점을 대조한다. 확인된 식별 주장과 근거를 연결한다. 아직 모르면 중립적 대상 이름을 유지하고 후보와 다음 확인을 남긴다. 특정 A/4 사례를 외우게 하거나 모두 미상으로 돌리는 규칙으로 바꾸지 않는다.

속성이 변하면 그 속성의 가감속도 따로 확인한다. 적용하지 않는 속성을 억지 수치로 채우지 않는다. 외곽 이동과 내부 변화, 텍스트 크기와 주변 프레임 크기, 빛 이동과 밝기 변화를 분리한다. 위치 감속을 봤다는 이유로 크기 감속까지 확인했다고 쓰지 않는다.

Phase 00 지식이 제공되면 관련 ID와 정의를 조회하되 관측의 증거로 사용하지 않는다. 가속/감속을 모르면 원인을 적고 확인된 방향·존재·순서는 보존한다. 기록 누락과 판독 불가를 같은 것으로 처리하지 않는다.

## 원본 전체와 구간의 진행 범위

[범위 집계](references/source-coverage.md)에 따라 원본별 개요 표본, 잠정 작업 묶음, 실제 기록 구간을 구분한다. 전체 범위를 훑은 표본 수를 정밀 분석 시간으로 바꾸지 않는다. 구간 기록의 합집합과 미기록 시간·열린 쟁점은 `scripts/source_coverage.py`로 집계한다. 이 도구는 장면 발견이나 정밀 검수 완료를 판정하지 않는다.

## 기록과 종료

[출력 계약](references/output-contract.md)에 따라 `observations.json`을 저장한다. 한 주장은 한 대상·속성·판정에 해당하게 작성한다. 같은 표의 서로 다른 셀 값은 `dimension`으로 구분하고, 확인 안 한 속성을 범위 밖으로 숨기지 않는다. 관측/계산/추론, 근거, 내용 검수 상태를 나눈다. 추출 로그가 있으면 카탈로그를 생성한 뒤 `scripts/check_record.py <observations.json> --catalog <catalog.json>`으로 구조와 원본·프레임·시각 연결을 검사한다. 카탈로그 없는 검사는 구조만 확인한다. 검사기는 글자를 읽거나 전체 대상 발견을 입증하지 않는다.

`scripts/render_observations.py <observations.json> --out <observations.md>`로 JSON에서 요약을 생성한다. 새 발견은 JSON을 수정한 뒤 재생성하며 MD만 따로 바꾸지 않는다. 과거 `a3-observation-0.1`은 현행 형식으로 간주하지 않고 원본 보존 후 새 분석 기록에서 필요한 범위를 다시 확인한다. R4 정본 DB로 자동 등록하지 않는다.

완료 전 아직 조사하지 않은 대상·속성과 증거 부족을 확인한다. ‘모두 확인’ 대신 검사한 시각 범위/표본/남은 불확실성을 보고한다. 사용자 질문은 조사 후 남은 쟁점만, 해당 화면과 구체 주장으로 제시한다. 이전 사용자 확인은 정확히 같은 주장·자료 범위에만 연결한다. AI의 새 발견은 AI 관측으로 남기며 회사 공통 규칙/제작 의도/AE 구현으로 승격하지 않는다.

저장 전 대상별 주장과 근거를 역대조한다. 근거 ROI에서 해당 대상의 특징이 실제로 보이는지, 가림 해소를 이동으로 쓰지 않았는지, 다른 대상의 숫자를 가져와 설명하지 않았는지 확인한다. 이 내용 점검은 JSON 검사로 대체되지 않는다.

누락·오답 피드백을 받아 고칠 때는 [수정 검수](references/review-ledger.md)에 따라 이전 기록을 보존하고 지적 → 보완 주장 → 현재 근거를 연결한다. 이 검사는 이미 등록한 지적의 보완 추적이며 새 누락 발견이나 독립 품질 합격을 대신하지 않는다.

## 전체 디자인과 반복 패턴

[디자인과 패턴 기록](references/design-and-patterns.md)을 읽고 전체 레이아웃과 모션의 흐름·세부를 나눠 기록한다. 전체 사례를 보존하고 레이아웃·전체 흐름·독립 세부 동작에 각각 번호를 부여한다. [패턴 조합](references/pattern-composition.md)에 따라 사례의 `reuse_map`에서 각 번호와 순서·중첩·배치 관계를 연결한다. 첫 정의는 해당 단위를 상세히 분석하고 반복은 고정 스냅샷과 현행 근거·차이를 연결한다. 독립 재사용 가치가 없는 작은 변화마다 번호를 늘리지 않는다. 전체 디자인 기록을 선택적 수치 측정과 혼동해 생략하지 않는다.

## 다음 판단으로 인계

첫 레이아웃의 상세 기록이나 디자인 누락 보완에서는 [디자인 기록 밀도](references/design-density.md)에 따라 영역·글자 크기 관계·여백·선틀·배경층을 구체화한다. 수치는 재사용 판단에 필요한 관계부터 시점·좌표계·방법·오차와 함께 적는다. 묶음 이동과 하위 요소의 크기 변화는 분리하며, 상세 보강 파일을 연결하면 `scripts/check_design_details.py`로 일관성을 검사한다.

재사용·재제작 인계를 요청받으면 [판단 인계](references/judgment-handoff.md)를 읽는다. 관측 주장과 새 목적·사용 조건 후보·구현 제안을 분리한다. 근거는 원본·추출 설정·관측 판본이 같은 범위에서 재사용한다. 메시지와 정보 관계를 보존한 뒤에만 반복 설명·불필요한 정밀 측정을 줄인다. 외부 스킬의 모든 훅을 설치할 필요는 없다.
