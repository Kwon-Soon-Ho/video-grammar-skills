# 도구와 스킬 심층 검토

2026-10-16 · 조사 범위는 01-A1의 최소 도구 선택입니다. 모든 영상·디자인 스킬을 다시 전수 조사한 결과가 아닙니다.

## 1. 현재 환경 확인

현재 확인한 bundled Python 3.12.14와 PATH에는 `ffmpeg`·`ffprobe` 실행 경로가 없었습니다. PC 전체 디스크에 존재하지 않는다는 판정은 아닙니다. bundled Python에는 PyAV/OpenCV/PySceneDetect/OpenAI SDK가 없었습니다. Pillow 12.3.0·NumPy 2.3.5는 있어 정답 도형 작성에 활용했습니다. Phase 00의 검증 환경은 옮기거나 변경하지 않았습니다.

| 기능 | 후보·결정 | 이유와 미지원 |
|---|---|---|
| 영상 디코딩·프레임 시간 읽기 | **PyAV 19.0.1 격리 후보** | wheel·소스 해시 고정, 합성 자료로만 실행. 실제 MP4·시간 출처·표시 방향 확인은 다음 단계 |
| 별도 메타데이터 교차확인 | FFprobe 후보, 현재 미확보 | 독립 명령 호출 경로 없음. 같은 FFmpeg를 쓴 교차확인도 완전 독립 진위 증명은 아님 |
| 장면 자동 분할 | PySceneDetect 도입 보류 | 컷과 모션그래픽 화면 상태는 다름. 먼저 사람 근거와 작은 구간 관찰 필요 |
| OCR·화면 해석 | 현재 Codex 이미지 읽기 우선 제안 | 실제 정밀 좌표/한국어 수치 정확성 미검증. 표시·축소 경로를 기록해야 함 |
| 별도 비전 API | OpenAI 이미지 입력 문서 검토, 미호출 | 작은 글자·회전·공간 위치 오독 가능. 모델·입력 detail·응답 기록 필요 |
| 전사 | 공식 speech-to-text API 문서 검토, 미호출 | 25MB 업로드 한도·분할 오프셋, 모델별 시간 정보 지원 차이 확인. 자동 채택하지 않음 |
| 로컬 AI·GPU 추론 | 미도입 | 사용자가 원하는 API 기반 방향에 맞춰 최소 전처리만 로컬에서 수행하는 안 |

## 2. PyAV 원문·참조·코드·의존성

- 확보 원본: `av-19.0.1-cp312-abi3-win_amd64.whl` 28,149,519바이트, `av-19.0.1.tar.gz` 4,274,648바이트.
- SHA-256: wheel `906fc3db09288319a75ea23ffefb59961c7dbe0d1c074601507a89de7d8593d8`, source `08674930eaf1af78a3ed8f93d3ba49383323b3a867e84349d9c399e36f7497da`.
- PyPI 메타데이터의 고정 URL·해시를 확인해 공개 배포처에서만 받았습니다. 이는 출처·바이트 고정이며 모든 배포물의 안전성 인증은 아닙니다.
- 원문은 19.0.1 태그와 sdist를 기준으로 봤습니다. 예전 `pyav.org/docs/stable`은 9.0.x 문서를 반환해 판본 근거에서 제외했습니다. 새 stable 사이트도 19.0.0 설명과 19.0.1 패키지 사이 차이가 있어 코드·실행값을 우선 대조했습니다.
- 실행: wheel을 작업 폴더의 `후보런타임`에만 안전한 경로 검사 후 압축 해제. pip·setup.py·CLI·전역 설치·AE 환경 변경 없음. 모듈과 번들 DLL 로드는 실행했으므로 ‘다운로드만 했다’고 기록하지 않습니다.
- Python runtime 추가 Requires-Dist는 검토 메타데이터에서 확인되지 않았습니다. 소스 빌드는 setuptools≥78·Cython≥3.3,<4가 필요하지만 실행하지 않았습니다. NumPy/Pillow는 이 진단 작성·이미지 변환에 사용했습니다.

전체 원본 파일의 정적·동적 보안 감사를 했다는 주장은 아닙니다. 검토 파일 SHA·행 수는 `정적검토_파일목록.json`, 실행 빌드 정보는 `격리런타임_검토결과.json`에 보존합니다.

## 3. 라이선스·외부 통신·배포 경계

PyAV 자체는 BSD-3-Clause 원문을 보존했습니다. 실제 로드된 FFmpeg는 버전 문자열 9.0.2, library metadata는 `LGPL version 3 or later`를 보고했습니다. configuration에는 libx264/libx265 등 외부 구성요소가 보입니다. **이 문자열과 구성요소 목록만으로 모든 포함 DLL의 조건·소스 제공·재배포 적합성을 확정하지 않았습니다.** wheel 안에서 확인한 루트 라이선스가 전체 의존성을 충분히 설명하는지도 미해결입니다. 조직 배포/패키징 전 별도 검토가 필요합니다. 법률·회사 승인 판정이 아닙니다.

이번 진단 코드는 고정 합성 로컬 파일만 엽니다. 공개 다운로드 외 회사 파일 업로드·API 호출·키 접근은 하지 않았습니다. 다만 라이브러리는 URL 프로토콜과 장치 기능을 지원하므로 ‘PyAV는 통신 기능이 없다’고 할 수 없습니다. 추후 도구는 등록된 로컬 파일 경로 허용목록·외부 참조/프로토콜 제한·입력 크기/시간 제한·실패 로그를 갖춰야 합니다. 아직 그 범용 도구를 구현하거나 검증하지 않았습니다.

## 4. 기존 스킬의 사용 범위

| 스킬·지식 | 이번 활용 | 보류 범위 |
|---|---|---|
| `video-knowledge-curator` 0.2.0-draft.3 | 근거/출처와 용어 후보의 구분을 계약에 반영 | 실제 회사 DB 변경·자동 병합 없음 |
| `video-record-steward` 0.2.0-draft.5 | 원본/사본·버전·백업·검증 원칙 반영 | 새 분석 추출기로 변경하지 않음 |
| `video-guidance-reviewer` 0.2.0-draft.4 | 적용 근거·반례·사람 보류 구분 | 실제 화면을 보고 검수한 결과 아님 |
| Anthropic Skill Creator | A3에서 초안·시험·피드백 흐름 사용 예정 | 이번에는 새 SKILL·자동 평가/CLI 최적화 미실행 |
| Taste·편집/화면 설계·모션 관련 외부 스킬 | Phase 00에서 허용한 지식 정본·관점 참조 | 원문/코드를 일괄 이식하거나 새 정답·강제 스타일로 쓰지 않음 |

새 스킬 추가가 최소 추출 경로보다 먼저 필요하다는 근거는 이번에 없었습니다. 기존 허용 지식으로 관찰 항목을 만들고, 실제 예비 오류가 드러나면 부족한 기능에 맞춰 추가 조사합니다. R3의 검토 보류 소스를 포괄 승인하지 않습니다.
