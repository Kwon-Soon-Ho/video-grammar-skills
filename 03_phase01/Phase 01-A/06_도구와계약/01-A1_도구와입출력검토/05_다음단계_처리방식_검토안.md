# 01-A2 예비 시험의 처리 방식 — 4안

2026-10-16 · 이전 A안의 시험 순서와 기존 관리 스킬 사용 정책은 유지합니다. 이번 선택은 **첫 예비 시험에 어떤 도구·외부 AI 경로를 사용할지**에 관한 것입니다.

| 안 | 진행 범위 | 영향 |
|---|---|---|
| **A. 로컬 추출 + 현재 Codex 화면 검토 (추천)** | 장헌의 메타데이터·시간/표시 방향을 먼저 확인하고 작은 구간의 프레임을 추출해 현재 Codex에서 검토. 이어 무문서 EG-BIM에 같은 원칙 적용 | 별도 API 키·추가 과금 경로를 새로 만들기 전에 입력/근거 연결부터 확인. 음성 트랙/전사 필요가 확인되면 처리 범위를 따로 구체화. 음성 미처리는 미확인으로 남김 |
| B. 별도 비전·전사 API를 함께 설계 | 두 영상의 필요한 이미지/음성 범위·모델·예산·실행 한도를 먼저 정리 | 일관된 호출/모델 기록에 유리하나 키·사용 범위·비용 설정이 선행. 이 선택만으로 임의 예산·전체 업로드를 확정하지 않음 |
| C. 전처리 기술 검증만 더 진행 | 합성 MP4·비영 회전·SAR·음성 동기·독립 생성기 교차확인을 먼저 확대 | 실제 회사 화면은 계속 열지 않음. 기술 위험은 더 줄지만 사용자 관점의 관찰 오류 발견이 늦어짐 |
| D. 도구·범위를 수정하고 A2 보류 | 부족하다고 보는 항목을 지정해 A1 계약부터 수정 | 실제 분석 없이 설계를 먼저 재검토 |

A에서도 로컬 AI 모델을 설치하지 않습니다. 로컬 도구는 파일 읽기·디코딩·이미지 준비를 맡고, AI 해석은 연결된 Codex가 담당합니다. 현재 Codex 이미지 입력 역시 AI 서비스 처리이며 완전 오프라인이 아닙니다.

A를 선택하더라도 새 분석 스킬 제작(A3), 전체 영상 일괄 분석, 회사 문법 확정(01-B), 새 화면 창작(02), 기존 스킬 기본 전환은 포함하지 않습니다. 실제 MP4 특성 확인에서 문제가 나오면 결과·영향을 보고하고 보완합니다.
