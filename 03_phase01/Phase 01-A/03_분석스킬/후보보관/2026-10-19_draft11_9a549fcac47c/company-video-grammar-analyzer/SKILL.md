# Company video grammar analyzer

원본 영상의 레이아웃·디자인 언어·부품 조합·전체 흐름·세부 동작을 다음에 찾아 쓸 수 있는 수집 기록으로 만든다. 현재 판본은 **0.1.0-draft.11 개발 후보**다. 기본은 Markdown 수집 기록이며 JSON 검사·DB 입력은 필요한 경우의 별도 경로다. 과거 관측·실패 기록·잠금 기준·검수 상태를 소급 변경하지 않는다.

## 범위와 입력

분석할 원본의 경로·해시·구간, 사용할 근거와 문서의 유형/판본을 고정한다. [근거 계약](references/evidence-and-records.md)의 시간·좌표·주장 범위를 지킨다. 실제로 듣거나 전사하지 않은 음성·싱크는 미검수다.

사용자 지정 변경안은 별도 내용 기준이다. 원본 화면의 숫자·문구와 달라도 원본 관측을 고쳐 쓰지 않는다. 시나리오 시간 메모를 원본 타임코드로 사용하지 않는다.

수집 요청만으로 새 브리프·화면 재구축·모션 렌더·AE 제작을 시작하지 않는다. 수집 완료 조건에 새 화면 제작이나 시안 승인을 넣지 않는다. 원본 표현은 충실히 보존하되 이후 활용 스타일을 하나로 강제하지 않는다.

## 수집과 관찰

[수집 기록](references/collection-record.md)과 [디자인·반복 패턴](references/design-and-patterns.md)을 읽고 전체 사례의 정보 관계와 시각 구성을 먼저 기록한다. 대상 목록만 나열하지 말고 **배치·위계·재질·배경/전경·역할·동반 조합**을 연결한다. 원제작 의도는 문서/제작자 확인과 구별하고, 근거 있는 기능 해석은 추론으로 남긴다.

[모션 관찰](references/motion-review.md)에 따라 화면 전체, 대상 주변, 대상 내부를 살핀다. 시간순 관찰과 정착 상태의 역추적을 대조하고 목록이 다른 경계에 표본을 보충한다. 바깥이 멈췄다고 내부도 정지라고 기록하지 않는다. 관련 숫자·막대·도상이 동시에 시작/완료한다고 가정하지 않는다.

대상 이름을 붙이기 전 보이는 형태를 기록한다. 의미를 바꾸는 글자·숫자·부정어·방향은 원본 크기 ROI와 다른 시점을 대조한다. 한 장·개요 시트에서 안 보인 것을 곧바로 ‘없음’으로 닫지 않는다. 정지·해당 없음·미관측·판독 불가를 구별한다.

관측된 상태·순서·겹침을 보존하고 정밀도는 사용 목적에 따라 고른다. [디자인 기록 밀도](references/design-density.md)는 정성 설명만으로 중요한 관계가 불명확할 때 사용한다. 미상의 폰트/효과/곡선 원값 때문에 전체 디자인이나 확인된 동작까지 비우지 않는다. 측정값은 시각·좌표계·방법·오차·필요 이유를 연결하며, 외관을 원본 AE 속성으로 단정하지 않는다.

검증된 제한 추출기가 있으면 필요한 구간만 보충한다. 이 스킬은 범용 디코더를 번들하지 않는다. 추출기가 없으면 제공된 근거 범위에서 기록하고 미확보 부분을 남긴다. Phase 00 지식은 관찰 질문을 돕는 참고이지 원본 관측의 증거가 아니다.

## 기록과 반복 연결

기본 결과는 [수집 기록 계약](references/collection-record.md)의 Markdown이다. 관측 사실·계산·기능 해석·변경안 내용·요청받은 새 제안을 구별한다. 새 제안이 필요 없으면 만들지 않는다. 기록만으로 전체 사례·근거·재사용 단위·차이·적용 조건을 찾을 수 있게 한다.

전체 사례를 보존하고 레이아웃·전체 흐름·독립 세부 동작을 번호로 연결한다. 처음에는 해당 단위의 구성과 단계·조건을 기록하고, 반복은 **같은 번호/정의 판본 + 이번 근거 + 차이 + 미검증 부분**을 남긴다. 공통 외형 가족·같은 부품·공식 회사 규칙을 구별한다. 독립 재사용 가치가 없는 하위 단계마다 번호를 늘리지 않는다. 정의와 사용처에는 같은 전체 ID/판본을 쓰거나 명시적 별칭표를 둔다. 사례→정의→현재 근거·차이를 한 번 왕복해 끊긴 연결을 고친다.

[패턴 조합](references/pattern-composition.md)에 따라 포함·배치 기준·선후·중첩·동반을 연결한다. 로컬 수집 후보와 정본 등록을 구별한다. 이름이나 색이 비슷하다는 이유로 같은 패턴을 확정하지 않으며, 새 시안을 원본 패턴의 근거에 섞지 않는다.

## 검수와 종료

원본과 기록을 대조해 요소·문구·정보 관계·강조·조합·중간 상태·동반 사건·구간 경계의 누락을 확인한다. 각 주장에 그 대상의 실제 근거가 있는지 역대조한다. [원본 재대조](references/source-readback.md)로 의미를 바꾸는 문구·도상·수치의 확정 수준을 확인한다. 판독을 유보한 내용은 검색 가능한 형태·위치로 남기며, 확인된 전체 디자인까지 비우지 않는다. 같은 대상의 가림 해소를 이동으로 쓰거나 다른 대상의 숫자·곡선을 빌리지 않는다.

기록 범위, 실제 관측 방식/표본, 내용 검수 주체, 미관측·판독 불가·정밀 원값 미상을 따로 남긴다. 부분 수집과 원본 전편 완료를 구별한다. [범위 집계](references/source-coverage.md)의 창 길이는 정밀 검수 시간이나 완료율이 아니다. 미상에는 무엇을 막는지와 다음 확인을 붙이되 모든 미상 해소를 무조건적인 종료 조건으로 삼지 않는다.

검수 결과는 선언한 범위의 원본-기록 대응으로 판단한다. 재구축 성공·사용자 시안 승인·새 주제 적용·회사 규칙 승인은 다른 검증이다. 실제 피드백을 고칠 때는 [수정 검수](references/review-ledger.md)에 따라 이전 기록과 지적→보완→현재 근거를 보존한다. 개발 수정과 독립 실행 성능 평가를 구별한다.

작업·중요 분기점은 Markdown으로 기록한다. PDF는 사용자가 요청할 때만 생성하고 해당 프로젝트의 보관 규칙을 따른다. 멈출 때는 채팅에 현재 범위·결과·다음 작업·남은 대상을 설명한다. 실제 판단이 필요하면 프로젝트가 정한 방식으로 질문한다.

## 선택 경로

- **기계 검사/기존 DB 연계 요청:** [JSON 출력 계약](references/output-contract.md)을 사용한다. `video-observation-0.4`와 draft.11의 호환 경로이며 Markdown 수집 전체를 검사하는 형식이 아니다. 원본 카탈로그는 `scripts/evidence_catalog.py`, JSON 검사는 `scripts/check_record.py`, JSON 표시용 MD는 `scripts/render_observations.py`를 사용한다. JSON 모드에서는 JSON을 수정하고 표시를 재생성한다. 기존 검사/검색은 내용 정확성·전체 발견·회사 승인을 판정하지 않는다. R4 정본 DB에 자동 등록하지 않는다.
- **적용 판단·제작 인계 요청:** [판단 인계](references/judgment-handoff.md)를 읽고 관측/조건/새 목적/구현 제안을 분리한다. 수집 조건을 적었다는 이유로 제작을 시작하지 않는다.
